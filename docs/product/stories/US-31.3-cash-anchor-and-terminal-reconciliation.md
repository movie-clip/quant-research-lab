# US-31.3: Stop cash absorbing valuation error, and never publish a reconciliation adjustment as a return

**Epic:** Epic 31 — Ledger Replay Correctness
**PRD:** [`epic-31-ledger-replay-correctness.md`](../prd/epic-31-ledger-replay-correctness.md)
**Status:** Done
**Last updated:** 2026-08-04

## Story

As a **portfolio researcher**, I want the replayed series to tell me when its
opening cash is derived from mismatched inputs, and to never show me an
accounting correction as if it were a day's performance, so that every return
on the imported path is a real market move or is honestly withheld.

## Context

PRD findings **F-2 (cash plug)** and **F-3 (reconciliation published as a
return)** — the last two open findings in Epic 31. Both were re-measured
against merged `main` on 2026-08-04, **after** US-31.2 (F-1), US-31.4 (F-5)
and US-31.5 (F-4) landed. Those three removed the entire terminal
*market-value* drift (now **$1.35**), so what remains is purely the cash
anchor, and it is now precisely characterised.

**Root cause of F-2 — a date mismatch, not a valuation error.** The anchor is

```
base_cash = starting_nav − opening_positions_value      (portfolio_state.py)
```

but the two terms are dated differently on the committed IB2026 statement:

| Term | Value | As of |
|---|---|---|
| `starting_nav` | $52,381.12 | **2026-01-01** — the statement-period start |
| `opening_positions_value` | $49,124.79 | **2026-01-08** — the replay window start (first trade date) |

Five trading days of market movement are therefore absorbed into opening cash
as a plug. Measured drift vs the statement-implied opening cash is
**−$1,196.61** on the anchor itself and **−$1,196.61** at the terminal state —
i.e. **identical to the cent**. That constancy is the proof the in-window
cash flows are handled correctly (they track the ledger exactly once
US-31.5's FX conversion is applied); the whole error is the anchor itself.

**A measurement trap this story must not repeat.** The statement-implied
opening cash must be computed with **FX-converted** ledger flows. The raw sum
of `cash_effect` is currency-mixed (**−$271.23**, adding EUR −10,317.85 +
GBP −2,210.55 + USD 12,257.17); converted it is **−$2,459.29**. Using the raw
sum yields an implied opening cash of $2,264.88 instead of the correct
**$4,452.94**, and produces a wrong drift figure. The earlier PRD numbers used
the raw sum, which is why they differ from the ones above.

**F-3 is the same error surfacing as performance.** The constant anchor offset
rides every state, then `_reconcile_terminal_state_to_statement_totals`
overwrites the final state's `total_portfolio_value` with the statement's
ending NAV. The return series reads that correction as a market move: the
final day yields **+2.95%** with reconciliation vs **+1.00%** without — a
fabricated **+1.95pp**, with nothing marking the day as an adjustment.
(Annualised volatility is barely affected now, **23.63%** vs **23.27%**;
US-31.2 already removed the +79% inflation the epic opened with. The remaining
defect is correctness-of-kind, not magnitude: an accounting adjustment must
never be published as a return — guardrail #3.)

**Owner decision (2026-08-04): fail-closed + disclose.** Above a documented
tolerance the affected figure is withheld with an explicit trust level rather
than published as a confident number.

## Acceptance criteria

- [x] AC1 — The replay records **how** its opening cash was derived and whether
  that derivation is trustworthy: a `replay_cash_anchor` disclosure carrying the
  basis, the NAV as-of date, the window start date, the measured residual, and
  a trust level. On the committed IB2026 portfolio the basis is the
  date-mismatch case (`nav_as_of` 2026-01-01 vs `window_start` 2026-01-08) with
  residual **−$1,196.61** and trust `degraded` — never presented as `verified`.
- [x] AC2 — When the NAV date and the replay window start **agree** and the
  residual is within tolerance, the anchor reports trust `verified` with a zero
  (or sub-tolerance) residual — the disclosure is a real signal, not a banner
  that always fires.
- [x] AC3 — The statement-implied opening cash used for the residual is computed
  from **FX-converted** ledger flows, never the currency-mixed raw sum. A test
  pins both numbers on IB2026 (converted −$2,459.29 → implied opening cash
  $4,452.94; the raw −$271.23 is explicitly asserted to be the *wrong* basis)
  so the trap cannot be reintroduced.
- [x] AC4 — The terminal reconciliation is recorded as an adjustment on the
  state it modifies: `reconciliation_adjustment` carries the signed amount the
  terminal `total_portfolio_value` was moved by (**+$1,197.88** on IB2026), and
  is `null`/absent on every non-terminal state and whenever no reconciliation
  was applied.
- [x] AC5 — **No accounting adjustment is ever published as a return.** The
  replayed return series yields **no** return for a day carrying a
  reconciliation adjustment above tolerance — the point is withheld (null),
  never a computed number. On IB2026 the fabricated **+2.95%** final-day return
  no longer appears; the series' last published return is a real market move.
- [x] AC6 — Withholding is disclosed, not silent: the run metadata surfaces
  that the terminal day's return was withheld due to a reconciliation
  adjustment, so a researcher sees a gap with a stated reason rather than an
  unexplained missing point.
- [x] AC7 — Downstream statistics are computed on the published (real) returns
  only: annualised volatility on IB2026 falls from the adjustment-contaminated
  **23.63%** to **23.32%**, and the withheld date is absent from the return
  series (117 points from 119 states) — pinned, so it cannot leak back into any
  rolling window, volatility, beta or correlation.
  *Note:* 23.32% (day withheld) rather than 23.27% (day computed un-reconciled)
  — withholding removes the day entirely, which is the honest choice: the
  state's value was overwritten, so no trustworthy return exists for it.
- [x] AC8 — Behaviour is unchanged where there is nothing to disclose: a
  snapshot whose replay reconciles within tolerance produces the same states,
  the same return series, and a `verified` anchor — and a snapshot with no
  `statement_totals` (the request path) is byte-identical to today, since it
  never had a reconciliation step.
- [x] AC9 — `dashboardGoldens.ts` is regenerated **deliberately** (no
  `--capture`; `golden_market_data.json` byte-identical) and the diff is
  itemized per field family: the terminal state's `total_portfolio_value` /
  the withheld final return point may move; statement-identity, ledger-count,
  weight, sector, cost-basis, ISIN, cash-by-currency and every non-terminal
  daily state must be **byte-identical**.

## Out of scope

- **Re-deriving a correct opening cash.** The honest fix for the date mismatch
  would be valuing opening positions at the statement-period start
  (2026-01-01), but the replay has no price data before the window start and
  the ledger's first trade is 2026-01-08. This story **discloses** the
  limitation per the owner's fail-closed decision; it does not fabricate a
  period-start valuation.
- **US-24.9** (ledger-path cash de-dilution) — unblocked by this story, built
  after it on a trustworthy series.
- **Distributing the adjustment** across the window (an alternative F-3
  treatment) — rejected: spreading an accounting correction over real trading
  days would fabricate small returns on many days instead of one large one.
  Withholding is the honest treatment.
- No new analytics, cards, routes, or market-data providers; no change to the
  synthetic path (Epic 30 / US-30.5c).

## Notes / decisions

- **No new formula, so no new citation.** This story adds trust classification
  and a fail-closed rule to an existing documented replay; the methodology
  edits are rules, not formulas.
- **Why the residual is measured, not corrected:** the drift is a genuine
  information gap (no prices exist before the window start), so any "fix" would
  be an assumption presented as data. Measuring and disclosing it keeps
  guardrail #3 intact and gives US-24.9 a known baseline.
- **Tolerance must be a named constant** in `app/core/constants.py` with a
  one-line rationale, following the US-24.2 precedent (no bare magic number).
  It gates both the anchor trust level and the return-withholding rule.
- **The constancy of the drift is the key diagnostic** and worth preserving in a
  comment: anchor −$1,196.61 vs terminal −$1,196.61 proves in-window flows are
  correct and isolates the anchor. If a future change makes those two diverge,
  the flow handling has regressed.
- **Do not reuse the raw `cash_effect` sum anywhere** — see AC3. The
  currency-mixed −$271.23 appears in the older PRD text and is the single
  easiest way to get this story's numbers wrong.
