# US-36.3: The docs an agent is told to trust for "what's shipped" actually match the repo

**Epic:** Epic 36 — Findings-First Doc & Gate Hygiene
**PRD:** [`epic-36-findings-first-doc-and-gate-hygiene.md`](../prd/epic-36-findings-first-doc-and-gate-hygiene.md)
**Status:** Done (2026-08-20)
**Last updated:** 2026-08-20

## Story

As a **developer or agent reading this project's canonical docs to find out
what's shipped**, I want the cache CLI description, the route-module
inventory, a closed epic's PRD status header, and the API-boundary note on an
accepted security tradeoff to all match the current repo state, so that I stop
discovering the doc was wrong by reading the code myself.

## Context

Bundles findings **F-R5, F-R6, F-R7, F-R8**
(`docs/product/review-2026-08-20-findings.md`), mirroring Epic 32's
`US-32.1`/`US-32.3` bundling pattern — each finding is individually too small
to be its own story, and all four are the same class of gap: a doc that was
accurate when written and has since drifted from the repo it describes.

**F-R5.** `docs/contracts/cache-fields.md` header read "Last updated:
2026-06-05" — predates US-35.2 (2026-08-19) by over two months. Prose
described the pre-US-35.2 behaviour, with no mention of what US-35.2 actually
shipped: namespaces enumerated live from disk (`JsonFileCache.namespaces()`,
not hardcoded), and a typo'd `--namespace` rejected with the present
namespaces listed (previously silently reported "Removed 0 cache file(s).").

**F-R6.** `docs/product/current-product-state.md:96-108` said "12 route
modules" and listed exactly 12. The actual `services/quant-engine/app/api/
routes/` directory had **15** — missing: `cache.py` (Epic 20/35),
`currency_risk.py` (Epic 26), `provenance.py` (Epic 18) — all three shipped
and wired into `app/api/main.py`. `CLAUDE.md`'s own repo-layout route list was
checked in the same pass and confirmed **already correct** (all 15 modules) —
no edit needed there.

**F-R7.** `docs/product/prd/epic-24-codebase-improvement.md:3` read "**Status:**
Active (started 2026-06-19)" though `epic-roadmap.md` and the story index both
have Epic 24 Completed. The PRD's status line was simply never flipped.

**F-R8.** `services/quant-engine/app/api/routes/imports.py:17-34` accepts any
filesystem path with no restriction to an app-owned directory, and the FastAPI
server has no auth. Given the local-first, single-user, no-execution design
and CORS restricted to the app's own dev origin (not wildcard), this is a
reasonable, accepted tradeoff rather than a defect — but the one-line note
documenting that decision was never added to
`docs/architecture/system-architecture.md`'s "API Boundary" section.

Also in scope: retiring `docs/product/review-2026-08-20-findings.md` once
these findings and the other two stories are folded into the Epic 36 PRD —
per this project's established convention (Epic 32's own precedent), marking
it explicitly superseded/historical rather than deleting it, preserving the
who-claimed-what-when audit trail, including its own second, self-authored
error (falsely claiming six findings were "logged in
`docs/tech-debt-register.md`").

## Design decision (tech lead, `05-technical-plan.md`)

**AC9 (the mechanical route-inventory check): IN, added.** Precedent already
exists in this exact repo for this exact class of gap —
`test_docs_paths.py` (Epic 32) exists specifically because "a document that
admits it cannot be trusted should be checked mechanically." A route-module
count that had already drifted once (12 vs. 15, three additions across three
different epics, none of which updated the count) is precisely the pattern
that lesson exists to prevent. New, narrowly-scoped
`test_route_inventory.py` (not folded into `test_docs_paths.py`, matching
that file's own stated convention of leaving adjacent doc classes for a
follow-up).

Because the new test is a pytest file, it is `app/tests/**` — the test lane's
scope, not the docs lane's — so T-36.3.2 split across two lanes/tickets
(T-36.3.2a docs, T-36.3.2b test).
