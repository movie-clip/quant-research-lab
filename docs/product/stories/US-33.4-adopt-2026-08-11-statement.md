# US-33.4: Adopt the 2026-08-11 statement as the golden fixture

**Epic:** Epic 33 — Corporate Actions & Replay Quantity Integrity
**PRD:** [`epic-33-corporate-actions-replay-integrity.md`](../prd/epic-33-corporate-actions-replay-integrity.md)
**Status:** Done (2026-08-13)
**Last updated:** 2026-08-13

## Story

As a **portfolio researcher**, I want the refreshed broker statement adopted as
the project's golden fixture with every pin re-derived against a replay that is
no longer producing garbage, so that the committed expectations describe the
product's real behaviour rather than an 8× error.

## Context

The owner replaced `docs/IB2026.csv` with an export covering 2026-01-01 →
2026-08-11. `statement_truths.py` and `golden_market_data.json` were refreshed
at the time, but the suite stayed red and nothing was committed, because the
replay was inflating market value ~8× (Epic 33 F-1/F-2). **US-33.2 fixed that**;
this story adopts the statement.

Two distinct classes of failure are in the current red suite, and they are not
fixed the same way:

**(a) Legitimate measurement pins that moved.** The replay's own evidence —
cash-anchor residual, terminal reconciliation adjustment, withheld-return date,
TWR/volatility figures, golden dashboard fixtures. These are re-measured
against the fixed engine and re-pinned with their new values.

**(b) Structural tests that were wrongly pinning statement truths.**
`docs/architecture/testing-architecture.md` §Statement refresh workflow is
explicit that a refresh must only surface diffs from `statement_truths.py` plus
the registry step, and that *"anything else failing on a refresh is a
structural test wrongly pinning statement truths (fix the test)"*. The refresh
meta-test `test_statement_refresh.py::test_swap_simulation_fails_only_the_documented_pin_surface`
exists to catch exactly this and is itself currently failing. Class (b) is
therefore not "update the number" — it is "stop pinning it here".

Four class-(b) offenders, all reproduced:

| Test | Wrongly pinned | Correct home |
|---|---|---|
| `test_currency_conversion.py` ×3 | `61238.53`, the pre-fix raw sum `58588.76`, four per-symbol weights, position HHI | `statement_truths.py` |
| `test_exposure_engine.py` ×2 | `61238.53` as the look-through / currency-exposure denominator | `statement_truths.py` |
| `test_importer_csv.py` (mutations, combine) | CSV row text for AMZN/DEFS as mutation anchors; `statement_period.endswith("2026-06-30")` | derive from the snapshot |
| `test_statement_refresh.py` | an AMZN row that the refresh sold in full | derive from the snapshot |

**One failure is neither (a) nor (b) — it is a real over-assertion.**
`test_cash_balances_per_currency_without_base_summary_double_count` asserts
`ending_settled_cash == cash_total`. That held on the old statement only
because it had no unsettled cash; the new one has **$453.38** unsettled
(`ending_cash` **$506.996** = `cash_total` ✓, `ending_settled_cash`
**$53.619**). The no-double-count invariant the test exists to prove is the
`ending_cash` equality; the settled equality was never an invariant.

Implementer must read:
- `docs/architecture/testing-architecture.md` §Statement refresh workflow —
  the five-step process and the "fix the test" classification rule.
- `services/quant-engine/app/tests/statement_truths.py` docstring — the
  statement-truth vs structural-invariant split.
- US-33.2's story file — the numbers below come from the fixed engine, and
  must never be re-derived against the pre-fix one.

## Notes / decisions

- **The ordering is the whole point.** Goldens regenerated before US-33.2 would
  pin the 8× error as expected behaviour — the exact failure mode Epic 31
  existed to undo. Regeneration happens in T-33.4.4, after the engine fix, and
  never earlier.
- **Class (b) is the durable win.** Re-pinning those numbers would leave the
  same trap armed for the next refresh; moving them into `statement_truths.py`
  is what makes the documented one-command refresh actually true.
- **A stale pin and a regression look identical from the outside.** That is why
  AC6 keeps the old values in docstrings and AC10 requires the golden diff to
  be characterised rather than accepted.

- **The adoption found a real defect, and that is the point of doing it this
  way.** Re-measuring US-24.9's de-dilution tripwire produced a
  trade-neutral / cash-inclusive volatility ratio of **×0.965** against a
  cash-weight prediction of ×1.042 — the wrong side of 1. Cause: US-33.2
  withheld LQQ's quantity but its trades still moved cash, so the cash-inclusive
  chain published six steps with no position behind them, inflating annualised
  volatility 14.18% → 15.49% and making a fabricated **+3.08%** the window's
  largest move. Fixed at source (US-33.2 AC11, `unbacked_cash_flow`) rather than
  pinned — pinning it would have written the fabrication into the goldens, which
  is precisely the failure this epic exists to undo.

- **Golden diff characterisation (AC10).** `dashboardGoldens.ts` 30,107 →
  34,924 lines. Three causes, all intended: (1) the window is longer — the
  statement now runs to 2026-08-11, so the replay produces 148 daily states
  against 119; (2) every value family moves because the underlying statement
  changed (peak `total_market_value` 63,537.96 on the old statement → 65,377.31,
  against `stock_total` 64,922.99); (3) one new field, `unbacked_cash_flow`,
  present on every state and `0.0` on all but LQQ's six trade dates. **No value
  anywhere in the file exceeds $66k** — the pre-fix regeneration peaked at
  $518,078.75, and its absence is the check that the goldens encode the fixed
  engine.

- **Deliberate over-withholding, recorded.** `unbacked_cash_flow` materiality
  reuses `REPLAY_RECONCILIATION_TOLERANCE` ($1.00). Two of the six withheld
  days carry flows of only $5.13 and $25.09 and distort nothing measurable, so
  their real returns are discarded along with the four that matter. A relative
  threshold would keep them, at the cost of a new tuned constant; withholding a
  real day is the safe error and publishing a fabricated one is not.
