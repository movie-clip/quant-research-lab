# US-27.5: Reconcile the factor risk-share denominator with the methodology

**Epic:** Epic 27 — Financial Calculation Correctness
**PRD:** [`epic-27-financial-calculation-correctness.md`](../prd/epic-27-financial-calculation-correctness.md)
**Status:** Done
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher**, I want one documented denominator for factor
risk shares, so that "share of risk", the top-N shares, and the factor HHI all
mean what the methodology says they mean.

## Context (audit finding F6)

`financial-methodology.md` §Risk share:

```text
risk_share_i = variance_contribution_i / total_variance
  total_variance = total_variance_raw (positions) or factor_total_variance (factors)
                   — the denominator matching the same decomposition
```

The code disagrees for factors. `_build_factor_risk_contributions` computes
`risk_share = variance_contribution / factor_total_variance` (matching the
doc), but `build_risk_contribution_breakdown` then **overwrites** every factor
row with `variance_contribution / total_variance_raw` where
`total_variance_raw = factor_total_variance + specific_variance`. Result:

- Factor shares sum to `factor_risk_share_total` (< 1), not 1 — while position
  shares sum to ~1 over their own decomposition.
- `factor_hhi` and `top_1/3_factor_risk_share` are computed over the rescaled
  values, so the doc's "HHI = 1/n when evenly spread" interpretation doesn't
  hold for factors.
- The dead inner computation invites future drift.

Either convention is defensible ("share of factor-explained variance" vs
"share of total variance including specific") — but code and doc must state
the **same** one, the position/factor asymmetry must be intentional and
written down, and the overwritten dead computation removed.

Recommended resolution: keep the doc's convention (denominator matches the
decomposition, factor shares sum to 1) and expose the existing
`factor_risk_share_total` / `specific_risk_share` fields as the
"share-of-total" view — they already carry that information without rescaling
the per-factor rows. Decide in T-27.5.1 with a written reason.

Implementer must read:
- `analytics/risk.py` `build_risk_contribution_breakdown` +
  `_build_factor_risk_contributions` + `_herfindahl_index` +
  `_sum_top_risk_shares`.
- `docs/finance/financial-methodology.md` §Risk Contribution and Concentration
  (incl. the HHI fraction-vs-percent contract rule).
- `docs/contracts/diagnostics-fields.md` + `dashboard-fields.md` risk-share
  rows; `RiskSummaryCard.tsx` (renders `top_*_risk_share` / HHIs).
