# US-28.3: Statement-refresh resilience — centralize statement-truth pins + document the workflow

**Epic:** Epic 28 — IBKR CSV Importer & Statement-Refresh Resilience
**PRD:** [`epic-28-ibkr-csv-importer.md`](../prd/epic-28-ibkr-csv-importer.md)
**Status:** Backlog
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher who replaces `IB2026.csv` with a fresh broker
export every few weeks**, I want the refresh to be one command plus a small,
documented set of deliberate updates, so a new statement never turns into an
afternoon of chasing scattered test failures.

## Context

Depends on US-28.2 (CSV is canonical; its close-out catalogued which tests
broke on the Jan–Apr → Jan–Jun statement swap). Two classes of assertions
exist against IB2026 data:

- **Structural invariants** — true for ANY valid statement: schema shape,
  reconciliation-summary passes, Σ positions = stock total, entry-type
  coverage, per-currency positions present, importer/format fields. These
  must never pin statement-specific values.
- **Statement truths** — specific to the current export: symbol lists
  ("VUAA in symbols"), position counts, registry/ISIN coverage for held
  tickers, hand-pinned totals (the FF2026-style constants), App-level
  `loadedFileLabel`. These are legitimate pins but today live scattered
  across `test_importer.py`, `test_exposure_engine.py`,
  `test_registry_isin_integrity.py`, `test_analytics.py`, and frontend
  fixtures.

Deliverables:
1. **Audit + convert**: every IB-statement assertion classified; structural
   ones rewritten to invariants (derive expected values from the imported
   snapshot itself or the statement's own totals, never a literal that
   changes with the export).
2. **Centralize**: remaining statement truths move to one module per side
   (backend: extend `_statement_fixtures.py` or a new
   `statement_truths.py`; frontend: the generated `dashboardGoldens.ts`
   already regenerates — verify nothing else hand-pins IB values).
3. **Document the workflow** in `refresh_statement.py`'s docstring +
   `docs/architecture/testing-architecture.md`: replace `docs/IB2026.csv` →
   run `python scripts/refresh_statement.py` → update the one truths module +
   add registry entries for new symbols → commit the listed files together.
4. **Prove it**: a test-fixture simulation (a copy of IB2026.csv with one
   position's quantity changed and one new symbol) run through the import +
   analytics paths must fail ONLY in the truths module's pins — a
   documented, greppable set — plus the expected registry-coverage check.

Implementer must read:
- The US-28.2 close-out catalogue (slice log) — the authoritative broke-list.
- `scripts/refresh_statement.py`, `docs/architecture/testing-architecture.md`
  (golden-freshness design), `.claude/skills/write-tests/SKILL.md` assertion
  conventions (membership/superset for extensible structures; pin implicit
  defaults once).

## Acceptance criteria

- [ ] AC1 — No backend test outside the designated truths module pins a
  statement-specific value (symbol literal, count, total) for the IB
  statement; converted tests assert invariants derived from the snapshot or
  the statement's own totals.
- [ ] AC2 — The truths module is single-source: each pin appears once, named,
  with a comment tying it to the statement period; frontend IB truths flow
  only from generated goldens.
- [ ] AC3 — The swap simulation (AC-fixture with a changed quantity + a new
  symbol) fails only the truths-module pins + the registry-coverage check;
  the failure output names the refresh workflow doc.
- [ ] AC4 — The workflow is documented in both `refresh_statement.py` and
  `testing-architecture.md`, including the CSV file, the truths module, the
  registry step, and the commit set.
- [ ] AC5 — Full suite + dead-code gate green; goldens untouched by this
  story (pure test/doc refactor — behaviour-neutral for the current
  statement).

## Test plan

- The swap-simulation test itself (AC3) — runs the mutated fixture through
  import + reconciliation and asserts the failure surface is the documented
  set (implemented as a meta-test on the truths module, not by actually
  breaking the suite).
- Existing tests: converted invariants keep their counts (rewrites, not
  deletions); `run_all_tests.py` green before and after with identical
  goldens (behaviour-neutrality proof).
