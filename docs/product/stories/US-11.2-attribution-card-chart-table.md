# US-11.2: Attribution card (chart + table)

**Epic:** Epic 11 — Factor Return Attribution
**PRD:** [`epic-11-factor-return-attribution.md`](../prd/epic-11-factor-return-attribution.md)
**Status:** Done
**Last updated:** 2026-05-27

## Story

As a **portfolio researcher**, I want to see a Factor Return Attribution card in the Exposure tab, so that I can immediately understand which systematic factors drove my portfolio's cumulative returns and how much each contributed over any rolling window.

## Context

US-11.1 delivered the `/api/engines/attribution/run` endpoint and the `FactorAttributionResponse` schema. This story adds the frontend-only `FactorAttributionCard` component to the Exposure tab (below the Rolling Factor Analysis card). No new backend work is required.

The card has two visual elements:
1. A **cumulative attribution line chart** — one colored line per factor showing cumulative contribution over the selected window, a grey dashed "Unexplained" line, and a white thick "Total Portfolio" line.
2. A **period attribution table** — one row per factor with average β, factor own return %, and contribution %.

The component must carry a "Synthetic" trust badge and show an explicit "Not enough history" empty state (never a blank or zeroed chart).

Implementer must read:
- `docs/finance/financial-methodology.md` §Factor Return Attribution — field definitions, trust class, residual naming
- `docs/contracts/attribution-fields.md` — backend ↔ TS ↔ UI field inventory (created in US-11.3; if not yet present, derive from `FactorAttributionResponse` schema)
- `services/quant-engine/app/schemas/attribution.py` — Pydantic schema to mirror in TS types
- `apps/desktop/src/features/portfolio/ExposurePanel.tsx` — where to insert the new card

## Out of scope

- No backend changes in this story — the endpoint was delivered in US-11.1.
- No drill-down to position-level attribution — factor-level only.
- No export or download of attribution data.
- No geometric/compounding display — the chart and table are explicitly arithmetic.
- No new CSS framework — reuse existing card and badge patterns from the Exposure tab.

## Notes / decisions

- **Chart library**: Use Recharts (already in use for the drift benchmark and factor model charts). `LineChart` with `Line` per factor + "Unexplained" + "Total Portfolio" lines.
- **Factor color convention**: if a factor color map already exists in the codebase (check `RollingFactorCard` or similar), reuse it. If not, define a 16-color palette in the component and document it — this becomes the convention for Epic 12+.
- **"Total Portfolio (arithmetic)" label**: the chart and table must communicate that sums are arithmetic. The word "arithmetic" must appear somewhere visible on the card (tooltip, footnote, or label suffix) per the methodology contract rule.
- **Trust badge**: reuse the same `SyntheticBadge` component (or equivalent) used in the vs-Market drift panel. If it doesn't exist as a reusable component, extract it here.
- **Endpoint call**: `runAttributionEngine` calls `POST /api/engines/attribution/run` with the same `daily_states` + `factor_history` payload shape as the diagnostics adapter. The `window` field is passed as a body field (20, 60, or 252).
- **Residual naming in UI**: the "Unexplained" line maps to `cumul_unexplained` from the response. Never label it "Alpha" anywhere in the component or its tests.
