# US-10.1: 3-way combine and API-level import tests

**Epic:** Epic 10 — Multi-broker Import Correctness
**PRD:** [`epic-10-multi-broker-import-correctness.md`](../prd/epic-10-multi-broker-import-correctness.md)
**Status:** Done
**Last updated:** 2026-05-27

## Story

As a **portfolio researcher**, I want the quant engine to be regression-tested against the full IB + Freedom24 + ESPP three-broker import scenario, so that any future change that breaks multi-broker position merging, ledger deduplication, or analytics computation fails a test before it reaches production.

## Context

Manual investigation confirmed that `combine_imported_snapshots([IB2026, FF2026, ESPP2026])` produces 23 positions, 194 ledger entries, `multi_broker` importer, and the correct statement period `2025-01-01 – 2026-05-25`. The existing test suite only covers IB+IB (sequential years) and IB+FF (2-way mixed broker); no test covers ESPP involvement or the full 3-way scenario.

The public `import_statements()` function — the entry point called by the import route — is also untested for 3-way mixed-broker input. And `build_import_bootstrap()` (which calls exposure + history analytics on the merged snapshot) is untested against a multi-broker combined snapshot, meaning analytics crashes would only appear at runtime.

Implementer must read:
- `services/quant-engine/app/services/statement_importer.py` — `combine_imported_snapshots`, `_merge_terminal_positions`, `_merge_ledger_entries`
- `services/quant-engine/app/services/import_engine.py` — `build_import_bootstrap`
- `services/quant-engine/app/tests/test_importer.py` — existing test patterns to follow

## Acceptance criteria

- [x] A pytest named `test_three_broker_combine_ib_ff_espp` passes, asserting: `importer == "multi_broker"`, all three account IDs in `account_id`, 23 positions (21 IB + VTI + MSFT), `len(positions) == len(ib.positions) + 2`, all three source files in `statement.source_path`, period starts `2025-01-01`, ledger count ≥ IB + FF + ESPP ledger counts minus a small dedup budget (−10), and `statement_totals.starting_nav > 0` (ESPP zero starting_nav does not corrupt the combined total).
- [x] A pytest named `test_import_statements_three_broker_api_function` passes, calling `import_statements([IB2026_path, FF2026_path, ESPP_path])` and asserting the same structural invariants as the combine test above.
- [x] A pytest named `test_import_bootstrap_three_broker_no_crash` passes, calling `build_import_bootstrap([IB2026_path, FF2026_path, ESPP_path], "SPY", {})` and asserting the response is an `ImportedBootstrapResponse`, `overview.sector_allocation` is non-empty, and `history_context.history_start_date` is `"2025-01-01"`.
- [ ] All three tests skip gracefully (return without error) when any required fixture file is absent — no `pytest.skip`, just an early `return`.
- [ ] `python scripts/run_all_tests.py` is green after the new tests are added.
