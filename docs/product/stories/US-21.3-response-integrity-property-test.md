# US-21.3: Engine response-integrity property test

**Epic:** Epic 21 — Testing Strategy & Architecture Hardening
**PRD:** [`epic-21-testing-strategy-hardening.md`](../prd/epic-21-testing-strategy-hardening.md)
**Status:** Done
**Last updated:** 2026-06-10

## Story

As a **portfolio researcher**, I want every engine route to be provably
JSON-strict (no NaN/inf) under a single parametrized test, so that the bug
class that 500'd attribution (2026-06-10) and the correlation routes
(2026-06-10, NaN cache bars) is caught by the suite — for **every** engine,
including ones added later — instead of by my running app.

## Context

Two production 500s in one week came from non-finite floats reaching FastAPI's
strict JSON encoder. Each got a targeted fix + one-off regression, but nothing
guards the *class* across the API surface. This story adds one parametrized
property test that drives each analytics engine route with a standard mocked
portfolio (US-21.2 fixtures) and asserts the response is well-formed strict
JSON. It also audits the remaining shared-OLS consumer —
`risk.py::_build_rolling_factor_loadings` (same `_fit_factor_model` as the
attribution bug) — and adds a non-finite guard there if values can leak.

Implementer must read:
- `app/tests/test_attribution.py::test_nonfinite_window_skipped_and_response_is_json_safe`
  — the pattern to generalize (NaN-injection via monkeypatched `_fit_factor_model`)
- `app/analytics/risk.py` — `_build_rolling_factor_loadings` (where betas/alpha/
  r²/residual-vol flow into `rolling_loadings_*`)
- `app/tests/fixtures.py` (US-21.2) — the standard portfolio + mock installer

## Acceptance criteria

- [x] AC1 — A parametrized test posts a standard mocked portfolio to each of
  these routes and asserts HTTP 200 with a parseable, strict-JSON body:
  `/engines/stress/run`, `/engines/drawdown/run`, `/engines/distribution/run`,
  `/engines/attribution/run`, `/engines/correlation/multi`,
  `/engines/correlation/intra`, `/engines/provenance/run`, `/engines/drift/run`.
  (A 200 already proves no NaN/inf — FastAPI's encoder raises on them — and the
  body is additionally `json.loads`-parsed.)
- [x] AC2 — Each parametrization runs with that engine's `MarketDataService`
  mocked to deterministic synthetic data (no reliance on the conftest autouse
  mocks' module list staying in sync — the property test installs its own).
- [x] AC3 — `_build_rolling_factor_loadings` (`risk.py`) never emits a
  non-finite loading/alpha/r²/residual-vol: a NaN-injection test (monkeypatched
  `_fit_factor_model`) proves degenerate windows yield `None`s (fail-closed),
  not NaN — and a guard is added if the audit finds leakage.
- [x] AC4 — The test file documents the policy: any **new** engine route must be
  added to the parametrization (assert-listed against `app.api.main`'s route
  table so a forgotten engine fails the test, not a code review).
- [x] AC5 — Full backend suite green (network guard active); frontend/tsc
  untouched unless the risk.py guard changes an existing fixture expectation.

## Test plan

Backend (pytest):
- `test_engine_response_integrity.py` (new) — **2 parametrized tests**:
  (1) `test_engine_route_responses_are_strict_json[…]` × 8 routes (AC1/AC2);
  (2) `test_all_engine_run_routes_are_covered` — introspects the FastAPI route
  table for `POST /engines/*` paths and asserts each is either parametrized or
  explicitly waived with a reason (AC4; waiver list: exposure / diagnostics /
  dashboard-history — heavier request contracts, already golden-pinned).
- `test_risk.py` or `test_diagnostics*.py` (extend) — **1 test**: NaN-injected
  `_fit_factor_model` → rolling loadings contain `None` (or the date is
  omitted), never NaN (AC3).

Regression / guardrail:
- Full suite green under the network guard.
- The two existing one-off NaN regressions (attribution, intra-correlation)
  stay green — the property test supplements, not replaces, them.

## Notes / decisions

- **Why 200 is the assertion:** starlette's `json.dumps` raises on NaN/inf
  (that *was* both bugs), so a 200 with parseable JSON is exactly the property
  "no non-finite values reached the response". No custom recursive scan needed.
- **Self-policing coverage (AC4):** the route-table check turns "we forgot to
  add the new engine to the property test" from a review-time hope into a
  test-time failure — the suite enforces its own completeness.
- No financial formula; methodology touched only if the risk.py guard formalizes
  the degenerate-window→null contract rule.
