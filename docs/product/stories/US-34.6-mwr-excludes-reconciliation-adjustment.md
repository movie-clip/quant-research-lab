# US-34.6: Stop the money-weighted return and investment gain from publishing the reconciliation adjustment

**Epic:** Epic 34 — An Answerable Dashboard: Reachable Trust States
**PRD:** [`epic-34-answerable-dashboard-and-reachable-trust.md`](../prd/epic-34-answerable-dashboard-and-reachable-trust.md)
**Status:** Done (2026-08-13)
**Last updated:** 2026-08-13

## Story

As a **portfolio researcher**, I want every performance figure on the Dashboard
to exclude the statement reconciliation, so that the money I am told I made is
money the market gave me and not a bookkeeping entry.

## Context

PRD finding **F-7**, found by US-34.2 and only visible once the returns were
published.

US-31.3 (Epic 31 F-3) established the rule: the terminal state is snapped to the
statement's ending NAV, that correction is an **accounting entry, not a market
move**, and it must never be published as performance. It applied the rule to
the time-weighted return, which withholds the affected day.

**The rule was never applied to the other period-level figures.** Both
Modified Dietz implementations and the investment-gain calculation read
`daily_states[-1].total_portfolio_value` — which *is* the reconciled value — so
each of them silently contains the correction the TWR refuses:

```text
IB2026        reconciliation adjustment = +$1,366.17

  money-weighted return    5.30%   ->   2.95%   (2.35pp of it is the adjustment)
  investment gain      $3,080.88   ->  $1,714.71

FF2026        the whole TWR/MWR divergence is this one day
  time-weighted  0.12%   +   withheld impact 3.63pp   =   money-weighted 3.75%
```

On FF2026 there are **zero external flows**, so the time- and money-weighted
returns should agree; they differ by exactly the adjustment.

**Levels stay reconciled.** The statement's ending NAV is broker truth and is
the right number for `end_value`, the portfolio-value chart, and every level the
researcher reads. This story changes only the figures that claim to be
*performance*. That is the same distinction US-31.3 drew for the cash anchor:
levels are affected, returns must not be.

Implementer must read:
- PRD F-7, and US-34.2's "Findings surfaced while implementing".
- `docs/finance/financial-methodology.md` §Money-Weighted Return (Modified Dietz)
  and §Publication rungs for the replayed return.
- `app/services/dashboard_history_engine.py` → `_compute_money_weighted_return`
  and `_compute_visible_summary`; `app/analytics/performance.py` →
  `build_performance_summary` (the second implementation — both must change, or
  the two paths disagree).

## Acceptance criteria

- [x] AC1 — **Performance figures are computed from the market-derived terminal
  value**, i.e. the terminal `total_portfolio_value` less its
  `reconciliation_adjustment`. This applies to `money_weighted_return_pct` and
  `investment_gain`, in **both** implementations (the dashboard engine's and
  `build_performance_summary`'s), so the two paths cannot disagree.

- [x] AC2 — **Levels are unchanged.** `end_value`, `start_value`,
  `net_contributions`, the daily states and the portfolio-value chart all keep
  the reconciled terminal value — it is the broker's own ending NAV. A test pins
  that `end_value` still equals `statement_totals.ending_nav`.

- [x] AC3 — **The IB2026 figures move by exactly the adjustment.**
  `money_weighted_return_pct` **5.30% → 2.95%** and `investment_gain`
  **$3,080.88 → $1,714.71**, with the $1,366.17 difference pinned against the
  terminal state's own `reconciliation_adjustment`.

- [x] AC4 — **The FF2026 divergence closes to one day.** With zero external
  flows the two returns move from **0.12% vs 3.75%** to **0.12% vs 0.53%**, and
  the residual is pinned as *the terminal day's genuine market move* — not an
  accounting entry. The test asserts that identity directly, so an entry leaking
  back into either statistic fails it.

  > **Residual logged as Epic 34 F-8 / US-34.8.** The remaining 0.41pp is TWR
  > withholding the whole terminal day while MWR now includes its market part.
  > US-31.3 withheld that day because no trustworthy value existed — this story
  > produces one, so the justification is partly gone. Relaxing a US-31.3
  > withholding is a guardrail change and gets its own review rather than a
  > ride-along here.

- [x] AC5 — **A run with no reconciliation is unaffected.** When the terminal
  state carries no adjustment (or a sub-tolerance one) every figure is
  byte-identical to today — this story must not perturb the request path or any
  snapshot that reconciles cleanly.

- [x] AC6 — **The researcher is told.** The Dashboard states that the
  reconciliation is excluded from the gain and the return while the displayed
  portfolio value includes it — otherwise `end_value − start_value −
  net_contributions ≠ investment_gain` reads as an arithmetic bug on screen.

- [x] AC7 — **The methodology says so.** §Money-Weighted Return gains the rule
  and its reason, cross-referenced to US-31.3 — the two are the same guardrail
  applied to two statistics.

## Out of scope

- **Changing the reconciliation itself.** Snapping the terminal state to the
  statement's ending NAV is correct and stays (US-31.3, unchanged).
- **The cash anchor's contribution to `start_value`** — that is F-2 / US-34.3.
  This story does not touch the opening side.
- **Withholding the MWR outright.** A single period statistic blanked for one
  contaminated day would return the Dashboard to silence, which is the failure
  Epic 34 exists to fix. Removing the entry and disclosing is the proportionate
  answer.

## Notes / decisions

- **No new formula.** Modified Dietz is unchanged; only which terminal value
  feeds it. The methodology entry gains the input rule, not a new equation.
- **Why not simply exclude the terminal state?** Dropping the last state would
  also drop a real trading day's market move and shift `end_value` away from the
  broker's ending NAV — losing a level that is correct in order to fix a return.
  Subtracting the recorded adjustment removes exactly the accounting entry and
  nothing else.
- **The screen-arithmetic risk is real** (AC6). Once the gain excludes the
  adjustment, the three displayed numbers no longer reconcile by subtraction. A
  researcher who notices that and is not told why will trust the card less, not
  more — which is why the note is an acceptance criterion rather than a nicety.
