# US-29.1: Defer ChartShell's chart mount by one tick

**Epic:** Epic 29 — Chart First-Render Reliability
**PRD:** [`epic-29-chart-first-render-reliability.md`](../prd/epic-29-chart-first-render-reliability.md)
**Status:** Done
**Last updated:** 2026-07-04

## Story

As a **portfolio researcher**, I want **charts to actually render right after
I import a portfolio**, so that **I don't have to reload the page to see the
Performance chart, Rolling Factor Analysis, or Exposure-tab charts I was just
told are there**.

## Context

Root-caused in the Epic 29 PRD: Recharts' `ResponsiveContainer` measures its
container synchronously on mount; if that mount races a same-commit DOM
insertion of several other new cards (exactly what happens right after an
import resolves and multiple Dashboard/Exposure cards flip from `EmptyState`
to populated content together), the measurement can come back degenerate
(`-1, -1` per the console warning), and — because `ResizeObserver` only fires
on subsequent size *changes*, not to correct a bad initial reading — the
chart can stay invisible until something else (a reload) triggers a fresh
measurement.

**Implementation corrected the original premise mid-story.** The first
attempt deferred the chart mount by one `requestAnimationFrame` tick. Live
browser reproduction (import a real statement, inspect the chart's actual
SVG/path count) proved this insufficient — the chart was still blank. Root
cause of *that*: `requestAnimationFrame` is tied to the next paint and is
**paused indefinitely while `document.hidden` is true**. This matters
specifically because Tauri's native file-picker dialog (used for import) can
blur/hide the webview — exactly the moment this defer needs to fire. Verified
directly: `requestAnimationFrame` did not fire within 3 seconds while
`document.hidden === true`, while `setTimeout(fn, 0)` fired in the same
hidden state in under 1ms (layout is computed synchronously, independent of
paint). Switched the fix to `setTimeout(fn, 0)`, then re-verified against a
real import end-to-end: the Dashboard's Performance & Benchmark chart and the
Exposure tab's Rolling Correlation / Factor Return Attribution charts all
rendered with real, populated SVG paths on the very first render after
import, with `document.hidden` still `true` at the time of inspection.

Read before implementing:
- `apps/desktop/src/app/primitives/ChartShell.tsx` — the shared wrapper every
  chart in the app goes through (`IndexedReturnChart`, `RollingCorrelationChart`,
  `FactorAttributionCard`, `PerformanceBenchmarkCard`, `RollingFactorLoadingsCard`,
  and others)
- `node_modules/recharts/es6/component/ResponsiveContainer.js` — confirms the
  synchronous `getBoundingClientRect()` read inside `useEffect`, and that
  `ResizeObserver`'s callback only fires on a *change* from the last observed
  size, not to self-correct a bad first read
- `apps/desktop/src/test/setup.tsx` — `ResponsiveContainer` is fully mocked
  here (a `cloneElement` passthrough with fixed dimensions); this bug is
  invisible to the test suite by design of that mock, so verification for
  this story is manual/visual, not a new jsdom test of the real measurement
  path

## Notes / decisions

- **rAF → setTimeout correction, with evidence.** The original story assumed
  `requestAnimationFrame` was the right defer mechanism (matching "wait for
  a paint" intuition). Reproducing the bug live in a browser proved that
  wrong: with `document.hidden === true`, a scheduled `requestAnimationFrame`
  callback did not fire within 3 seconds, while `setTimeout(fn, 0)` fired in
  under 1ms in the identical hidden state. Layout (which is what
  `getBoundingClientRect()` needs) is computed synchronously as part of DOM/
  CSS resolution, independent of paint/compositing — so waiting for "the next
  macrotask" is sufficient and doesn't require an actual paint to have
  happened, which is good, because in the Tauri-desktop-file-picker scenario
  this fix targets, a paint might not happen for a while.
- No academic citation — this is a frontend rendering-reliability fix, not a
  financial formula.
