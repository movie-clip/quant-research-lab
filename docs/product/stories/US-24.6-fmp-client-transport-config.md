# US-24.6: Make the FMP client's transport config configurable (escaped URL + timeout)

**Epic:** Epic 24 — Codebase Improvement
**PRD:** [`epic-24-codebase-improvement.md`](../prd/epic-24-codebase-improvement.md)
**Status:** Done
**Last updated:** 2026-07-17

## Story

As a **developer running or testing this platform**, I want every outbound FMP
call to go through configured settings, so that pointing `FMP_BASE_URL` at a
proxy, a mock server, or a recorded fixture actually redirects **all** traffic —
today one endpoint escapes that config and always hits the live vendor host.

## Context

Tech-debt register row **US-24.6 — market-data client config** (Epic 24
backlog), re-validated against the code on 2026-07-17. Two of the three
recorded items are real; the third is a scoping correction.

### F-1 (the real defect) — one endpoint bypasses `fmp_base_url`

`FmpClient.__init__` resolves `self.base_url` from settings
(`clients/fmp.py:29`) and every method routes through `_get()` →
`f"{self.base_url}/{path}"` (`:76`) — **except** `get_etf_holders`, which builds
an **absolute** URL inline (`:183`):

```python
response = self.client.get(
    f"https://financialmodelingprep.com/api/v3/etf-holder/{symbol}",
    params={"apikey": self.api_key},
)
```

Consequences: the ETF look-through holdings call cannot be redirected to a
proxy, a local mock, or a recorded fixture; it is the one hole in the "all
market data flows through the configured client" contract (CLAUDE.md: *"Market
data via FMP client … Never call FMP directly from routes"* — same principle).

**Important subtlety (why the naive fix is wrong):** `fmp_base_url` defaults to
`https://financialmodelingprep.com/stable`, but this endpoint lives on the
**legacy v3 API** (`/api/v3/etf-holder`), which has no `/stable` equivalent.
Simply substituting `self.base_url` would produce
`https://financialmodelingprep.com/stable/etf-holder/…` and **404**. The correct
fix is a *second*, separately configurable base for the legacy-v3 surface —
preserving the API version while making the host configurable.

### F-2 — hardcoded transport timeout

`clients/fmp.py:33` — `httpx.Client(timeout=30.0)`. Every other transport knob
(cache TTLs, rate limit, base URL) is a setting; the timeout is the outlier, so
a slow-network or CI environment cannot tune it without a code edit.

### F-3 — scoping correction: `limit: int = 500` is **not** debt

The register lists `:248` screener `limit=500` as a hardcode. Re-check: it is a
**keyword-argument default on a public method** (`screen_stocks(..., limit: int
= 500)`) — i.e. already caller-overridable, which is the correct API design, not
a buried constant. It also has **no in-app callers** today. Promoting it to
settings would add configuration surface for a value nothing sets. **Recorded as
examined-and-correct; deliberately unchanged** (the US-24.4 / US-24.7 precedent
for correcting register rows).

### Constraint that must not be broken

`get_etf_holders` derives its **cache key** from a path string
(`clients/fmp.py:165`):

```python
cache_identifier = json.dumps({"path": f"api/v3/etf-holder/{symbol}", "params": {}}, sort_keys=True)
```

This identifier is the cache key **and** the in-flight coalescing key. It must
stay **byte-identical**: changing it silently invalidates every cached holdings
entry (16 exist in the local `data/raw/fmp-cache` today) and forces refetches
that require a live `FMP_API_KEY`. The URL construction changes; the cache
identity must not.

Implementer must read: `app/clients/fmp.py` (`__init__` :26-34, `_get` :76,
`get_etf_holders` :160-200, `screen_stocks` :248); `app/core/settings.py`
(the `fmp_*` block); `app/tests/test_market_data.py` (the
`app.clients.fmp.get_settings` mock site — new settings must be set there so
the mock stays honest); the tech-debt register row US-24.6.

## Acceptance criteria

- [x] AC1 — `get_etf_holders` builds its request URL from a **setting**, not an
  absolute literal: no `https://financialmodelingprep.com` string remains
  anywhere in `app/clients/fmp.py`. Overriding the setting redirects the call
  (asserted by inspecting the URL passed to `httpx`).
- [x] AC2 — The legacy-v3 base is its **own** setting (e.g.
  `fmp_legacy_base_url`, default `https://financialmodelingprep.com/api/v3`),
  **not** reused `fmp_base_url` — because that points at `/stable`, where this
  endpoint does not exist. The default preserves today's exact URL
  (`…/api/v3/etf-holder/{symbol}`), so live behaviour is unchanged.
- [x] AC3 — The transport timeout is a setting (e.g.
  `fmp_request_timeout_seconds`, default `30.0`) read in `__init__`; no literal
  `30.0` timeout remains.
- [x] AC4 — **Cache identity is byte-identical**: `get_etf_holders`'s
  `cache_identifier` still serialises `{"path": "api/v3/etf-holder/<SYM>",
  "params": {}}` exactly as before, so existing cached holdings entries stay
  valid and in-flight coalescing is unchanged — pinned by a regression test.
- [x] AC5 — Behaviour-neutral at default settings: with defaults, the URL, the
  timeout, the cache key and the response handling (incl. the stale-cache
  fallback path) are exactly as before. `dashboardGoldens.ts` untouched.
- [x] AC6 — `limit: int = 500` is **unchanged** (F-3 scoping correction), and
  the register row records why.
- [x] AC7 — Every existing `app.clients.fmp.get_settings` mock in
  `test_market_data.py` sets the new attributes explicitly (so a `Mock`
  auto-attribute never silently stands in for a real timeout/URL), and the full
  `run_all_tests.py` + tsc + dead-code gate are green.
  *(Corrected during verify: this AC originally said "the two existing mocks" —
  there is only **one** pre-existing site; the initial count of two included a
  stale `.pyc`. Verified relevant because `httpx.Client` silently **accepts** a
  `Mock` timeout, so an unset attribute would have produced a passing but
  meaningless test.)*

  sentinel host, `get_etf_holders("SPY")` calls `httpx` with

  requested URL is exactly
  `https://financialmodelingprep.com/api/v3/etf-holder/SPY` (live behaviour

  is unchanged by the refactor: the identifier still serialises
  `{"path": "api/v3/etf-holder/SPY", "params": {}}` (regression pin against

  with the timeout taken from `fmp_request_timeout_seconds` (asserted via a

Regression / guardrail:

  those paths is a larger refactor beyond this row.

## Notes / decisions

- **Why a second base URL rather than reusing `fmp_base_url`:** the endpoint is
  on the legacy v3 API while `fmp_base_url` is `/stable`. One setting cannot
  serve both without encoding version-switching logic in the client. Two
  explicit bases is the honest model, and it keeps the default URL identical.
- **Numbering-collision fix (recorded here, own error):** the US-30.5c docs
  close-out logged the deferred ledger-path cash de-dilution item as
  "US-24.8" in the tech-debt register, but **US-24.8 already exists** as a
  Done story (`US-24.8-harden-ibkr-espp-importer-parsing.md`). This story
  renumbers that register row to **US-24.9** so the backlog and the story files
  stop disagreeing.
