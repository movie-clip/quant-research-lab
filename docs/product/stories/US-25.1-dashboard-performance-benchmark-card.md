# US-25.1: Performance & benchmark comparison card

**Epic:** Epic 25 — Dashboard Performance & Risk Summary
**PRD:** [`epic-25-dashboard-performance-risk-summary.md`](../prd/epic-25-dashboard-performance-risk-summary.md)
**Status:** Done
**Last updated:** 2026-07-04

## Story

As a **portfolio researcher**, I want **to see my portfolio's return history
plotted against its benchmark, plus a summary strip of headline performance
numbers, on the Dashboard tab**, so that **I can judge my track record without
leaving the tab I land on first**.

## Context

`DashboardHistoryResult.performance_series` (indexed portfolio + benchmark
points) and `range_metrics[<range>].summary` (`time_weighted_return_pct`,
`money_weighted_return_pct`, `net_contributions`, `start_value`, `end_value`)
are already computed by the backend and already flow into `DashboardAnalysis`
via `composeDashboardAnalysisWithHistory` — `DashboardPanel.tsx` just never
renders them (see Epic 25 PRD for how this gap arose). This story restores the
performance surface only; monthly returns and risk metrics are separate
stories (US-25.2, US-25.3).

Read before implementing:
- `docs/finance/financial-methodology.md` §Indexed Return Series and
  §Portfolio Return Methodology (the formulas this card visualizes — no new
  formula needed)
- `docs/contracts/dashboard-fields.md` "Summary cards" and "Performance
  section" tables (the field-level contract this story re-establishes)
- `apps/desktop/src/features/portfolio/IndexedReturnChart.tsx` (existing
  indexed-series chart pattern on the Exposure tab — reuse its axis/tooltip
  conventions, do not duplicate its logic)
- `DashboardPanel.tsx: normalizePerformanceSeries` — already builds
  `portfolio_index`/`benchmark_index` from `performance_series`; this function
  exists and is exported but currently has no caller in the render tree

## Acceptance criteria

- [x] AC1 — When `result.performance_series` has at least one point, the
      Dashboard tab renders a line chart with portfolio and benchmark indexed
      series (base 100), using the existing `normalizePerformanceSeries`
      output — no new client-side return math.
- [x] AC2 — The chart carries a trust badge reflecting
      `result.run_metadata.return_basis_contract` for the portfolio and
      benchmark paths (e.g. `verified_total_return` vs
      `unverified_adjusted_proxy`) — never a bare "Synthetic"/"Verified" badge
      without checking the actual contract value.
- [x] AC3 — A summary strip shows Portfolio Value, Time-Weighted Return,
      Money-Weighted Return, and Net Contributions for the currently selected
      range, sourced from `range_metrics[selectedRange].summary`.
- [x] AC4 — Any summary-strip field that is `null` renders `n/a`, never `0`
      or a blank cell — per the existing `dashboard-fields.md` unavailable
      rule for these exact fields.
- [x] AC5 — When `range_metrics` is absent/unavailable entirely, the whole
      card (chart + strip) renders a single `EmptyState`, not a partially
      populated card with scattered `n/a` values.
- [x] AC6 — When `run_metadata.investor_economics_status.status = 'withheld'`,
      the card still renders normally for the allowlisted scalars
      (`time_weighted_return_pct`, exact-slice `benchmark_return_pct`/
      `excess_return_pct` per `investor_economics_partial_unlock`) but must
      not display or imply any non-allowlisted investor-economics field —
      this card does not touch `max_drawdown_pct` at all (that's US-25.3,
      sourced from diagnostics instead).
- [x] AC7 — A range selector (matching the ranges already present in
      `range_metrics` keys) lets the researcher switch the summary strip and
      re-anchor the chart; switching ranges never triggers a new network
      fetch (data for all ranges is already present in `result`).

## Notes / decisions

- No new formula: this card is a pure visualization of already-methodology-
  documented outputs (§Indexed Return Series, §Portfolio Return Methodology,
  §Value-at-Risk... not applicable here). No `financial-methodology.md` change
  needed from this story; US-25.4 handles the contract-doc reconciliation for
  the epic as a whole.
- Chart and summary strip are combined into one card (not two) because they
  share the same range selector and the same unavailable-state boundary —
  splitting them would require duplicating the range-selection state.
- AC2 ("trust badge"): implemented as a plain-text label
  (`Portfolio: Verified · SPY: Unverified proxy`) rather than the shared
  `TrustBadge` primitive. `TrustBadge`'s vocabulary (`synthetic`/`unavailable`)
  models the Exposure tab's always-synthetic-history semantics; dashboard-
  history's `return_basis_contract` is a different ladder
  (`verified_total_return`/`price_return_only`/`unverified_adjusted_proxy`/
  `unavailable`) that doesn't map onto it without stretching the primitive's
  meaning. The label still satisfies the AC's actual requirement — it reflects
  the real contract value per-path, never a bare generic badge.
