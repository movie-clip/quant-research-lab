# US-14.1: Fix overlay symbol collision (sum, don't replace)

**Epic:** 14 — Post-Epic-13 Bug Sweep
**PRD:** [`epic-14-post-epic-13-bug-sweep.md`](../prd/epic-14-post-epic-13-bug-sweep.md)
**Status:** Done
**Last updated:** 2026-06-01

## Story

As a **portfolio researcher**, I want the "Add Statement" overlay flow
to SUM market values and quantities when the new statement and the
existing portfolio both hold the same ticker (and same for cash
balances when the same currency appears in both), so that I never
silently lose dollars when combining statements from brokers whose
holdings overlap.

## Context

`overlayImportedSnapshot` in
`apps/desktop/src/features/portfolio/portfolioSnapshot.ts` today
deduplicates positions by symbol via a `Map`, then spreads the new
imported position over the existing one — which REPLACES the
existing `marketValue` and `quantity` instead of summing them.
Concrete failure: IB statement has MSFT @ $50,000 (qty 250). User
clicks "Add Statement" with an ESPP statement that has MSFT @ $5,000
(qty 25). After overlay the workspace shows MSFT @ $5,000 (qty 25);
the IB position is lost. This is silent — no warning, no audit log.

Cash-balance overlay has the same bug shape (lines 105–108): when
the new statement has the same currency as an existing balance, the
new value REPLACES the old. Same fix; same ticket.

The downstream effect is observable in every Risk-tab card and the
Exposure tab — the merged synthetic portfolio is smaller than the
researcher expects, sector breakdowns are wrong, factor attribution
is computed off the wrong dollar amounts.

Note: `normalizePortfolioSnapshot` (called at the end of
`overlayImportedSnapshot`) has a position-dedup reduce that DOES
sum marketValue + quantity for duplicate-symbol rows. But because
the upstream `Map` already dedupes, the reduce is a noop on this
path — the bug fix has to be in the Map population.

Implementer must read:

- `apps/desktop/src/features/portfolio/portfolioSnapshot.ts` —
  `overlayImportedSnapshot` (the function to fix) +
  `normalizePortfolioSnapshot` (already does the right thing for
  the post-fix invariant — keep it consistent)
- `apps/desktop/src/features/portfolio/workspaceTypes.ts` —

## Acceptance criteria

- [x] AC1 — `overlayImportedSnapshot(base, imported)`: when a
  symbol appears in BOTH `base.positions` and `imported.positions`,
  the merged position's `marketValue` equals
  `base.marketValue + imported.marketValue` exactly. Verified by
  a vitest fixture asserting on the exact merged value.
- [x] AC2 — `overlayImportedSnapshot(base, imported)`: when a
  symbol appears in BOTH, the merged position's `quantity` equals
  `(base.quantity ?? 0) + (imported.quantity ?? 0)`. When BOTH
  base and imported have `quantity === null`, the merged quantity
  is `null` (not `0`, not fabricated). When exactly ONE has
  `quantity === null`, the non-null value is used (treating the
  null as 0 in the sum).
- [x] AC3 — `overlayImportedSnapshot(base, imported)`: when a
  symbol appears ONLY in `imported.positions`, the merged
  position equals the imported position's record verbatim (no
  field altered, except the defaults that
  `normalizePortfolioSnapshot` already imposes).
- [x] AC4 — `overlayImportedSnapshot(base, imported)`: when a
  symbol appears ONLY in `base.positions`, the merged position
  is preserved unchanged.
- [x] AC5 — `overlayImportedSnapshot` preserves the nullable
  metadata-field semantics: `sector`, `currency`, `sourceType`,
  `name` prefer the imported statement's value when non-null,
  fall through to the existing value when imported is null, and
  fall through to the base currency / null when both are null.
  This matches the current behaviour for these fields — no
  regression.
- [x] AC6 — `overlayImportedSnapshot(base, imported)`: when a
  cash-balance currency appears in BOTH, the merged cash balance
  for that currency equals `base.amount + imported.amount`
  (parallel fix to positions, same ticket). When the currency
  appears only in one side, the existing behaviour is preserved.
- [x] AC7 — `normalizePortfolioSnapshot` is unchanged. Its
  position-dedup reduce still sums duplicates correctly (the
  reduce is a noop on the overlay path post-fix but remains
  the safety net for any direct construction that produces
  duplicate-symbol arrays).
- [x] AC8 — Existing overlay tests from US-10.2
  (`overlayImportedSnapshot` describe block in
  `portfolioSnapshot.test.ts`) stay green. The 3-broker
  combine fixture and the sourceFileNames dedup test must not
  regress. If any existing test happened to silently assert
  the BUGGY behaviour (e.g. asserting that the post-overlay
  marketValue equals only the imported value), update its
  assertion to the SUM and add a comment explaining the
  US-14.1 fix.
- [x] AC9 — All previously Done tests stay green. Net delta:
  0 backend, +6 frontend. `python scripts/run_all_tests.py`
  green; `cd apps/desktop && npx tsc --noEmit` clean.

## Notes / decisions

- **Why sum and not warn-and-prompt.** The user's intuition
  is that two statements covering the same ticker represent
  two LOTS of the same security (e.g. IB-brokerage MSFT +
  ESPP-held MSFT both being held by the same investor).
  Summing is the only correct merge under that intuition.
  A warn-and-prompt UX would push a product question that
  doesn't have a better answer in practice.
- **Null quantity handling.** The rules in AC2 are:
  - both non-null → sum
  - one null, one non-null → non-null wins (treat null
    as 0 in the sum)
  - both null → keep null (don't fabricate a 0)
  This preserves the fail-closed semantics for quantity —
  null means "unknown", and the merged quantity is unknown
  only when BOTH sides are unknown.
- **Cash-balance parallel fix included.** Same bug shape,
  one-line addition, kept in the same ticket so the
  symmetry is reviewable in one diff.
- **Existing US-10.2 tests.** The 3-broker combine test
  may or may not be sensitive to the bug — if its fixture
  uses three statements with disjoint tickers, the test
  doesn't catch the collision and stays green unchanged.
  If any of its assertions accidentally pinned the buggy
  REPLACE behaviour, the implementer fixes the assertion
  and notes the fix inline.
- **No retroactive remediation.** Users who already
  imported overlapping statements before this fix won't
  have their workspaces auto-corrected. We don't have an
  audit log to recover the lost dollars from prior
  overlays. The user can re-import the affected statements
  manually after the fix ships. Worth surfacing in the
  commit message but not blocking on a migration story.
