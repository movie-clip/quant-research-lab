# US-13.4: Risk tab polish — density, trust-state, a11y verification

**Epic:** 13 — Risk Analytics Tab
**PRD:** [`epic-13-risk-analytics-tab.md`](../prd/epic-13-risk-analytics-tab.md)
**Status:** Done
**Last updated:** 2026-06-01

## Story

As a **portfolio researcher**, I want the Risk tab to feel as visually tight
as the Exposure tab — no oversized page header competing with card titles,
no chapter-break dividers inside a single table — and to pass the same
accessibility baseline established for the Exposure cards in Epic 12, so
that the surface is usable as a real workbench instead of feeling like a
draft.

## Context

US-13.1, US-13.2, US-13.3 (all Done) shipped the three Risk-tab cards
end-to-end. After visual review in the running app, two density problems
surfaced:

1. **Page header collision** — `RiskPanel.tsx` renders `<h2
   className="panel-label">Risk Analytics</h2>` which competes visually
   with the first card's title ("Stress Scenarios", also styled via
   `panel-label` inside CardShell). The user reads two near-identical
   headings stacked. ExposurePanel uses a smaller eyebrow `<p
   className="panel-label">Exposure</p>` followed by an `<h2>` with a
   descriptive subtitle — a cleaner two-tier hierarchy — but the Risk
   tab v1 didn't follow that pattern.

2. **VarDistributionCard section dividers** — the three section headers
   ("PERCENTILES", "TAIL RISK", "DISTRIBUTION SHAPE") use uppercase +
   `letterSpacing: '0.05em'` + `var(--space-md)` top margin, which
   reads as three loud chapter breaks rather than three quiet groupings
   inside a single table. The card's 12 rows feel taller than the
   information density warrants.

This story is the **polish pass** before docs close-out (US-13.5). No
analytics, no schema, no methodology — pure UI density tightening +
cross-card trust-state and a11y audit.

## Acceptance criteria

- [x] AC1 — `RiskPanel.tsx`'s header no longer renders `<h2
  className="panel-label">Risk Analytics</h2>`. The visual treatment
  mirrors ExposurePanel's two-tier pattern: a small eyebrow `<p
  className="panel-label">Risk</p>` (caption-sized) followed by an
  `<h2>` with a short descriptive subtitle (e.g. `"Stress, drawdown,
  and tail-risk views"`). The h2 uses no special className so it picks
  up the default `<h2>` styling from `styles.css` (matching ExposurePanel).
- [x] AC2 — When `snapshot` is null, the no-import helper text
  (`"Import a portfolio to see stress scenarios and other risk
  analytics."` — or any close variant chosen during the polish) renders
  exactly once. The visible header tier above it (eyebrow + h2 subtitle)
  reads as one cohesive block, not as a hero title that dominates the
  page.
- [x] AC3 — When `snapshot` is non-null and all three cards are rendered,
  the rendered "Risk" eyebrow text does NOT visually overpower the
  first card's title ("Stress Scenarios"). The cards' titles remain
  the dominant headings on the page (matching ExposurePanel's hierarchy
  where the card titles are visually heavier than the panel header
  itself).
- [x] AC4 — `VarDistributionCard.tsx`'s `SectionHeader` (used for
  "Percentiles", "Tail Risk", "Distribution shape") no longer uses
  `textTransform: 'uppercase'` AND no longer uses `letterSpacing:
  '0.05em'`. The top margin tightens from `var(--space-md)` to
  `var(--space-sm)` (or smaller). The visual outcome is three quiet
  group labels, not three chapter breaks.
- [x] AC5 — The section headers in VarDistributionCard render as the
  literal mixed-case strings `"Percentiles"`, `"Tail Risk"`, and
  `"Distribution shape"` (matching the file-source casing). They
  still use `var(--font-caption)` and `var(--color-text-muted)` so
  they read as labels, not body text.
- [x] AC6 — Cross-card trust-tooltip wording is consistent for the two
  history-based cards. DrawdownAnalyticsCard and VarDistributionCard
  both refer to "synthetic daily portfolio" (matching phrase) in their
  TrustBadge tooltip. StressScenariosCard keeps its distinct
  factor-shock phrasing (genuinely different computation). The exact
  copy is left to the implementer's judgement, but the two
  history-based tooltips share a common opening clause.
- [x] AC7 — Every nullable cell across the three cards renders the
  literal em-dash character `'—'` (U+2014) when its value is null.
  Verified by spot-check: StressScenariosCard's pct cell when
  `estimated_return_pct: null`; DrawdownAnalyticsCard's recovery cell
  (rendered as "Still underwater" italic, NOT em-dash — keep that
  distinct UX) AND its duration/underwater cells when null;
  VarDistributionCard's StatRow when value is null. No cell renders
  `"0"`, `"n/a"`, blank, or any fabricated default.
- [x] AC8 — Every card has `CardShell` as its outer wrapper (which
  provides `role="region"` + `aria-labelledby`). Verified by source
  inspection across `StressScenariosCard.tsx`,
  `DrawdownAnalyticsCard.tsx`, `VarDistributionCard.tsx` — no card
  hand-rolls a raw `<section>`.
- [x] AC9 — Every chart on the Risk tab is wrapped in `ChartShell`
  with a meaningful `ariaLabel`. DrawdownAnalyticsCard:
  `"Underwater drawdown curve over selected window"`.
  VarDistributionCard: `"Daily return distribution histogram with
  VaR-95 threshold"`. StressScenariosCard has no chart (row-list only
  — no AC9 requirement).
- [x] AC10 — Every `WindowSelector` instance passes an `ariaLabelFn`
  so each button's `aria-label` is descriptive (e.g.
  `"252 trading day window"` rather than the default
  `"252d window"`). Verified across DrawdownAnalyticsCard +
  VarDistributionCard; StressScenariosCard has no window selector
  (point-in-time).
- [x] AC11 — Color is not the sole encoder for any signal on the Risk
  tab. Verified: StressScenariosCard magnitude bars are paired with
  numeric pct text in the same row; DrawdownAnalyticsCard's null
  `recovery_date` is paired with explicit "Still underwater" text;
  VarDistributionCard's loss-tail bars have a tooltip showing the
  bucket range numerically. No new signal added in this story that
  uses color alone.
- [x] AC12 — `designSystem.audit.test.ts` stays 5/5 green. The polish
  pass introduces no hex, no px in inline styles, no hand-rolled
  `attribution-trust-badge` className outside `TrustBadge.tsx`, no

- [x] AC13 — All previously Done tests stay green: 294 backend pytest +

## Notes / decisions

- **This is the only Epic 13 story driven by user-facing UI
  feedback.** US-13.1, 13.2, 13.3 ACs were satisfied
  programmatically; visual review surfaced the density gaps.
  The lesson worth capturing in `ui-polish` SKILL.md
  eventually: the design system enforces tokens + primitives
  but cannot enforce *information density* — a card can pass
  the audit while still feeling visually bloated. Density
  judgements need a human eye.
- **Two-tier header hierarchy** in ExposurePanel uses
  `<p className="panel-label">Eyebrow</p>` + `<h2>Subtitle</h2>`.
  The `panel-label` class is the SMALL caption — it's the
  RiskPanel's mistake to use it AS the h2's class. Plain
  `<h2>` without a className picks up the default browser-ish
  h2 styling that styles.css globally tones down.
- **Methodology unchanged.** No formula touched; trust class
  unchanged (all three cards remain synthetic-history). No
  methodology doc edit.
- **No commit blocker beyond regression.** Existing 294
  backend + 179 frontend must stay green plus the +2 polish
  tests. Tests are intentionally narrow — they pin the specific
  anti-patterns being fixed without over-coupling to visual
  treatment.
- **`update-docs` close-out** ticks the slice-log + status
  rows; methodology + contract docs are not touched in this
  story.
