# US-23.6: Tests, fixtures & golden-pipeline hygiene

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Next phase
**Last updated:** 2026-06-12

## Story

As a **developer of this project**, I want the test suites swept of dead
helpers, skipped/duplicate tests, and un-migrated fixtures, and the test smells
catalogued, so that the suite is all live coverage and the US-21 hardening
(shared fixtures, network guard, frozen goldens, xdist) is actually followed
everywhere.

## Context

Epic 21 established a shared fixtures module (`app/tests/fixtures.py`), a network
guard, frozen-deterministic goldens, and assertion conventions. This story
checks the rest of the suite against that bar: dead test helpers, `@skip`/`xfail`
left lying around, tests duplicating the shared fixtures instead of importing
them, and obsolete golden-adjacent code. It also confirms the golden pipeline's
invariants still hold (no live network in the default run; `git status` clean
after `run_all_tests.py`). Removing a test is only valid if it covered **dead
code already removed** by an earlier sweep — never delete a behavioural test.

Implementer must read:
- `.claude/skills/write-tests/SKILL.md` — the shared-fixtures mandate +
  assertion conventions (US-21.2/21.5).
- `app/tests/fixtures.py` + `app/tests/conftest.py` — the canonical builders +
  autouse guards.
- `docs/architecture/testing-architecture.md` — the golden + layering rules.

## Acceptance criteria

- [ ] AC1 — Backend test files that hand-roll snapshot/market-data builders the
  shared `app/tests/fixtures.py` already provides are migrated to import them
  (per the US-21.2 mandate), or an explicit reason is recorded; duplication is
  removed without changing any test's behaviour or count-of-asserted-facts.
- [ ] AC2 — Dead test helpers (functions/fixtures never used) are removed; any
  `@pytest.mark.skip` / `xfail` / `it.skip` is either re-enabled, deleted (if it
  covered removed code), or annotated with a dated reason — none left silently
  skipped.
- [ ] AC3 — Tests that existed only to cover dead code removed in US-23.2/23.3/
  23.4 are removed *with a reference to the removal*; **no behavioural test is
  weakened or deleted** (the asserted facts about live code are unchanged).
- [ ] AC4 — The golden-pipeline invariants hold: the default `pytest` run makes
  no live network call (network guard), the frozen goldens stay deterministic,
  and `git status` is clean after `python scripts/run_all_tests.py`.
- [ ] AC5 — Test smells (brittle exact-equality on extensible structures missed
  by US-21.5, fixture duplication, over-mocking) are appended to
  `docs/tech-debt-register.md` (area = `tests`) — not fixed here beyond the
  migrations in AC1.

## Test plan

Backend (pytest) + Frontend (vitest):
- Full suite green under network guard + xdist after each change; **test counts
  for live code unchanged** (only dead-code-covering tests removed, with
  references).
- `app/tests/fixtures.py` consumers compile and pass after migration.

Regression / guardrail:
- Frozen goldens determinism intact; `run_all_tests.py` leaves `git status`
  clean.
- `npx tsc --noEmit` clean (frontend test changes).

## Out of scope

- **Adding new coverage** — this is hygiene, not coverage expansion (gaps found
  are recorded for Epic 24).
- **Reworking the golden pipeline or network guard** — they stay as US-21
  shipped them; this story only confirms the invariants.
- **Fixing catalogued test smells beyond fixture migration** — Epic 24.

## Notes / decisions

- **Never weaken behavioural coverage in the name of cleanup.** The only tests
  removed are those whose *only* subject was code deleted earlier in the epic;
  each removal cites the removal commit/story.
- Sequenced after the code sweeps so "tests for removed code" are identifiable.
- No new formula; no methodology change.
