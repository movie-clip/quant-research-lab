# US-30.5b: Gate per-position risk statistics on the minimum observation floor

**Epic:** Epic 30 — Exposure Improvements
**PRD:** [`epic-30-exposure-improvements.md`](../prd/epic-30-exposure-improvements.md)
**Status:** Done
**Last updated:** 2026-07-08

## Story

As a **portfolio researcher**, I want a position's beta, correlation and
volatility withheld until it has enough return history to estimate them, so
that a freshly-listed holding never shows me a confident risk number computed
from two days of data.

## Context

PRD finding **F-9 (Medium)**, verified by US-30.4 — with a wording correction
found while scoping this fix (recorded here, the F-3 precedent):

- **The finding as recorded** named `build_position_risk_contributions`
  (`risk.py:582`), whose per-position `beta`/`correlation` gate only on
  `len >= 2` via `_calculate_beta`/`_calculate_correlation`. **Correction:**
  that public function is **orphaned** — its only caller is one test
  (`test_analytics.py:5384`) and its result type `PortfolioRiskContribution`
  is on no response schema, so it does **not** currently feed any UI. It is a
  latent trap, not a live defect.
- **The live surface** with the same defect class is the *private*
  `_build_position_risk_contributions` (`risk.py:1989`), which feeds the
  surfaced `RiskContributionBreakdownPayload` (Risk Summary card). Its
  per-position **`volatility`** is published whenever `len(returns) >= 2`
  (`risk.py:2025`) — a 2-day annualised volatility for a thin holding.

The methodology contract is unambiguous: §Beta ("len(series) < 20 trading
days: return null") and §Rolling Pearson Correlation's edge cases require
`MIN_DAILY_OBSERVATIONS = 20` (already in `core/constants.py`, but never
imported by `risk.py`). This story applies that floor to the per-position
**published** statistics on both functions.

Deliberately **out of scope**: the covariance-matrix cells
(`_compute_covariance_matrix`, floor `< 2`) are intermediate inputs to the
variance decomposition, not published per-position betas; their reliability
is already surfaced via the payload's `observation_count`, and raising their
floor would shift `portfolio_variance` and every `risk_share` for edge
portfolios beyond the finding's scope. They keep the US-27.3 pairwise-≥2
discipline.

**No golden change:** every IB2026 golden-portfolio position has the full
~250-day history, so all clear the 60-day window's 20-observation floor — the
gate only nulls genuinely under-powered positions. `dashboardGoldens.ts` stays
byte-identical.

Implementer must read: PRD F-9; `analytics/risk.py`
(`build_position_risk_contributions` :582, `_build_position_risk_contributions`
:1989, `_calculate_beta`/`_calculate_correlation` :2197); `core/constants.py`
(`MIN_DAILY_OBSERVATIONS`); methodology §Beta, §Rolling Pearson Correlation,
§Risk Contribution and Concentration.

## Acceptance criteria

- [x] AC1 — A position with fewer than `MIN_DAILY_OBSERVATIONS` (20)
  overlapping return observations has its published per-position statistics
  set to `null`, never a number: `beta`, `correlation` and
  `contribution_to_portfolio_beta` in `build_position_risk_contributions`, and
  `volatility` in `_build_position_risk_contributions`.
- [x] AC2 — A position **at or above** the floor is unchanged: with ≥ 20
  overlapping observations, every statistic is computed exactly as before
  (the gate adds a floor, it does not alter the estimator).
- [x] AC3 — The floor is the shared named constant `MIN_DAILY_OBSERVATIONS`
  imported from `core/constants.py` — not a new literal `20` in `risk.py`
  (the constant already backs the correlation engines; this closes the "never
  imported by risk.py" gap the audit noted).
- [x] AC4 — Trust semantics: a withheld statistic is `null`, and the
  surrounding fields that do not depend on it still render (e.g. a position
  with < 20 obs still shows its `weight` and `market_value`; only the
  estimated statistics are withheld). No fabrication, no zero-fill.
- [x] AC5 — Behaviour-neutral for the committed portfolio: the full suite is
  green and `dashboardGoldens.ts` is **byte-identical** (every IB2026 position
  clears the floor), proving the gate changed no live golden output.

## Test plan

Backend (pytest), `test_analytics.py` (**+4**):
- (1) `build_position_risk_contributions` — a symbol with 19 overlapping
  observations returns `beta = correlation = contribution_to_portfolio_beta =
  None`, while its `weight`/`market_value` are still populated (AC1/AC4).
- (2) the same symbol at exactly 20 observations returns non-null
  `beta`/`correlation` (AC2 boundary).
- (3) `_build_position_risk_contributions` — a position with 19 window
  observations has `volatility = None`; a position with ≥ 20 has a non-null
  `volatility` (AC1/AC2 on the live surface).
- (4) the existing `build_position_risk_contributions` test
  (`test_analytics.py:5384`, currently 3 observations → non-null beta) is
  updated to feed ≥ 20 observations so it still exercises the happy path
  under the new floor (documenting the boundary, not weakening it).

Regression / guardrail:
- The IB2026 risk-summary / concentration golden and diagnostics tests stay
  green **unchanged** (all positions clear the floor).
- Full `run_all_tests.py` + dead-code gate green; `dashboardGoldens.ts`
  byte-identical (AC5).

## Notes / decisions

- **Why gate the orphaned function instead of deleting it:** the honest fix
  for a latent trap is to make it correct, so that a future wiring cannot
  reintroduce the defect. Deleting it is a separate dead-code judgement
  (Epic 24). Gating costs one guard and a test.
- No new formula — this adds the documented minimum-observation floor
  (§Beta) to code that omitted it. No citation required.
- The single-ticket structure reflects the fix's size: one constant import,
  two guards, four tests, one methodology line. It is deliberately small.
