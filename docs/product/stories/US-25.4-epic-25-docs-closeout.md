## Story

As a **maintainer**, I want **the Dashboard contract and product-state docs to
match what US-25.1–25.3 actually shipped**, so that **the next agent (or
researcher) doesn't inherit the same doc-drift this epic was created to fix**.

## Context

This epic exists because `dashboard-fields.md` and
`current-product-state.md` described Dashboard sections that had been removed
from `DashboardPanel.tsx` across several earlier, undocumented refactors. This
story is the reconciliation pass, run only after US-25.1–25.3 land so it
describes the *final* shipped shape rather than the intermediate one.

Also closes two methodology gaps surfaced during this epic's origin review:
- `money_weighted_return_pct` is a live, contract-documented field with no
  formula section in `financial-methodology.md`.
- `docs/finance/financial-methodology.md` §Risk Contribution and Concentration
  is two sentences of prose with no formulas, despite
  `DiagnosticsRiskConcentrationSummary` (`factor_hhi`, `position_hhi`, top-N
  risk shares) being fully implemented and now rendered (US-25.3).

## Notes / decisions

- HHI citation: Hirschman, A.O. (1964), "The Paternity of an Index,"
  *American Economic Review* 54(5): 761-762 (or the equivalent Herfindahl
  1950 dissertation precedent) — standard citation pair for this index in
  finance/economics literature; either is acceptable, cite one.
- Modified Dietz citation: Dietz, P.O. (1966), "Pension Fund Investment
  Performance — What Method to Use When," *Financial Analysts Journal*
  22(1): 83-89 (the return-measurement problem the Dietz method solves) —
  and CFA Institute GIPS Standards, "Modified Dietz Method" guidance, which
  is the day-weighted-cash-flow variant the implementation follows (weight
  = fraction of the period remaining after the flow, not a full 0/1 mid-point
  split).
- Bug found and fixed while writing the HHI/risk-share methodology section:
  cross-checking `financial-methodology.md`'s new formula against
  `risk.py`'s actual implementation revealed `top_*_risk_share` fields are
  0-1 fractions (`_sum_top_risk_shares`), but `RiskSummaryCard.tsx` (US-25.3)
  rendered them with a bare `%` suffix — a ~100x display error that had
  passed US-25.3's own tests because those tests used test values
  (`42.5`, `70.1`, …) that happened to look plausible as already-percentage
  numbers. Fixed with `formatShareAsPct` (multiplies by 100) and corrected
  the test fixture to use real 0-1 fractions. This is exactly the kind of
  premise-vs-implementation mismatch that writing the methodology doc
  (which forces reading the real formula) is good at catching — worth
  keeping "write the methodology section before/alongside the UI" as a
  discipline for future numeric-display work, not just an after-the-fact
  formality.
