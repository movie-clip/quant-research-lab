# US-23.2: Backend dead-code sweep — analytics, schemas, domain, instruments

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Done
**Last updated:** 2026-06-19

## Story

As a **developer of this project**, I want the pure-logic backend core
(`app/analytics/`, `app/schemas/`, `app/domain/`, `app/instruments/`) swept of
confirmed-dead code and its hardcodes/anti-patterns catalogued, so that the
financial heart of the engine reads as only-live code without changing any
formula or result.

## Context

These modules are the deterministic core: factor/correlation/attribution/risk/
drift/portfolio analytics, the Pydantic contract schemas, the ledger domain
model, and the instrument registry. Using the US-23.1 detectors plus manual
confirmation under the removal protocol, this story deletes unused functions/
classes/schemas/branches (e.g. the orphaned admission-disposition schema once
US-23.4 removes its FE consumer — coordinate order) and records every hardcode/
magic-number/smell into `docs/tech-debt-register.md`. **No formula, threshold,
or trust-state behaviour changes** — only removals of unreferenced symbols.

Implementer must read:
- `docs/tech-debt-register.md` + the removal protocol (US-23.1).
- `docs/finance/financial-methodology.md` — to confirm a "dead" analytics helper
  is not the documented code path for a live formula before deleting.
- `app/analytics/*`, `app/schemas/*`, `app/domain/*`, `app/instruments/*`.

## Acceptance criteria

- [x] AC1 — Every symbol removed from these modules is **confirmed dead** by the
  protocol: no static or dynamic reference (incl. Pydantic validators,
  `schema_version` round-trips, registry/dispatch lookups), and not the
  documented code path for any live methodology formula. A short removal list
  (symbol → why-dead) is recorded in the slice log.
- [x] AC2 — `vulture`/`ruff` report **no remaining unused** symbols in these four
  modules except entries on the reasoned allowlist (dynamic-use false positives);
  the allowlist additions name their reason.
- [x] AC3 — **No behaviour change**: full `python scripts/run_all_tests.py` green;
  dashboard goldens untouched; no methodology doc edit required (if a deletion
  would require one, it was not a pure dead-code removal → out of scope, recorded
  instead).
- [x] AC4 — Hardcodes / magic numbers / anti-patterns found in these modules are
  appended to `docs/tech-debt-register.md` (area = `backend/analytics-schemas`),
  each with `file:line`, category, severity, effort — **not fixed here**.
- [x] AC5 — Any schema field removed as dead is reconciled with its TS mirror and
  contract doc in the same pass (or deferred to US-23.5 with a register note if
  it crosses the seam) — never leave a dangling TS type or contract row.

## Test plan

Backend (pytest):
- Full suite green under network guard + xdist after each removal (the gate).
- Any test that only existed to cover now-deleted dead code is removed with it
  (and noted); no *behavioural* test is weakened.

Regression / guardrail:
- `npx tsc --noEmit` clean if any schema's TS mirror changed.
- Goldens untouched; `git status` clean after `run_all_tests.py`.
- Methodology doc unchanged (proof the removals were behaviour-neutral).
