# US-17.2: Diversification summary metrics

**Epic:** Epic 17 — Intra-Portfolio Correlation
**PRD:** [`epic-17-intra-portfolio-correlation.md`](../prd/epic-17-intra-portfolio-correlation.md)
**Status:** Done
**Last updated:** 2026-06-05

## Story

As a **portfolio researcher**, I want two headline diversification scalars —
the Diversification Ratio and the Effective Number of Bets — alongside the
intra-portfolio correlation heatmap, so that I can quantify *how much*
diversification my holdings actually deliver, not just eyeball the pairwise
grid.

## Context

US-17.1 shipped the holdings × holdings correlation matrix + average pairwise
correlation in the `IntraCorrelationHeatmap` card. This story adds two
well-founded summary measures derived from that same synthetic-history data:

- **Diversification Ratio** (Choueifaty & Coignard 2008): weighted-average
  standalone volatility ÷ realised portfolio volatility. DR = 1 means no
  diversification benefit; DR > 1 quantifies the volatility reduction from
  imperfect correlation.
- **Effective Number of Bets** (Meucci 2009): the entropy of the normalised
  eigenvalue spectrum of the correlation matrix. ENB = 1 when one component
  explains everything; ENB → N when risk is spread across independent bets.

Both extend the existing `IntraCorrelationResult` and render in the card's
existing summary strip. ENB requires an eigendecomposition; the dependency
decision is already made — **numpy is approved** (`numpy.linalg.eigvalsh`) and
is introduced in this story.

## Acceptance criteria

- [x] AC1 — The card's summary strip shows a **Diversification Ratio** value
  (2 decimals, e.g. `1.42`) when available. When the engine returns `null`, the
  field reads an explicit `Unavailable` label — never `0` or a blank.
- [x] AC2 — The card's summary strip shows an **Effective Number of Bets** value
  (1 decimal, e.g. `3.2`) when available. When the engine returns `null`, the
  field reads an explicit `Unavailable` label — never `0` or a blank.
- [x] AC3 — The engine computes `diversification_ratio = Σ wᵢσᵢ / σ_p`, where
  `wᵢ` are current market-value weights renormalised over the priceable
  universe, `σᵢ` is the population stdev of holding i's daily returns over the
  window, and `σ_p` is the population stdev of the synthetic portfolio's daily
  returns over the window. It is `null` when `σ_p` is 0 or fewer than 20
  portfolio daily returns exist.
- [x] AC4 — The engine computes `effective_number_of_bets = exp(−Σ pₖ ln pₖ)`
  over the normalised eigenvalues `pₖ = λₖ / Σλ` of the holdings correlation
  matrix. It is `null` when there are fewer than 2 holdings, when **any
  off-diagonal matrix cell is null** (the matrix is not fully populated), or when
  the matrix is not positive-semidefinite. Tiny-negative eigenvalues from
  floating-point noise are clamped to 0 (`0·ln 0 ≡ 0`).
- [x] AC5 — Both values carry **synthetic** trust (they derive from current
  holdings applied to historical prices). When the card's top-level
  `trust='unavailable'` (fewer than 2 priceable holdings), the summary strip is
  not shown at all (existing EmptyState path), so no diversification scalar is
  fabricated.
- [x] AC6 — `numpy` is declared in `services/quant-engine/requirements.txt` and
  the backend imports cleanly; the ENB path is the only consumer.
- [x] AC7 — `npx tsc --noEmit` is clean; the design-system audit stays green
  (`IntraCorrelationHeatmap.tsx` already in the audited set — no hex/px
  introduced); all US-17.1 backend + frontend tests stay green.

## Out of scope

- No clustering, dendrogram, or PCA **factor extraction** beyond the single ENB
  scalar.
- No rolling time-series of DR/ENB — point-in-time for the selected window only.
- The pairwise matrix, average pairwise correlation, and most/least pair are
  US-17.1 (already shipped) — not re-touched here except to read the matrix.
- No optimizer / target weights / max-diversification portfolio construction
  (Choueifaty & Coignard's MDP is a construction method; this story only
  *reports* DR, it never proposes weights — no-execution guardrail).

## Notes / decisions

- **numpy scope**: numpy enters the engine solely for the ENB
  eigendecomposition (`numpy.linalg.eigvalsh`, which is appropriate for a
  symmetric matrix). DR and `population_stdev` stay pure-Python. After adding
  numpy to `requirements.txt`, ensure it is installed in the engine environment
  (`pip install -r requirements.txt`) before running tests.
- **ENB requires a complete matrix**: the eigendecomposition needs a fully
  numeric correlation matrix. If any off-diagonal cell is `null` (a
  sub-threshold pair from US-17.1), ENB is `null` — fail-closed, never
  zero-filled. This is stricter than DR, which tolerates per-holding gaps.
- **σ_p reuse**: the synthetic portfolio daily return series is exactly the one
  `correlation_engine.py` already derives — `total_portfolio_value` per
  `_build_synthetic_snapshot_history_states` state → `_returns_from_price_series`.
  Reuse that construction; do not re-derive portfolio returns a third way.
- **Academic precedent** (already in methodology §Intra-Portfolio Correlation):
  Choueifaty, Y. & Coignard, Y. (2008), "Toward Maximum Diversification,"
  *Journal of Portfolio Management* 35(1) — Diversification Ratio; Meucci, A.
  (2009), "Managing Diversification," *Risk* 22(5) — Effective Number of Bets
  via eigenvalue-spectrum entropy.
- **Research brief**: Epic 17 PRD + methodology §Intra-Portfolio Correlation.
