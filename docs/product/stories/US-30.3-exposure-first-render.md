# US-30.3: Exposure-tab first-render reliability — self-fetching drift panel + Since-Import anchor

**Epic:** Epic 30 — Exposure Improvements
**PRD:** [`epic-30-exposure-improvements.md`](../prd/epic-30-exposure-improvements.md)
**Status:** Done
**Last updated:** 2026-07-08

## Story

As a **portfolio researcher**, I want the vs-Market drift chart to appear the
moment I open the Exposure tab on any imported portfolio — with a meaningful
"Since Import" window — so that I never have to poke the benchmark dropdown to
make the panel render, and the since-import view actually covers my statement.

## Context

PRD findings F-4 and F-5 (verified 2026-07-08).

**F-4 (blank chart until dropdown):** the drift panel is props-only; App owns
`driftResult` and fetches drift in `analyzeExposureSnapshot`
(`App.tsx:483`) — but the *restore* path `analyzeRestoredSnapshot`
(`App.tsx:553`) never calls `runDriftEngine`, so on a restored session
`driftResult` stays `null` and the panel shows "No drift data" until
`handleDriftBenchmarkChange` (the dropdown, `App.tsx:695`) fires a fetch.
The fix follows the project's documented **self-fetching component pattern**
(`FactorAttributionCard`, `BenchmarkCorrelationTable`): the panel takes a
`snapshot` prop, owns a `useEffect([snapshot, benchmark])` fetch with
`'idle' | 'loading' | 'error' | 'done'` state and a cancellation flag. This
kills the whole bug class (no analyze path can "forget" to fetch drift) and
removes the App-level `driftResult` / `driftError` / `driftBenchmark` /
`handleDriftBenchmarkChange` / `driftPromise` machinery. The panel is fed
App's already-reactive `dashboardSnapshot` (`App.tsx:306`, the workspace
`PortfolioSnapshot` that carries US-30.2's `fxRates`), so
`runDriftEngine(snapshot: PortfolioSnapshot, benchmark)` keeps its exact
signature and every US-30.2 fx test stays green.

**F-5 (dead "Since Import" window):** `since_import_date =
request.imported_at.date()` (`drift_engine.py:174`) is the *import timestamp*
(≈ today), so the window spans <2 valuation dates and always reports
`unavailable`. The meaningful anchor is the **statement period start** — the
beginning of the imported statement's coverage — parsed from
`request.statement_period` (e.g. `"2026-01-01 - 2026-06-30"`), falling back to
`imported_at` only when no period is available.

## Notes / decisions

- **Why self-fetch over patching `analyzeRestoredSnapshot`:** the two-line
  patch (add `runDriftEngine` to the restore path) would fix this instance,
  but drift has three parallel analyze paths and the bug is "one path forgot
  to fetch." Self-fetching makes the omission structurally impossible and
  matches the documented pattern (`FactorAttributionCard`,
  `BenchmarkCorrelationTable`) — the durable fix, and it net-removes App
  state.
- **Signature preserved:** the panel is fed the workspace `PortfolioSnapshot`
  (`dashboardSnapshot`), not `result.snapshot` (`ImportedSnapshot`), so
  `runDriftEngine(snapshot: PortfolioSnapshot, benchmark)` and the US-30.2
  `fxRates` plumbing are untouched — this is the one place the drift panel
  differs from the other self-fetching cards, and it is deliberate.
- **No new formula:** F-5 changes only which date anchors an existing window;
  §Indexed Return Series already defines the window math. No citation needed.
- `statement_period` parse reuses the ISO `"YYYY-MM-DD - YYYY-MM-DD"` shape
  the importers normalize to (US-28.1); guard a malformed value by falling
  back to `imported_at` (fail-safe, never crash the engine).
