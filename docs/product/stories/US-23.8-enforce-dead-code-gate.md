# US-23.8: Enforce the dead-code detection floor in the canonical test gate

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Next phase
**Last updated:** 2026-06-12

## Story

As a **developer of this project**, I want the dead-code detectors wired into
the canonical test gate (`scripts/run_all_tests.py`) as a zero-findings check,
so that once Epic 23 has cleaned the baseline, **newly-introduced unused/dead
code fails the suite automatically** — and the project never needs another
manual cleanup epic.

## Context

US-23.1 installed the detectors (Python: `ruff` unused-rules + `vulture`;
TypeScript: `knip` + `tsconfig` `noUnusedLocals`/`noUnusedParameters`) but
deliberately did **not** gate on them — the pre-cleanup baseline was dirty.
After US-23.2–23.7 remove the dead code and reconcile contracts, the baseline is
clean, so this **tail** story turns the detectors into an enforced gate: a new
"Dead-code gate" step in `run_all_tests.py` runs `knip` + `ruff` + `vulture`
with zero-tolerance (a non-empty finding fails the run), backed by a committed,
reasoned **allowlist** for the legitimate dynamic-use false positives (pytest
fixtures, Pydantic validators, FastAPI route handlers, `schema_version`
persistence sanitizers, CLI entry-point scripts). This is sequenced **last** in
the epic because the gate can only be green once the baseline is clean.

**Tool choice (researched):** `knip` is the enforcement tool for TypeScript —
it catches unused **exports / types / files / dependencies** across the project
(the dead-export class), which `tsc`'s `noUnusedLocals` (in-file only) and an
ESLint `no-unused-vars` rule (also in-file only, and redundant with `tsc`) do
**not** catch. ESLint is therefore not adopted for this goal. `ruff` + `vulture`
are the Python equivalents (in-file + whole-program).

Implementer must read:
- `docs/product/stories/US-23.1-detection-tooling-and-register.md` — the
  detectors + allowlist this story promotes to a gate.
- `scripts/run_all_tests.py` — the canonical gate to extend.
- `docs/architecture/testing-architecture.md` + `CLAUDE.md` — where the gate is
  documented.

## Acceptance criteria

- [ ] AC1 — `scripts/run_all_tests.py` runs a **"Dead-code gate"** step that
  executes `knip` (frontend) and `ruff` unused-rules + `vulture` (backend) and
  **fails the run (non-zero exit) on any finding** not covered by the committed
  allowlist — alongside the existing goldens / pytest / vitest steps.
- [ ] AC2 — The gate is **green on the cleaned baseline**: with US-23.2–23.7
  landed, `python scripts/run_all_tests.py` passes including the new step, with
  no findings outside the allowlist.
- [ ] AC3 — The allowlist is **committed and reasoned**: each entry names why the
  symbol is a false positive (dynamic/reflective/persistence/CLI use), so the
  gate's signal stays trustworthy and the allowlist doesn't become a silent
  dumping ground. (A lint of the allowlist — every entry has a reason — is part
  of the deliverable.)
- [ ] AC4 — A newly-introduced unused export/file/import (a deliberate test
  case during development, not committed) is shown to **fail** the gate — proving
  the enforcement actually catches regressions, not just passes on clean code.
- [ ] AC5 — `tsconfig` `noUnusedLocals`/`noUnusedParameters` (from US-23.1) stay
  enabled and `npx tsc --noEmit` is part of the green gate (or explicitly run by
  it), so in-file unused code is caught too.
- [ ] AC6 — The gate is **documented**: `CLAUDE.md` Development Commands and
  `docs/architecture/testing-architecture.md` describe the dead-code gate, how to
  read a failure, and how to (rarely, with a reason) add an allowlist entry.
- [ ] AC7 — No behaviour change to application code; the gate is tooling-only.
  Full suite + gate green; goldens untouched; `git status` clean after the run.

## Test plan

This is a tooling/gate story; the "tests" are the gate itself behaving correctly.

- `python scripts/run_all_tests.py` green **including** the new dead-code step on
  the cleaned baseline (AC2).
- A scratch unused export added locally makes the gate fail (AC4), then removed —
  demonstrated in the slice log, not committed.
- Backend pytest + frontend vitest unchanged and green (the gate is additive).
- `npx tsc --noEmit` clean with the unused-flags on.

Regression / guardrail:
- The gate must not introduce non-determinism or network use (knip/ruff/vulture
  are static and offline — consistent with the US-21.1 network guard).
- Dashboard goldens untouched; the gate adds bounded wall-time (record it).

## Out of scope

- **Adopting ESLint / a style ruleset** — not needed for the dead-code goal
  (`tsc` + `knip` cover it); a broader lint config is a separate decision.
- **Acting on findings** — by this point the baseline is clean (US-23.2–23.7);
  this story only *enforces* it.
- **CI integration** — there is no CI; the gate lives in the local canonical
  runner. (If CI is added later, it runs the same `run_all_tests.py`.)
- **Gating on coverage %** — out of scope (Epic 21 non-goal stands).

## Notes / decisions

- **Why this is a separate tail story, not part of US-23.1:** the gate can only
  be green after the baseline is clean (US-23.2–23.7). Enabling enforcement
  before the sweep would make every run red. Sequenced last for that reason.
- **Why knip over ESLint for enforcement:** the failure mode that accumulates is
  unused *exports / files* (the disposition-plumbing class). `tsc`
  `noUnusedLocals` and ESLint `no-unused-vars` only see *within* a file; `knip`
  sees the whole import graph. Adding ESLint would add maintenance without
  closing the gap this epic exists to close.
- **The allowlist is the integrity risk:** if it grows unreasoned it silently
  re-opens the door. AC3's "every entry has a reason" lint keeps it honest.
- No new formula; no methodology change.
