# US-27.8: Surface FX-fallback trust + fix the drift-window return basis

**Epic:** Epic 27 — Financial Calculation Correctness
**PRD:** [`epic-27-financial-calculation-correctness.md`](../prd/epic-27-financial-calculation-correctness.md)
**Status:** Backlog
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher**, I want a missing FX rate to degrade trust
instead of silently valuing a EUR position at a 1:1 USD rate, and I want the
Exposure drift panel's windowed returns to measure performance rather than
cash-flow and trade activity, so both broker-path surfaces obey the same
no-silent-fallback and cash-flow-neutral rules as the rest of the product.

## Context (audit findings F9 + F10)

**F9 — silent FX fallback.** `engine/portfolio_state.py` `to_base_currency`:

```python
fx_rate = self.fx_history.get(fx_key)
if fx_rate is not None:
    return value * fx_rate
return value          # ← EUR treated as USD, silently
```

No trust degradation, no note. Worse, `services/drift_engine.py` calls
`build_daily_portfolio_states(..., fx_history={})` — so on the drift path
**every** non-base-currency position is always mis-valued by the raw rate
being skipped. Violates "trust semantics over fabrication / never silently
fallback".

**F10 — drift return is not a return.** `drift_engine._portfolio_return` =
`last.total_market_value / first.total_market_value − 1` over ledger-replayed
states. A mid-window BUY moves cash into positions and shows up as
"portfolio return"; deposits/withdrawals contaminate it the same way. The
benchmark spread is then misleading. The row's note also mis-describes the
basis ("current holdings applied to historical prices" — the engine actually
replays the ledger). Fix: compute the window return by compounding the
cash-flow-neutral TWR daily series (§Portfolio Return Methodology) over the
window's states — the formula already exists (`_time_weighted_daily_return`
in `analytics/performance.py`) — and correct the note. The indexed
`daily_series` (§Indexed Return Series) documents value_t = market value; if
kept value-based, its label must say "value, not return" or it should be
rebased on the TWR chain consistently with the windows — decide and document.

Implementer must read:
- `engine/portfolio_state.py` (`to_base_currency`, state assembly),
  `services/drift_engine.py`, `analytics/performance.py`
  (`_time_weighted_daily_return`).
- `MarketDataService.get_fx_history` (exists, currently zero callers — the
  natural source for real FX rates on the drift/dashboard paths; verify its
  FMP behaviour empirically before wiring, per the Epic 26 brief's warning).
- Methodology §Portfolio Return Methodology + §Indexed Return Series;
  `docs/contracts/drift-fields.md` (or the drift section of the exposure
  contract doc).

## Acceptance criteria

- [ ] AC1 — A missing FX rate never silently converts at 1.0: the affected
  valuation path surfaces an explicit degraded state (per-state or per-run
  flag propagated to the consuming response's trust/note) — the value may
  still be computed, but the claim is downgraded.
- [ ] AC2 — Drift windows' `portfolio_return_pct` is cash-flow-neutral: a
  fixture with a mid-window deposit+BUY and flat prices reports ~0% (today it
  reports the deposit as return); a fixture with a real price move and no
  flows is unchanged vs today.
- [ ] AC3 — The drift note/label states the actual basis (ledger replay, TWR
  chain) — no "current holdings applied to historical prices" claim on this
  path.
- [ ] AC4 — The `daily_series` basis decision (value-indexed vs TWR-indexed)
  is made, implemented, labelled, and documented in §Indexed Return Series.
- [ ] AC5 — Where real FX rates are wired in (if chosen over pure
  degradation), `get_fx_history`'s symbol resolution is verified empirically
  first and the finding recorded; otherwise the drift path's permanent
  degradation for non-base positions is explicit.
- [ ] AC6 — Methodology + drift contract doc updated; goldens regenerated
  deliberately if dashboard-history values shift (FX flag only → likely
  golden-neutral; TWR drift windows → drift fixtures shift).
