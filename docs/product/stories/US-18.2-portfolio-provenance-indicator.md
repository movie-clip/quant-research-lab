# US-18.2: Portfolio-level data-sources indicator

**Epic:** Epic 18 — Secondary Market-Data Provider

**Status:** Done

## Story

As a **portfolio researcher**, I want one clear "Data sources" indicator on the
Exposure tab showing which of my holdings are priced by the secondary provider
(Yahoo Finance) versus the primary (FMP), so that I always know my data
provenance at a glance — without hunting for a per-card marker.

## Context

US-18.1 added the Yahoo fallback and a provenance marker **on the Intra-Portfolio
Correlation card only**. Provenance is portfolio-wide (a holding is Yahoo-sourced
regardless of which analytic shows it), so rather than repeat the marker on every
history-based card, this story surfaces it **once** as a portfolio-level
indicator on the Exposure tab. (Design decision: a single source-of-truth panel,
not per-card badges — chosen 2026-06-05.)

A small dedicated engine resolves provenance per holding by doing a short
market-data probe (which provider answers) and reading
`MarketDataService.last_fetch_meta[...]['vendor']` — no full-history refetch.

## Acceptance criteria

- [x] AC1 — A "Data sources" indicator is visible on the Exposure tab when at
  least one holding is priced by the secondary provider (Yahoo Finance). It names
  the count and the Yahoo-sourced symbols (e.g. "7 holdings via Yahoo Finance
  (secondary source): VUAA, SXRV, …").
- [x] AC2 — When **every** holding is FMP-sourced, the indicator either renders a
  quiet "all holdings via FMP (primary)" state or is omitted — never implies a
  secondary source that isn't there.
- [x] AC3 — Holdings for which **neither** provider has history are listed
  separately as unpriced (e.g. "N holdings with no price history: …") — never
  silently merged with the Yahoo or FMP groups.
- [x] AC4 — The engine determines each holding's provenance from
  `MarketDataService.last_fetch_meta` vendor after a short probe; vendor is one of
  `fmp` / `yfinance`, or the holding is classified `unavailable` when no rows are
  returned. No value is fabricated.
- [x] AC5 — Provenance is a source label, **not** a return-basis trust claim: the
  panel does not assert `verified`/`synthetic` for the analytics — it only states
  the data source. (The synthetic-history trust badges remain on the individual
  analytic cards.)
- [x] AC6 — The panel renders via the Epic 12 design system (tokens only, no
  hex/px; the design-system audit stays green with the new file added to its set)
  and uses a non-color encoder (text label) for the source distinction.
- [x] AC7 — `npx tsc --noEmit` is clean; `python scripts/run_all_tests.py` green
  (only the pre-existing FMP-offline failures remain); existing Exposure tests
  stay green.

## Out of scope

- **Per-card provenance markers** on factor model / drift / rolling-risk /
  multi-benchmark — explicitly rejected in favour of the single indicator. The
  intra card keeps its existing inline marker (US-18.1); it is not removed here.
- **No return-basis/trust changes** — provenance is a source label only.
- **No new market-data provider** beyond FMP + yfinance (US-18.1).
- **No per-holding history display** — the panel only states the source.

## Notes / decisions

- **Single source of truth over repetition.** Provenance is portfolio-wide, so
  one Exposure-tab indicator communicates it once; repeating a marker on every
  card would be redundant plumbing for the same fact. (User decision 2026-06-05.)
- **Cheap probe.** Provider identity does not depend on the window (FMP 402s a
  symbol regardless; Yahoo serves it regardless), so the engine probes a short
  lookback purely to populate `last_fetch_meta` vendor — no full-history refetch;
  cached histories make it near-free.
- **Provenance ≠ trust.** Yahoo data is still `verified_adjusted_close`
  return-basis (US-18.1); the panel states *where the data came from*, distinct
  from the synthetic-history trust badges on the analytic cards.
- No new financial formula; no academic citation required.
