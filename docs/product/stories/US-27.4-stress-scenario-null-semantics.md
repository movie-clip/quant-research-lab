# US-27.4: Stress scenarios — null semantics for missing loadings

**Epic:** Epic 27 — Financial Calculation Correctness
**PRD:** [`epic-27-financial-calculation-correctness.md`](../prd/epic-27-financial-calculation-correctness.md)
**Status:** Done
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher**, I want a stress projection built from an
incomplete factor snapshot to say so, so I never mistake a
half-the-factors-missing estimate for a full-confidence one.

## Context (audit finding F5)

`analytics/risk.py` `build_stress_scenarios`:

```python
estimated = sum((latest_snapshot.get(factor) or 0.0) * shock for factor, shock in shocks.items()) * 100
```

Every factor whose latest loading is `None` contributes **0** to the scenario,
silently. `stress_engine.py` fails closed only when *all* loadings are null.
So a portfolio with loadings for 9 of the 12 shocked factors gets a projection
presented identically to a complete one. This violates the §Stress Scenarios
contract rule ("unavailable stress support must return null, not fabricated
zeroes"). The `or 0.0` also conflates a genuine 0.0 loading with a missing one
(same number, different meaning).

Design decision to make in T-27.4.1 (and record in the methodology):
- **Option A (strict):** any missing shocked-factor loading → that scenario's
  `estimated_return_pct = None`, `status='unavailable'`.
- **Option B (partial, recommended):** compute over available loadings but add
  per-scenario degradation — e.g. `status='partial'` +
  `missing_factors: [...]` (schema addition) — so the UI renders the caveat.
  Recommended because a 15/16-loading snapshot is common and still useful;
  strict nulling would make the card mostly unavailable for thin histories.

Implementer must read:
- `analytics/risk.py` `build_stress_scenarios` + `STRESS_SCENARIOS` +
  `_build_current_factor_snapshot` (where the fallback-across-windows loading
  comes from).
- `services/stress_engine.py` (`_has_any_factor_loading` guard) and
  `schemas/stress.py` / `schemas/reconciliation.py` `StressScenarioResult`.
- `docs/contracts/risk-fields.md` (stress section) + the US-24.2 pinned
  stress-projection golden test in `test_analytics.py`.

## Acceptance criteria

- [x] AC1 — A missing loading is never silently zero-filled: with any shocked
  factor's loading `None`, the scenario result carries an explicit degraded
  signal (per the chosen option) that the frontend renders.
- [x] AC2 — A genuine `0.0` loading is treated as a real value (uses `is None`
  checks, not falsiness).
- [x] AC3 — Full-snapshot behaviour is numerically unchanged (US-24.2 pinned
  stress golden test still passes without edit).
- [x] AC4 — The all-null path still returns the existing
  `trust='unavailable'` response shape.
- [x] AC5 — Methodology §Stress Scenarios documents the partial-loading rule;
  `risk-fields.md` documents any new field; TS types mirror the schema.

## Test plan

  chosen option) — never a bare full-confidence number.
