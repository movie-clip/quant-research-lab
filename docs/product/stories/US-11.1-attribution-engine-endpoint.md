# US-11.1: Attribution engine + endpoint

**Epic:** Epic 11 — Factor Return Attribution
**PRD:** [`epic-11-factor-return-attribution.md`](../prd/epic-11-factor-return-attribution.md)
**Status:** Done
**Last updated:** 2026-05-27

## Story

As a **portfolio researcher**, I want the quant engine to expose a factor return attribution endpoint, so that I can learn which systematic factors (market, growth, rates, etc.) generated my portfolio's realized returns over any rolling window.

## Context

The Rolling Factor Model card (Exposure tab) already shows per-factor β loadings computed by `_build_rolling_factor_loadings` in `services/quant-engine/app/analytics/risk.py`. That function calls `_orthogonalize_factors_window(raw_window)` for each date window and fits OLS to obtain `β̂_k(w, t)`. The orthogonalized factor returns `f*_k(t)` — the values needed for attribution — are already in scope inside that rolling loop as `orthogonalized_window[k][-1]`. This story adds a new `build_factor_attribution()` function (Option a from the PRD — mirror, don't refactor), a Pydantic schema, and a new POST route `/api/engines/attribution/run`.

Implementer must read:
- `docs/finance/financial-methodology.md` §Factor Return Attribution — all formulas, edge cases, contract rules
- `services/quant-engine/app/analytics/risk.py` — `_build_rolling_factor_loadings`, `_orthogonalize_factors_window`
- `services/quant-engine/app/api/routes/diagnostics.py` — request/response pattern to follow

## Notes / decisions

- **Option (a) from PRD**: `build_factor_attribution()` is a new function that mirrors the rolling loop from `_build_rolling_factor_loadings`. It does not modify the existing function, preserving all existing test coverage for the risk analytics path.
- **Orthogonalized factor return capture**: within the rolling window loop, after calling `_orthogonalize_factors_window(raw_window)`, the last element of each factor's orthogonalized series is `orthogonalized_window[k][-1]`. This is `f*_k(t)` — no additional computation needed.
- **Residual naming**: field is `unexplained_pct` in the schema. Never `alpha_pct`, never `residual_alpha`. Rationale: residual contains both true alpha and model specification error; labelling it "alpha" would mislead the researcher.
- **Reconciliation failure = HTTP 422**: if floating-point drift breaks the identity by more than 1e-10, the engine raises `ValueError`. The route catches this and returns 422 with an error body. The researcher should never see silently inconsistent attribution.
- **Request shape**: mirrors diagnostics — `FactorAttributionRequest` accepts `daily_states: list[DailyPortfolioState]` and `factor_history: list[FactorHistoryRow]`. Window is a body field defaulting to 60.
- **Academic precedent**: Brinson et al. 1986 (arithmetic decomposition); Fama & French 1993 (factor-based return decomposition); Bacon 2008 Ch. 8–9 (arithmetic linking and reconciliation). All cited in `financial-methodology.md` §Factor Return Attribution.
