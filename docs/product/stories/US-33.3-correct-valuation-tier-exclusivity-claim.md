# US-33.3: Correct the valuation-tier exclusivity claim

**Epic:** Epic 33 — Corporate Actions & Replay Quantity Integrity
**PRD:** [`epic-33-corporate-actions-replay-integrity.md`](../prd/epic-33-corporate-actions-replay-integrity.md)
**Status:** Done (2026-08-13) — commits with US-33.4, which clears the suite
**Last updated:** 2026-08-13

## Story

As a **portfolio researcher**, I want the valuation-tier contract to state
exactly what the engine guarantees, so that a symbol legitimately appearing in
two disclosure lists reads as documented behaviour rather than as a bug in the
replay.

## Context

PRD finding **F-3**. US-24.10's AC5, `docs/contracts/dashboard-fields.md`,
`financial-methodology.md`, `current-product-state.md` and two source comments
all claim a symbol appears in **exactly one** of `statement_anchored_symbols` /
`trade_price_anchored_symbols` / `unpriced_replay_symbols`. That is false as
written.

The precedence ladder (`price_for` in `app/engine/portfolio_state.py`) is
evaluated **per day**, and the disclosure sets are **unions over the window**.
A holding that is held before its first observed trade is `unpriced` on those
days and `trade_price_anchored` afterwards — so it lands in two sets, correctly.
The engine has always behaved this way; only the claim is wrong. US-24.10's
test exercised a single-day case per symbol, so the stronger claim went
unchallenged.

The 2026-08-11 statement produced a live instance: LQQ was in both
`unpriced_replay_symbols` and `trade_price_anchored_symbols`. US-33.2 removed
that particular instance by withholding LQQ, which makes this story **more**
necessary, not less: the false claim now has no counter-example in the
committed fixture, so only a purpose-built test keeps it honest.

Implementer must read:
- `app/engine/portfolio_state.py` — `price_for`, and note it is called once per
  (symbol, day).
- `docs/contracts/dashboard-fields.md` → `trade_price_anchored_symbols`.
- `docs/finance/financial-methodology.md` §Synthetic History Coverage Rule.

## Acceptance criteria

- [x] AC1 — The contract states the guarantee the engine actually makes: the
  tiers are exclusive **per (symbol, day)** — exactly one tier values a symbol
  on any given day — while the disclosure lists are unions over the window and
  may therefore name the same symbol in more than one list. Corrected in
  `dashboard-fields.md`, `financial-methodology.md`,
  `current-product-state.md`, the `DashboardHistoryRunMetadata` schema comment,
  and the `PortfolioStateEngine` comment.

- [x] AC2 — US-24.10's AC5 is corrected in place with a note recording that the
  original wording was an overstatement found by Epic 33 F-3 — the story file
  is a record of what shipped, so it is amended, never silently rewritten.

- [x] AC3 — A test demonstrates the two-list case directly: a symbol held from
  the window open whose first trade occurs mid-window appears in **both**
  `unpriced_replay_symbols` (before the trade) and
  `trade_price_anchored_symbols` (from it onward), and its per-day valuation is
  nonetheless single-tiered — `market_price` is `null` before the trade and the
  carried trade price after.

- [x] AC4 — The per-day guarantee is asserted, not just described: on every day
  of that fixture the symbol draws its price from exactly one tier, so a future
  change that let two tiers value one symbol-day fails the suite.

- [x] AC5 — US-24.10's existing exclusivity test keeps its coverage: the
  single-day case it pinned (three symbols, three tiers, no overlap on that
  day) still passes, restated as a per-day claim rather than deleted.

- [x] AC6 — No behaviour change. The engine is untouched by this story; the
  replay produces byte-identical states and identical disclosure lists.

## Test plan

- `app/tests/test_portfolio_state.py`, `TestUnpricedSymbolDisclosure` /
  `TestDisclosureTiers` — **2 tests**:
  1. `test_symbol_can_appear_in_two_disclosure_lists_across_days` — the F-3

     equals the trade price on the later days (AC3);

  `test_disclosure_tiers_do_not_overlap_within_a_single_day` with its docstring

## Out of scope

- **Making the claim true** by collapsing the disclosure lists to one tier per
  symbol. The current behaviour is right — a symbol genuinely is unpriced
  before its first trade and anchored after — and flattening it would hide a
  real degradation.
- The **currency**-tier exclusivity claims (US-30.2 / US-30.5a): those name one
  conversion policy per currency for the whole window, a different mechanism,
  and they are not implicated.
- Anything in US-33.2 or US-33.4.

## Notes / decisions

- **No methodology or formula changes** — this is a documentation-accuracy
  story with test backing. No academic citation applies.
- **Why the test comes first (T-33.3.1).** The defect is not the wording, it is
  that a contract claim shipped with no test able to falsify it. Correcting the
  prose without adding the falsifier would leave the same gap.
- The finding is mild in consequence but is the exact class Epic 32 exists to
  attack: agent-facing documentation asserting a guarantee the code does not
  make.
