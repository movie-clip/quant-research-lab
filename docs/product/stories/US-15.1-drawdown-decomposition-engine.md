# US-15.1: Drawdown decomposition engine + schema

**Epic:** 15 — Position-Level Analytics
**PRD:** [`epic-15-position-level-analytics.md`](../prd/epic-15-position-level-analytics.md)
**Status:** Done
**Last updated:** 2026-06-01

## Story

As a **portfolio researcher**, I want every drawdown episode the
backend returns to include a per-position contribution breakdown
(top-N contributors, aggregated "other", residual, and a
decomposition-level trust flag), so that the upcoming Drawdown card
"Contributors" drawer (US-15.2) can answer "which positions drove
this drawdown?" without computing anything on the frontend.

## Context

US-13.2 shipped the Risk-tab drawdown card: episodes are identified
via the greedy forward-walk algorithm in
`services/quant-engine/app/analytics/drawdown.py` and surfaced as a
top-5 table inside `DrawdownAnalyticsCard.tsx`. Today each episode
carries only its portfolio-level fields (peak / trough / recovery
dates, magnitude, duration, underwater days). The "which positions
drove this" question is unanswered.

This story extends the drawdown engine with arithmetic Brinson-style
position decomposition under the synthetic-history convention
(current holdings × historical prices, no rebalancing). The
methodology was just landed via `quant-research` as the new
subsection `### Drawdown episode decomposition` under
`## Wealth Index and Drawdown` in
`docs/finance/financial-methodology.md`, with academic citations
(Brinson, Hood & Beebower 1986; Goldberg & Mahmoud 2017 §3;
Bertsimas, Lauprete & Samarov 2004).

This is a backend-only story. US-15.2 ships the frontend drawer
that consumes the new schema fields. The schema additions are all
nullable-default so existing fixtures and tests stay green.

Implementer must read:

- `docs/finance/financial-methodology.md`
  `### Drawdown episode decomposition` — the full formula,
  reconciliation invariant, edge cases, and citations
- `services/quant-engine/app/analytics/drawdown.py` — the
  pure-functions module to extend (currently exports

- `services/quant-engine/app/schemas/drawdown.py` —

- `services/quant-engine/app/services/diagnostics_engine.py:722`
  `_build_synthetic_snapshot_history_states` — produces
  `DailyPortfolioState` with per-date per-position
  `market_price` + `market_value`, which is the data substrate the
  decomposition consumes
- `services/quant-engine/app/schemas/reconciliation.py` —
  `DailyPortfolioState` + `DailyStatePosition` definitions (for the
  decomposition's input shape)

## Acceptance criteria

- [x] AC1 — `services/quant-engine/app/schemas/drawdown.py`
  exports a new `EpisodeContributor` model with fields:
  `symbol: str`, `weight_at_peak_pct: float | None`,
  `return_pct: float | None`, `contribution_pct: float | None`,
  `trust: Literal['synthetic', 'unavailable']`.
- [x] AC2 — The existing `DrawdownEpisode` model gains four new
  nullable-default fields: `top_contributors: list[EpisodeContributor]
  | None = None`, `other_contribution_pct: float | None = None`,
  `decomposition_residual_pct: float | None = None`,
  `decomposition_trust: Literal['synthetic', 'partial',
  'unavailable'] = 'unavailable'`. Existing fixtures and tests do
  not need to populate these — the defaults preserve backward
  compatibility.
- [x] AC3 — `apps/desktop/src/features/portfolio/types.ts` adds
  matching TS types `EpisodeContributor`,
  `DrawdownDecompositionTrust` (`'synthetic' | 'partial' |
  'unavailable'`), and extends `DrawdownEpisode` with the four new
  nullable fields. `cd apps/desktop && npx tsc --noEmit` clean.
- [x] AC4 — `services/quant-engine/app/analytics/drawdown.py`
  exports a new pure function `decompose_drawdown_episode(daily_states,
  episode, top_n=5) -> tuple[list[EpisodeContributor], float | None,
  float | None, Literal['synthetic', 'partial', 'unavailable']]`.
  Returns `(top_contributors, other_contribution_pct,
  residual_pct, decomposition_trust)`. Pure — no I/O, no
  `MarketDataService` import.
- [x] AC5 — Formula implementation matches methodology §Drawdown
  episode decomposition exactly: for each position present at
  `episode.peak_date`'s state,
  `contribution_pct = (V_i(t_peak) / V_p(t_peak)) * (p_i(t_trough) /
  p_i(t_peak) - 1) * 100`. Cash is not iterated (only
  `state.positions`, not `state.cash`), so cash naturally
  contributes 0 (correct per methodology).
- [x] AC6 — Decomposition trust derivation:
  - `'unavailable'`: peak state missing from `daily_states`, OR
    trough state missing, OR `V_p(t_peak) == 0`, OR no position
    yields a non-null contribution.
  - `'partial'`: at least one position has non-null contribution
    AND at least one has null (data gap at peak or trough).
  - `'synthetic'`: every position present at peak has non-null
    contribution AND `abs(residual_pct) < 0.001` (residual is
    floating-point noise only).
- [x] AC7 — Top-N selection sorts decomposable contributors by
  `abs(contribution_pct)` descending; takes first N (default
  N=5); aggregates the rest into `other_contribution_pct =
  Σ contribution_pct over positions ranked N+1 and beyond`.
  Positions with null contribution are NOT included in
  `other_contribution_pct` (they're absorbed by the residual).
- [x] AC8 — Residual computation: `residual_pct =
  episode.magnitude_pct - (Σ over non-null contributions
  including top + other)`. By construction this should be near
  zero under `'synthetic'` trust; under `'partial'` trust it is
  the explained-share gap.
- [x] AC9 — Reconciliation invariant: when
  `decomposition_trust != 'unavailable'`, the equation
  `|episode.magnitude_pct - (sum_of_top_contributions +
  (other_contribution_pct or 0) + residual_pct)| < 1e-9` MUST
  hold. The engine raises `ValueError` if violated. The check is
  defensive — by construction `residual_pct` is defined as the
  remainder, so violation indicates a floating-point edge case or
  implementation bug.
- [x] AC10 — `services/quant-engine/app/services/drawdown_engine.py`
  `run_drawdown_engine` calls `decompose_drawdown_episode` for each
  episode in the response's top-N list, populating the four new
  schema fields. Skipped when there are no positions, no
  `daily_states`, or no episodes — the response's episodes simply
  carry default values (`decomposition_trust='unavailable'`,
  others `None`).
- [x] AC11 — Existing drawdown-engine tests stay green: 4 engine
  pytest in `test_drawdown_engine.py` + 8 analytics pytest in
  `test_drawdown_analytics.py`. The schema additions' nullable
  defaults preserve all existing fixture shapes.
- [x] AC12 — All previously Done tests stay green: 321 backend +
  191 frontend. Net delta: +9 backend (7 analytics + 2 engine), 0
  frontend (TS type extension is type-only, no new vitest in this
  story). `python scripts/run_all_tests.py` green;
  `cd apps/desktop && npx tsc --noEmit` clean.

## Notes / decisions

- **Methodology already complete.** The
  `### Drawdown episode decomposition` subsection in
  `docs/finance/financial-methodology.md` was landed via
  `quant-research` before this story began. It covers the
  formula, reconciliation invariant, edge cases, and the
  three required academic citations (Brinson Hood Beebower
  1986; Goldberg & Mahmoud 2017 §3; Bertsimas Lauprete &
  Samarov 2004). No methodology ticket needed in this story.
- **Cash handling.** Per methodology §Drawdown episode
  decomposition contract rule, cash contributes 0 by
  construction (`r_cash = 0`). The implementation achieves
  this naturally by iterating `state.positions` only (cash
  lives in `state.cash` dict, not in the positions list). The
  cash weight is implicitly in `V_p(t_peak)` denominator
  (because `total_market_value` includes cash via
  `total_portfolio_value`'s composition) — actually note:
  `total_market_value` is positions-only;
  `total_portfolio_value = total_market_value + total_cash`.
  Use `total_market_value` as `V_p(t_peak)` (denominator
  matches "positions only" decomposition). Document this
  inline so a future reader doesn't second-guess the choice.
- **Reconciliation under `'partial'` trust.** When some
  positions have null contributions, `Σ contribution_i_non_null`
  doesn't reach `magnitude_pct`; `residual_pct = magnitude_pct
  - Σ_non_null` captures the explained-share gap. This is
  honest reporting (the UI in US-15.2 will surface the
  residual as a "Partial: N% unexplained" caption). The
  reconciliation invariant
  `magnitude_pct == sum_top + other + residual` still holds
  by construction in this case — `residual` absorbs the gap.
- **Default `top_n = 5`.** Matches methodology §Drawdown
  episode decomposition. Not configurable via the request in
  v1 (avoid scope creep). Could become a query parameter in
  a future story if needed.
- **Backward compatibility.** All four new fields on
  `DrawdownEpisode` have nullable defaults (`None` for the
  values, `'unavailable'` for the trust enum). Existing
  tests that construct `DrawdownEpisode` instances without
  these fields continue to work. The TS extension is
  similarly nullable, so the existing `DrawdownAnalyticsCard`
  consumer code paths don't break.
- **Why no contract doc edit here.** The contract doc
  (`docs/contracts/risk-fields.md`) update is part of
  US-15.4's close-out. Reasoning: schema can change story-
  by-story, but the contract doc captures the *stable*
  external contract — verifying it once at end-of-epic
  catches drift across stories cleanly.
- **No new academic citation needed.** The three citations
  from §Drawdown episode decomposition are already in the
  methodology doc and are the authoritative basis for this
  implementation. Brinson Hood Beebower (1986) is the
  foundational arithmetic attribution paper; Goldberg &
  Mahmoud (2017) §3 extends it to drawdown context;
  Bertsimas et al (2004) is cited for context on coherent
  contribution measures (we use the simpler arithmetic
  decomposition).
