# US-18.1: yfinance fallback provider + data provenance

**Epic:** Epic 18 — Secondary Market-Data Provider
**PRD:** [`epic-18-secondary-market-data-provider.md`](../prd/epic-18-secondary-market-data-provider.md)
**Status:** Done
**Last updated:** 2026-06-05

## Story

As a **portfolio researcher** holding European UCITS ETFs, I want the engine to
fall back to Yahoo Finance for price history that my primary provider (FMP)
can't serve, so that those holdings appear in my analytics instead of being
silently dropped — and I want to see clearly which holdings were sourced from
the secondary provider.

## Context

`MarketDataService.get_historical_prices` resolves each symbol to ordered
candidates (already including exchange-suffixed forms like `VUAA.L`, `SXRV.DE`)
and tries each through `FmpClient.get_historical_price_light`. FMP's plan
returns HTTP 402 for those European symbols, so UCITS holdings get no history
and are excluded from every history-based analytic (the Intra-Portfolio
Correlation card shows "10 holdings excluded: insufficient history"). A
verified POC shows Yahoo Finance (`yfinance`) returns full **adjusted-close**
history for those same suffixed symbols, for free.

This story adds **yfinance as a fallback provider** behind the existing
`MarketDataService` seam (FMP first, yfinance only when FMP is empty), and
introduces an explicit, **visible data-provenance** dimension so the researcher
always knows a holding came from the secondary source. v1 surfaces provenance
on the Intra-Portfolio Correlation card (where the gap is visible); other
surfaces get the badge in US-18.2.

## Acceptance criteria

- [x] AC1 — When FMP returns no history for a symbol but Yahoo Finance has it,
  the engine returns the Yahoo history and the holding is **included** in the
  Intra-Portfolio Correlation matrix (it is no longer listed under "excluded:
  insufficient history"). Verified offline against mocked providers.
- [x] AC2 — The yfinance rows are returned in the same shape as FMP rows
  (`date`, `price`, and an `adjClose`/adjusted key), so `detect_history_return_basis`
  classifies them `verified_adjusted_close` (Yahoo Adj Close is total-return).
- [x] AC3 — When **FMP has data** for a symbol, yfinance is **not called** and
  the returned rows + `last_fetch_meta` are identical to today's behaviour
  (FMP-first path unchanged, byte-for-byte).
- [x] AC4 — When **both** providers return nothing, the result is still empty /
  `unavailable` (fail-closed) — never a fabricated series.
- [x] AC5 — Provenance is recorded per resolved symbol (`vendor='fmp'` vs
  `vendor='yfinance'`) and exposed to callers. The `IntraCorrelationResult`
  carries a `yahoo_sourced_symbols: list[str]` of the holdings whose history came
  from Yahoo.
- [x] AC6 — The Intra-Portfolio Correlation card renders a **visible secondary-source
  marker** when `yahoo_sourced_symbols` is non-empty, e.g. "N holdings via Yahoo
  Finance (secondary source): SYM, SYM…". It uses a text/badge marker (color is
  not the sole encoder) and never implies the data is from the primary provider.
  The existing `Synthetic` trust badge and matrix behaviour are unchanged.
- [x] AC7 — `yfinance` network access is **never** hit in the test suite; both
  providers are mocked. `yfinance` is declared in `services/quant-engine/requirements.txt`.
- [x] AC8 — yfinance results are cached via the existing `JsonFileCache` (a
  distinct history namespace) including negative caching of empty results, so a
  miss isn't refetched every run.
- [x] AC9 — `npx tsc --noEmit` is clean; the design-system audit stays green

## Notes / decisions

- **Provenance is a separate dimension from return-basis trust.** Yahoo data has
  Adj Close, so its return-basis is `verified_adjusted_close` — the same class as
  FMP. Provenance (`fmp` vs `yfinance`) is recorded and surfaced *in addition*,
  because the project's traceability guardrail requires the researcher to know
  the source. The user explicitly chose a **distinct, visible provenance badge**
  over silently treating Yahoo as FMP.
- **Fallback only — FMP path frozen.** yfinance is attempted strictly after FMP
  returns empty for all candidates. When FMP has data, there is no yfinance call
  and outputs are unchanged (AC3 pins this).
- **Row-shape contract.** yfinance rows must carry an `adjClose` key (mapped from
  Yahoo "Adj Close") so `detect_history_return_basis` classifies them correctly;
  `price` is set to the adjusted close for consistency with how the engines
  consume FMP `price`.
- **Offline tests.** `yfinance` hits the network; every test monkeypatches
  `yfinance.Ticker` (client tests) or mocks `YFinanceClient` / `MarketDataService`
  (service + engine tests). No autouse network. This mirrors the FMP mocking
  already in `conftest.py`.
- **No academic citation needed** — this story adds no formula; it is provider
  plumbing. The methodology doc is touched only to record the provenance trust
  dimension, not a new computation.
- **Coverage caveat (for the PRD/epic):** 7 of the 10 currently-excluded UCITS
  tickers resolve immediately via the existing suffix candidates; DFND/DEFS/IDFN
  need US-18.3.
