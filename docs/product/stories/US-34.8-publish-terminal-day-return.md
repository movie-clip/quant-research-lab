# US-34.8: Publish the terminal day's return, corrected rather than withheld

**Epic:** Epic 34 — An Answerable Dashboard: Reachable Trust States
**PRD:** [`epic-34-answerable-dashboard-and-reachable-trust.md`](../prd/epic-34-answerable-dashboard-and-reachable-trust.md)
**Status:** Done (2026-08-13)
**Last updated:** 2026-08-13

## Story

As a **portfolio researcher**, I want the most recent day of my history to carry
a return like every other day, so that the day I look at first is not
permanently blank for a reason the product has since solved.

## Context

PRD finding **F-8**, found by US-34.6.

US-31.3 (Epic 31 F-3) established the requirement: **an accounting adjustment
must never be published as a return.** It satisfied that by withholding the
reconciled terminal day entirely, because the day's `total_portfolio_value` had
been overwritten with the statement's ending NAV and *no un-overwritten value
existed*.

US-34.6 created exactly that value. `market_derived_terminal_value(states)`
returns the terminal value less its recorded `reconciliation_adjustment` — the
replay's own market outcome, before the snap.

**This story is not a relaxation of F-3.** Computing the day's return from the
market-derived value satisfies F-3's requirement *more exactly* than withholding
did: the adjustment never enters a return, and a real day of market movement
stops being discarded. Withholding was the best available answer in US-31.3, not
the requirement itself.

Measured on the committed statement:

```text
previous day (2026-08-08)        65,485.62
terminal, reconciled             65,429.98      <- the level, broker truth, unchanged
reconciliation adjustment           −58.11      <- 0.0888% of terminal value
terminal, market-derived         65,488.09      <- the replay's own outcome
terminal day return                 +0.0038%    <- an ordinary market move
```

The effect on IB2026 is small (All-window TWR 0.5384% → 0.5422%). It is not
small on FF2026, which is where F-8 was found: with **zero external flows** the
time- and money-weighted returns should agree, and the whole remaining gap is
this one withheld day.

**The asymmetry that settles it.** The reconciliation adjustment is the *only*
cross-check the replay has against broker truth — every other day in the window
is valued by the same machinery with nothing to check it against. Withholding
the single day we *can* check, while publishing the 140 we cannot, is backwards.
The adjustment's size is evidence about the replay's accuracy across the whole
window, and it is already disclosed as such; it is not a reason to blank one day.

- `docs/finance/financial-methodology.md` §Terminal-value input rule (US-34.6)

- `app/schemas/reconciliation.py` → `DailyPortfolioState.return_is_publishable`;

## Acceptance criteria

- [x] AC1 — **The terminal day publishes a return, computed on the
  market-derived value.** On IB2026 the 2026-08-11 daily return is
  **+0.0038%**, chained from the previous day's value exactly as every other day
  is. `withheld_return_dates` no longer contains it.

- [x] AC2 — **The adjustment never enters a return.** The published terminal
  return is computed from `total_portfolio_value − reconciliation_adjustment`,
  so F-3's requirement holds by construction. A test asserts that a state whose
  adjustment is large produces a return that does **not** move with the
  adjustment — the guarantee is preserved, not traded away.

- [x] AC3 — **The level is untouched.** `end_value`, the terminal state's
  `total_portfolio_value` and the portfolio-value chart still carry the
  statement's ending NAV. This story changes a *return*, not a level — the same
  split US-34.6 drew.

- [x] AC4 — **The unbacked-cash withholding is untouched.** US-33.2/US-34.4's
  four material days stay withheld: no corrected value exists for them, because
  the missing thing there is a *position*, not an adjustment.
  `withheld_return_dates` goes from **5 entries to 4**.

- [x] AC5 — **FF2026's two independent statistics converge.** With zero external
  flows the time-weighted and money-weighted returns now agree to within
  rounding, where they previously differed by the terminal day's market move.
  The test asserts the convergence rather than a pinned pair, so it states the
  property rather than the arithmetic.

- [x] AC6 — **The withheld-impact figure is re-measured** over the days that
  remain withheld, so it never describes a day that is now published.

- [x] AC7 — **A state with no reconciliation is unaffected.** The request path
  and any snapshot that reconciles within tolerance produce byte-identical
  returns — this story changes only the day that was being withheld for a
  reconciliation reason.

- [x] AC8 — **The disclosure stops claiming what is no longer true.** The
  withheld-return reason no longer names the terminal reconciliation as a cause
  when no day is withheld for it, so `ReplayDisclosuresCard` cannot describe a
  withholding that is not happening.

## Out of scope

- **The unbacked-cash withholding** (US-33.2 / US-34.4). Its cause is a missing
  *position*, not an overwritten value, and no corrected figure exists for it.
- **Changing the terminal reconciliation itself.** Snapping the terminal state
  to the statement's ending NAV stays exactly as it is (US-31.3, unchanged).
- **The reconciliation's size as a data-quality signal.** It is already
  disclosed; whether a large adjustment should degrade the *whole window* is a
  separate question this story does not open.
- Anything on the benchmark path — US-34.5 is blocked on F-10.

## Found while implementing

**`risk.py` holds a second, independent copy of the daily-return formula.**
`return_is_publishable` is shared between the two consumers — the docstring says
so, and says it exists precisely so they "cannot drift apart" — but the
*arithmetic* is duplicated. The correction therefore reached
`performance.py::_time_weighted_daily_return` and not
`risk.py::_portfolio_time_weighted_return_series`, and the two chains disagreed
by exactly the adjustment's share of terminal value (0.0888%) until it was
caught: the terminal day read **−0.085%** on one chain and **+0.0038%** on the
other.

The fix applies the correction in both, with a comment in each naming the
duplication. The shared-predicate claim in the docstring is narrower than it
reads: what is shared is *whether* a day publishes, not *what* it publishes.
Worth collapsing to one implementation, but that is a refactor with its own
blast radius, not something to fold into a guardrail story.

## Notes / decisions

- **No new formula.** `_time_weighted_daily_return` is unchanged in form; only
  which terminal value feeds it, matching the rule US-34.6 already documented
  for Modified Dietz and the investment gain. The methodology entry extends that
  section rather than adding one.
- **Why this is not a weakened guardrail.** F-3 requires that an accounting
  adjustment is never published as a return. Withholding achieved that by
  publishing nothing; correcting achieves it by publishing the market move with
  the adjustment removed. The second is strictly more informative and equally
  compliant, which is why the audit pin is restated rather than deleted.
- **Why no materiality threshold on the adjustment.** A large adjustment means
  the replay's valuation disagrees with broker truth — a concern about the
  *whole window*, since every other day is valued by the same machinery with no
  cross-check at all. Gating one day on it would be arbitrary; the adjustment is
  already disclosed as the window-level signal it is.
- **Expected magnitude.** IB2026 moves the All-window TWR by +0.004pp — small,
  because US-34.3 shrank the adjustment to −$58.11. FF2026 is the case that
  matters, and AC5 asserts the convergence rather than a pinned figure so the
  property survives a future statement.
