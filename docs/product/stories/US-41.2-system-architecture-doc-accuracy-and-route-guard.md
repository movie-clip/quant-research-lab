## Story

As an **agent or developer** directed by `CLAUDE.md` and `project.md`
§ "Sources of truth" to trust `docs/architecture/system-architecture.md` for
"what the backend seams are", I want its route / seam / data-flow inventory to
describe the routers that are actually registered in
`services/quant-engine/app/api/`, so that I plan backend work against the
shipped architecture and not one removed ~30 epics ago — and I want a mechanical
test to fail if that inventory drifts again.

## Context

`docs/architecture/system-architecture.md` still describes the pre-Epic-8
ranking / construction / optimizer / replay product. Its "Current Implemented
Backend Seams" and "Important implementation reality" sections list
`POST /backtests/portfolio-allocation*`, `/construction/run`,
`/construction/artifacts/{id}`, `/strategy-lab/etf-ranking*`,
`/strategy-lab/ranking/*`, `/optimizer/preview`, `/ranking/etf-replacements` and
eight service files (`portfolio_backtest_engine.py`,

The "Data Flow" section and the "Truth Classes" bulleted list carry the same
removed surfaces.

`CLAUDE.md` (doc map) and `project.md` § "Sources of truth" both name this file
the answer to "what are the backend seams?", and — unlike
`current-product-state.md`'s route-module list, which `test_route_inventory.py`

3-module undercount, one notch larger and in the doc `CLAUDE.md` points at first
for seams. Precedent for the story shape (doc-accuracy rewrite + a mechanical

## Notes / decisions

- **Why this is a story and not more docs-lane reconciliation.** Per
  `03-delivery-brief.md` § "Stories": it is authorship (~250 lines describing a
  different product), not label-correction; characterising the *current* seams
  is architecture-pack territory for the tech lead, not reconciliation from a
  contract note; and it ships a test with a test plan. That is a story shape,
  the direct analogue of US-36.3.
- **Why ticket 1 is a scoping pass, not the rewrite.** The producer's
  Estimable steer: the "Data Flow" section (lines ~267–345) was not read
  line-by-line by recon, so the rewrite's exact bounds are unconfirmed. Surface
  that inside the story rather than discovering it mid-rewrite.
- **The guard follows US-36.3's pattern deliberately.** `test_route_inventory.py`
  already reads a doc's stated route inventory and resolves it against
  `app/api/routes/`, failing with the offending module named. This story gives
  `system-architecture.md` the same treatment. Note the two docs list routes
  differently today — `current-product-state.md` lists module filenames,
  `system-architecture.md` lists route paths — so "the same guard" is an
  analogy; the representation the rewritten doc uses is T-41.2.1's call.
