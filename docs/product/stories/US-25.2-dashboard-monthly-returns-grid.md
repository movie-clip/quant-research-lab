# US-25.2: Monthly returns grid card

**Epic:** Epic 25 — Dashboard Performance & Risk Summary
**PRD:** [`epic-25-dashboard-performance-risk-summary.md`](../prd/epic-25-dashboard-performance-risk-summary.md)
**Status:** Next phase
**Last updated:** 2026-07-04

## Story

As a **portfolio researcher**, I want **a month-by-month return grid on the
Dashboard tab**, so that **I can spot seasonal patterns or specific bad/good
months without reconstructing them from the daily chart**.

## Context

`range_metrics[<range>].monthly_returns` (list of `{month, return_pct}`) and
`monthly_returns_reliable` (bool) are already computed and already flow into
`DashboardAnalysis` — no rendering component exists today. This story is
frontend-only.

Read before implementing:
- `docs/contracts/dashboard-fields.md` "Monthly Returns section" table — the
  exact hide/show rule this story must implement
  (`monthly_returns_reliable = false` → hide the whole grid, not individual
  cells)
- US-25.1 (build first — establishes the range-selector pattern this card
  reuses so the two cards stay in sync on the same selected range)

## Acceptance criteria

- [ ] AC1 — For the currently selected range (same selector as US-25.1), the
      card renders one cell per `monthly_returns[].month` with its
      `return_pct`, formatted to 2 decimal places with a `%` suffix.
- [ ] AC2 — Positive months and negative months are visually distinguished
      (color + a sign, not color alone — color-blind-safe per the `ui-polish`
      accessibility baseline already enforced by `designSystem.audit.test.ts`).
- [ ] AC3 — When `monthly_returns_reliable = false`, the entire card is
      replaced with an explicit unavailable/EmptyState message — never a grid
      of individually-suppressed or zeroed cells.
- [ ] AC4 — When `range_metrics` for the selected range is absent entirely,
      the card shows the same EmptyState as AC3 (both are "cannot show
      monthly data" states from the researcher's point of view, even though
      they are different backend conditions).
- [ ] AC5 — Switching the shared range selector (from US-25.1) updates this
      grid without a new network fetch.

## Test plan

Frontend (vitest):
- `DashboardPanel.test.tsx` — **4 new tests**: renders one cell per month with
  correct sign/formatting; hides the grid and shows EmptyState when
  `monthly_returns_reliable = false`; shows EmptyState when `range_metrics`
  absent; grid updates when the shared range selector changes (no new fetch).

Regression / guardrail:
- `designSystem.audit.test.ts` must stay green (new component must use the
  shared tokens/primitives, not ad-hoc colors).
- Existing "removed sections stay absent" regression in `DashboardPanel.test.tsx`
  unaffected.

- No drill-down from a month cell into daily detail — flat grid only.
