# US-24.2: Extract the risk-model scoring rubric & thresholds into named constants

**Epic:** Epic 24 — Codebase Improvement
**PRD:** [`epic-24-codebase-improvement.md`](../prd/epic-24-codebase-improvement.md)
**Status:** Done
**Last updated:** 2026-06-19

## Story

As a **developer of this project**, I want the risk-model's tunable policy
numbers (factor-mapping scoring weights, hard-cap ceilings, label thresholds,
quality→score maps, volatility-regime cutoffs, the ETF-coverage threshold) lifted
out of inline literals into a **named, documented constants block**, so that the
rubric that drives factor-mapping quality and regime classification is auditable
and tunable in one place — **without changing any computed value**.

## Context

`app/analytics/risk.py` encodes a large factor-mapping scoring rubric and several
classification thresholds as scattered inline literals (catalogued in
[`docs/tech-debt-register.md`](../../tech-debt-register.md) → Epic 24 backlog row
US-24.2). They are *policy* numbers — the kind a reviewer should be able to find
and tune — but today they are buried mid-expression across ~400 lines, so the
rubric is neither auditable nor citable.

This story is a **behaviour-neutral extraction**: every literal moves to a named
module constant (or a small named mapping) with a one-line rationale; **no value
changes**, so every computed score, regime label, stress projection, and the
dashboard goldens stay byte-identical. This is the Epic 24 discipline — a
deliberate, reviewed refactor, the opposite of a value change.

Implementer must read:
- `app/analytics/risk.py` — the rubric (`_compute_mapping_match_summary` +
  `_compute_*` weight expressions, `_apply_mapping_hard_caps`,
  `_mapping_match_label`, `_mapping_quality_score`, `_cost_fit_score`,
  `_classify_volatility_regime`, `build_statistical_factor_model` min-history,
  `STRESS_SCENARIOS`).
- `app/services/exposure_engine.py` — the `99.0` ETF-holdings coverage threshold.
- `docs/finance/financial-methodology.md` — the §Statistical Factor Model and
  any factor-mapping / regime sections, to cite the constants where a
  methodology basis exists.

## Acceptance criteria

- [x] AC1 — The tunable policy numbers are named module constants with a one-line
  rationale each: the mapping-match **composite weights** (`_compute_mapping_match_summary`
  + the equity/bond/commodity/structure/implementation `_compute_*`), the
  **hard-cap ceilings + reason strings** (`_apply_mapping_hard_caps`), the
  **mapping-match label thresholds** (`_mapping_match_label`), the
  **quality→score maps** (`_mapping_quality_score`, `_cost_fit_score`), the
  **volatility-regime percentile cutoffs** (`_classify_volatility_regime`), the
  **factor-model minimum shared-history** count (`build_statistical_factor_model`),
  and the **ETF-coverage threshold** in `exposure_engine.py`. No inline literal
  remains for any of these.
- [x] AC2 — **Behaviour-neutral:** every computed mapping `score_pct` /
  `hard_cap_reason` / `label`, every regime label, and every stress-scenario
  projection is **identical** to before; `apps/desktop/src/test/dashboardGoldens.ts`
  is **untouched** and the full `python scripts/run_all_tests.py` is green.
- [x] AC3 — **Exact-value pins** lock the neutrality: new tests assert the
  current computed values of a representative set (a market-factor `score_pct`, a
  bond hard-capped reason, a `_mapping_match_label` boundary, the three regime
  cutoff labels, and a stress-scenario projection) to exact numbers, so a future
  mis-extraction (e.g. a transposed weight) fails loudly.
- [x] AC4 — Where a constant has a methodology basis (regime cutoffs, the
  min-history floor, the stress shocks), `docs/finance/financial-methodology.md`
  names it; where it is a heuristic rubric weight with no academic source, the
  constant's inline rationale says so (no fabricated citation).
- [x] AC5 — The US-23.8 dead-code gate stays green (`ruff`/`vulture`/`knip` clean,
  `tsc` clean); no new unused symbols introduced by the extraction.

## Test plan

Backend (pytest):
- `test_analytics.py` — **6 tests** (exact-value golden-master pins, added
  before the extraction so they pin the current output):
  1. `build_factor_registry()` — the `market` primary-mapping `score_pct` equals
     its exact current value (not just `>= 80`).
  2. A bond factor (`rates_tlt`/`rates_ief`) primary-mapping `hard_cap_reason`
     and `score_pct` equal their exact current values.
  3. `_mapping_match_label` returns the documented label at each threshold
     boundary (e.g. 90 → "Exact / Best Match", 79.9 → "Strong Match"/"Usable Proxy").
  4. `_classify_volatility_regime` returns `calm` / `normal` / `stressed` at
     percentiles straddling the (now-named) cutoffs.
  5. `build_stress_scenarios(model)` — a scenario's `estimated_return_pct` equals
     its exact current value for a fixed factor-loading snapshot.
  6. `build_statistical_factor_model` — a snapshot with shared history just below
     vs at the (now-named) minimum returns `insufficient_history` vs a built model.
- Reuse existing helpers/fixtures in `test_analytics.py` (`_sample_snapshot`,
  the factor-registry/regime tests already present at ~L4137/L5247).

Regression / guardrail:
- `python scripts/run_all_tests.py` green; **`dashboardGoldens.ts` untouched**
  (proof the extraction changed no output). `npx tsc --noEmit` clean; gate green.
- The existing loose mapping/regime assertions (≈ L4137, L5247–5270) stay green.

## Out of scope

- **The per-branch leaf match-scores** inside `_index_match_score` /
  `_style_sector_similarity_score` / `_duration_match_score` / the other
  `_*_score` helpers (e.g. `0.85`/`0.60`/`0.30` returned per token match) — these
  are the scoring *rubric body*, not tunable policy knobs. Extracting each into a
  named constant would add dozens of single-use names without improving
  auditability; they stay inline with a clarifying docstring. Recorded as a
  lower-value follow-up in the register.
- **Changing any value** — this story only renames/relocates; value changes are
  a separate, methodology-reviewed decision, never bundled into an extraction.
- **The `risk.py` sector-inference ticker maps** (US-24 register) — those are
  fragile-coupling, owned by a later story.

## Notes / decisions

- **Pin-tests-first ordering (T-24.2.1 before T-24.2.2)** is deliberate: the
  exact-value pins must encode the *current* output and pass against the
  un-refactored code, so they are a true golden-master guard for the extraction.
- **No fabricated citations:** the mapping-rubric composite weights (e.g.
  `0.60/0.25/0.15`) are internal heuristics with no academic source — their
  rationale line says "heuristic rubric weight (no academic basis); tune as a
  reviewed policy change". Only the genuinely methodology-backed values (regime
  cutoffs, min-history, stress shocks) get a methodology-doc reference.
- No new formula; this is an auditability refactor, not a methodology change.
