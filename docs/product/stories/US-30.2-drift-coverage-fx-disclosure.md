# US-30.2: Drift coverage + FX disclosure — statement-anchored symbols, implied rates

**Epic:** Epic 30 — Exposure Improvements
**PRD:** [`epic-30-exposure-improvements.md`](../prd/epic-30-exposure-improvements.md)
**Status:** Done
**Last updated:** 2026-07-08

## Story

As a **portfolio researcher**, I want the drift panel to disclose which
holdings could not be valued from market data and which currencies were
converted with what rate, so that I know exactly how much of the vs-Market
number rests on degraded inputs instead of discovering it in a diagnosis
session.

## Context

PRD findings F-3 and F-6. **F-3 wording correction (verified during story
authoring):** a zero-coverage holding (LQQ — no provider price rows) is not
omitted from drift valuations; `PortfolioStateEngine.price_for` anchors it
**flat at the statement close price for the whole window** (documented
US-27.7 broker-path behaviour). Flat-anchoring means zero return
contribution — it dampens the portfolio return and volatility — and today it
is completely undisclosed on the drift surface (~3% of the real portfolio).
F-6: drift valuations convert non-base positions with `fx_history={}`, so
EUR/GBP are carried unconverted (disclosed as `fx_fallback_currencies` since
US-27.8) — while US-28.1's statement-implied rates
(`statement_totals.fx_rates`, broker truth derived from the statement's own
Open Positions totals) sit unused because neither the request schema nor the
workspace snapshot carries them.

Scope discovery: the workspace `PortfolioSnapshot`
(`workspaceTypes.ts:22`, persisted, `snapshotVersion: 1`) has no FX field —
the imported snapshot's `statement_totals.fx_rates` must flow through the
bootstrap mapper into the workspace snapshot (optional field,
backward-compatible with persisted v1 snapshots; mind the persistence
sanitizers — the CLAUDE.md cautionary example) and then through
`buildSnapshotAnalysisRequest` into the drift request.

Trust decision (see Notes): a statement-implied rate is a **static
period-end rate** applied across a historical window — FX dynamics are still
missing, so converted-at-static-rate currencies are disclosed in their own
field (`fx_static_rate_currencies`), distinct from the unconverted-fallback
family. Three disclosure tiers: converted-with-static-rate (best available),
carried-unconverted (fallback), and flat statement-anchored symbols.

## Acceptance criteria

- [x] AC1 — Statement-anchored disclosure: when any held symbol is valued at
  the flat statement close (zero in-window price coverage), `DriftResult`
  carries `statement_anchored_symbols` naming them, and the drift panel
  renders a helper note ("valued flat at statement close — no market
  history") alongside the existing FX note. Empty list → no note.
- [x] AC2 — Statement-implied FX is used when supplied: a drift request
  carrying `fx_rates` (e.g. `{"EURUSD": 1.1422}`) converts non-base position
  values at that rate on every valuation date, and those currencies are
  disclosed in `fx_static_rate_currencies` — NOT in
  `fx_fallback_currencies`. Window returns and the chart use the converted
  values.
- [x] AC3 — Fallback unchanged where no rate exists: a non-base currency
  absent from `fx_rates` still carries unconverted and appears in
  `fx_fallback_currencies` exactly as US-27.8 defined; mixed portfolios
  disclose each currency in exactly one tier.
- [x] AC4 — The implied rates flow end-to-end: the bootstrap mapper copies
  the imported snapshot's `statement_totals.fx_rates` into the workspace
  snapshot (optional `fxRates` field, absent for pre-existing persisted
  snapshots — no migration, no fabrication), and the drift adapter sends
  them; a workspace snapshot without `fxRates` sends none (AC3 behaviour).
- [x] AC5 — Trust semantics: static-rate conversion never upgrades trust —
  windows stay `synthetic`; the panel's FX note distinguishes "converted at
  the statement's implied period-end rate" from "carried unconverted"; no
  currency is silently converted 1:1 anywhere.
- [x] AC6 — No regression: with `fx_rates` absent (every existing caller
  until the frontend ticket lands) the engine output is byte-identical to
  US-30.1 behaviour; `dashboardGoldens.ts` untouched; full suite green.

## Notes / decisions

- **Why a distinct `fx_static_rate_currencies` tier instead of clearing the
  fallback:** converting a whole historical window at one period-end rate is
  a documented simplification (levels correct as of period end; FX return
  dynamics still absent). Folding it into "converted, all good" would
  overstate trust; folding into "fallback" would hide that real broker-truth
  rates were applied. Three tiers keep every degradation visible — guardrail
  #3. No new formula (level scaling only); no citation required.
- Statement-implied rates are broker truth **as of the statement period
  end** (US-28.1 derivation: base-currency restatements of the Open
  Positions totals). The methodology note must say exactly that.
- The persisted-snapshot compatibility path: `fxRates` is optional and only
  ever written by the mapper on fresh imports — old persisted snapshots
  simply lack it and keep US-27.8 fallback behaviour (honest, disclosed).
