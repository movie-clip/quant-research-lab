# US-31.2: Price the full reconstructed symbol set on the ledger-replay path

**Epic:** Epic 31 — Ledger Replay Correctness
**PRD:** [`epic-31-ledger-replay-correctness.md`](../prd/epic-31-ledger-replay-correctness.md)
**Status:** Done
**Last updated:** 2026-07-24

## Story

As a **portfolio researcher**, I want the replayed daily series to value every
position I actually held on each day — including the ones I have since sold —
so that my portfolio's historical value is measured from real prices instead of
being silently understated by $35.5k and papered over with a cash plug.

## Context

PRD finding **F-1 (Critical)**, verified 2026-07-18 and reproduced against the
**frozen** `golden_market_data.json` (deterministic, network-free).
`PortfolioStateEngine.build_daily_states` reconstructs *opening* positions by
rolling ending positions back through BUY/SELL
(`engine/portfolio_state.py:49-64`), producing **38** opening symbols for the
IB2026 snapshot that holds **20** today. But every caller fetches price history
with `[position.symbol for position in snapshot.positions]` — the 20 current
holdings only — so the 18 since-sold symbols have no price rows at all. On day
one (2026-01-08) just **11 of 38** positions are priced; the 27 unpriced ones
contribute **$0** through the `if market_value is not None` guard
(`portfolio_state.py:184-185`), giving opening market value **$14,582.03**
against an implied **$50,116.24**.

This story fixes **only the input-data defect (F-1)**. The downstream
consequences — cash absorbing the residual (F-2) and the terminal
reconciliation publishing that drift as a −36.34% return (F-3) — are US-31.3.
Fixing F-1 first is deliberate: F-2/F-3 cannot be assessed, let alone
regression-pinned, while the valuation inputs are missing a third of the
portfolio.

Two hazards found while scoping this story that are **not** in the PRD table
and that this story must handle, because expanding the fetch set arms them:

1. **`_effective_valuation_dates` defaults an unknown symbol's weight to 1.0**
   (`portfolio_state.py:246`, `weight_by_symbol.get(symbol, 1.0)`). Weights are
   built from *current* snapshot positions, so every since-sold symbol is
   absent from the map and scores the maximum weight. Today that is harmless —
   those symbols have no history, so they never reach `first_covered`. The
   moment we fetch their history they become "material", and any one of them
   whose coverage starts mid-window will **truncate the entire replay window**
   (US-27.7 rule). A latent trap that this story's fix springs.
2. **`fallback_prices` is keyed on current positions only**
   (`portfolio_state.py:67`), so a since-sold symbol that remains unfetchable
   gets `price_for → None` and silently contributes 0 — *and* is not recorded
   in `statement_anchored_symbols`. Residual unpriced opening positions must be
   disclosed, not silently zeroed (guardrail #3).

Implementer must read:

- `docs/finance/financial-methodology.md` §Synthetic History Coverage Rule

- `app/engine/portfolio_state.py:31-135` (reconstruction, `price_for`,

## Acceptance criteria

- [x] AC1 — On the committed IB2026 portfolio replayed against frozen market
  data, **every** opening position is priced on day one: the count of unpriced
  opening symbols on 2026-01-08 is **0** (was 27 of 38), and day-one opening
  market value reconciles to the statement-implied **$50,116.24** within a
  documented tolerance — regression-pinned at an exact value, not a
  not-null assertion.
  *Delivered:* unpriced count is 0; day-one MV pins at **$49,024.04**, a 2.2%
  residual (pre-fix: $14,582.03, 70.9% short). The residual is **LQQ**, a held
  symbol with no fetchable history that keeps its US-27.7 statement-close
  anchor — broker-truth-adjacent and already disclosed via
  `statement_anchored_symbols`, not a US-31.2 defect.
- [x] AC2 — The replay symbol universe is derived **once**, by a single named
  pure function taking the snapshot and returning current holdings ∪ every
  symbol carrying a BUY/SELL ledger entry. Every ledger-replay caller
  (`diagnostics_engine`, `dashboard_history_engine`) fetches that set; no
  caller re-derives `[p.symbol for p in snapshot.positions]` for a replay
  fetch. A unit test pins the IB2026 universe at ~~**38**~~ **63** symbols
  against the snapshot's 20 current positions.
  *Correction found during the build:* 38 is the count of non-zero **opening**
  positions, not the set needing prices. The universe is **63** = 38 opening
  ∪ 16 symbols bought AND sold entirely inside the window ∪ 9 opened during the
  window and still held. The middle group appears in neither the opening nor
  the ending set yet is held on interior days — which is exactly why the fetch
  set is derived from the BUY/SELL scan rather than from opening positions.
- [x] AC3 — Synthetic-path callers are untouched: `stress_engine`,
  `drawdown_engine`, `distribution_engine`, `correlation_engine`,
  `intra_correlation_engine`, and `attribution_engine` still fetch current
  holdings only (they build forward from today's holdings and never
  reconstruct opening positions — Epic 30 / US-30.5c basis rule stands), and
  no synthetic-path golden or trust field changes.
- [x] AC4 — The de-minimis trap is closed: a since-sold symbol can never
  truncate the replay window by scoring the default weight of 1.0. Materiality
  is evaluated on a weight basis that covers reconstructed symbols, or
  since-sold symbols are excluded from the truncation reference set — the
  choice is documented in the methodology coverage rule. Observable: the
  IB2026 replay window still starts **2026-01-08** after the fetch set
  expands, pinned; and a fixture with a since-sold symbol whose coverage
  begins mid-window does **not** shorten the window.
- [x] AC5 — Residual unpriced opening positions are disclosed, never silently
  zeroed: any opening symbol still lacking both fetched history and a
  statement anchor is recorded by the engine and surfaced on the
  dashboard-history run metadata (mirroring the `fx_fallback_currencies`
  disclosure shape), with the matching TS type and contract-doc row. A
  fixture holding one unfetchable since-sold symbol asserts it appears in the
  disclosure rather than contributing $0 in silence.
- [x] AC6 — Trust levels never improve as a side effect: no metric that is
  `null`/gated today becomes populated by this story, and nothing gated by
  `_allow_diagnostics_relative_return_outputs()` /
  `_allow_diagnostics_drawdown_outputs()` is un-gated here. The corrupted
  surfaces named in the PRD impact map stay as they are until US-31.3 — this
  story changes inputs, not policy.
- [x] AC7 — The frozen fixture and goldens are re-captured **deliberately** and
  itemized: `golden_market_data.json` gains the since-sold symbols' series
  (`export_dashboard_goldens --capture`, requires `FMP_API_KEY`), and the
  resulting `dashboardGoldens.ts` diff is reviewed **per field family** in the
  story close-out — portfolio value / market value / return series are expected
  to move; statement-identity, ledger-count, and exposure/weight families must
  be **byte-identical**.
- [x] AC8 — The residual opening-cash drift is measured and recorded, not
  fixed: a test asserts the post-fix opening cash anchor against its exact
  new value with a comment naming it the US-31.3 baseline (pre-fix
  $37,799.09 vs statement-implied $2,264.88). If the drift does not shrink
  substantially, F-1 was not the dominant term and the finding must be
  re-scoped before US-31.3 proceeds.

## Notes / decisions

- **No new formula, so no new citation required.** This story corrects the
  *input set* to an already-documented replay; the only methodology text that
  changes is the §Synthetic History Coverage Rule materiality clause, which
  gains a sentence about reconstructed (since-sold) symbols. If the
  implementer finds they are writing a new formula, the story has drifted into
  US-31.3.
- **Why the universe is current ∪ traded, not just opening:** the engine walks
  `running_positions` forward through the whole window, so a symbol bought and
  sold entirely *inside* the window is held on interior days without appearing
  in either the opening or ending set. Deriving the fetch set from the same
  BUY/SELL scan that builds `opening_positions` is what makes the two provably
  consistent — hence the single shared function in AC2 rather than two
  parallel derivations that can drift apart (the US-30.1 "one shared chain"
  lesson).
- **Cost note:** the fetch set roughly doubles (20 → 38 symbols) on two
  engines. These are cached FMP calls, so steady-state cost is one-time per
  symbol; but the `--capture` step in T-31.2.4 needs a live key, and a
  since-sold symbol that fails registry resolution will surface as a coverage
  gap rather than an error — check the registry **before** capturing, not
  after.
- **Ordering rationale (recorded so it is not re-litigated):** F-1 before
  F-2/F-3 because the cash plug's magnitude *is* the F-1 error. Fixing F-2's
  anchor first would pin a fail-closed bound against a number that this story
  then changes, forcing a second golden regeneration around a value known to
  be wrong.
- **AC8 is a falsification check, not a fix.** If the opening-cash drift does
  not shrink substantially once all 38 symbols are priced, then F-1 is not the
  dominant term in F-2 and the PRD's causal chain is wrong — that must be
  raised before US-31.3 is written, per the Epic 27/30 findings-first
  discipline (the US-30.5b/F-3 precedent, where a finding's wording was
  corrected during implementation).
