# US-21.5: Assertion conventions + suite speed

**Epic:** Epic 21 — Testing Strategy & Architecture Hardening
**PRD:** [`epic-21-testing-strategy-hardening.md`](../prd/epic-21-testing-strategy-hardening.md)
**Status:** Done
**Last updated:** 2026-06-11

## Story

As a **developer of this project**, I want additive-tolerant assertion
conventions codified in the write-tests skill (and the known brittle spots
converted), plus parallel pytest execution, so that adding a field to an
extensible structure or changing an implicit default stops cascading into
unrelated test failures, and the backend suite runs measurably faster.

## Context

Epic 21's review surfaced two assertion anti-patterns that each broke multiple
tests in a single week:
- **Exact-equality on extensible sets/dicts.** Adding `vendor` to
  `last_fetch_meta` broke 5 tests asserting the exact key set; adding an import
  admission check broke 2 (an exact dict and an exact route-set). Structures
  that are *intended* to grow should be asserted with membership/superset, not
  `==`.
- **Implicit-default pinning.** Changing the chart default window (60d → 20d)
  broke 10 frontend tests whose fixtures silently encoded the old default — the
  tests asserted a default they never meant to pin.

The suite is also sequential (~100s backend), with no parallelism.

This story (a) writes the conventions into `.claude/skills/write-tests/SKILL.md`
with the *real* breakage examples, (b) converts the specific brittle spots the
review named, and (c) adds `pytest-xdist` to `run_all_tests.py` and records the
wall-time delta. A first increment — silencing the `[drift] Unhandled fetch`
console noise in `App.test.tsx` by registering drift in the fetch stub — already
landed (commit `1c7154f`); this story completes the rest.

Implementer must read:
- `.claude/skills/write-tests/SKILL.md` — where the conventions go (it already
  has "No live network" and "Shared fixtures module" sections from US-21.1/21.2).
- The brittle spots to convert: tests asserting the exact `last_fetch_meta` key
  set; the import-admission exact-dict/route-set assertions; the frontend specs
  that pin the window default.
- `scripts/run_all_tests.py` — the backend pytest invocation to parallelize.
- `services/quant-engine/requirements*.txt` (or `pyproject`) — where
  `pytest-xdist` is declared.

## Test plan

This is a test-infrastructure + conventions story; the "tests" are the existing
suites staying green under the new assertion shapes and parallel execution.

Backend (pytest):
- Converted spots (`test_market_data*`/`test_*admission*` and the
  `last_fetch_meta` assertions) — same test count, loosened assertion shape for
  additive fields; all green.
- Full suite green under `-n auto` (xdist) with the network guard active and no
  env vars.

Frontend (vitest):
- Converted window-default specs — same count, explicit window in arrange;
  all green.

Regression / guardrail:
- No reduction in asserted behaviour — each converted assertion still proves the
  same fact; only tolerance to *additive* change increases.
- xdist must not introduce shared-state flakiness: confirm by a clean parallel
  run (and re-run) of the full backend suite.
- The drift-noise fix (already landed, `1c7154f`) stays green.

## Out of scope

- A blanket rewrite of all passing exact-equality assertions — only the named
  brittle spots plus the codified convention for *new/changed* tests (per the
  PRD non-goal "no rewriting passing tests for style").
- A coverage-percentage gate (PRD non-goal).
- A new test framework or E2E layer (PRD non-goal).
- Frontend parallelization tuning — vitest already parallelizes; this story's
  speed work is the backend xdist addition.

## Notes / decisions

- **Why membership/superset, not `==`, for extensible structures:** `last_fetch_meta`
  and admission results are explicitly designed to gain fields (provenance
  vendor, new admission reasons). An `==` on their key set asserts "these and
  *only* these fields exist forever", which is a stronger claim than any test
  there intends — every additive field then registers as a regression. Membership/
  superset asserts the fact the test actually cares about.
- **Why explicit defaults:** a fixture that omits the window and asserts a
  rendered value is implicitly asserting the default *and* the rendering. When
  the default moves, the failure points at the wrong thing. Setting the window
  explicitly isolates the assertion to the behaviour under test.
- **xdist determinism:** US-21.1 (network guard) and US-21.4 (frozen goldens)
  make the suite order-independent and network-free, which is the precondition
  for safe parallelization — this story is sequenced last in the epic for that
  reason.
- No financial formula; no academic citation.
