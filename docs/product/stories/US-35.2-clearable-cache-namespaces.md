# US-35.2: Make every cache namespace clearable and inspectable

**Epic:** Epic 35 — Market-Data Failure Honesty
**PRD:** [`epic-35-market-data-cache-resilience.md`](../prd/epic-35-market-data-cache-resilience.md)
**Status:** Done (2026-08-19)
**Last updated:** 2026-08-19

## Story

As a **developer clearing a poisoned market-data cache**, I want every namespace
the cache actually holds to be one I can target and be told about, so that
"clear the history cache" does not silently leave half of it behind.

## Context

PRD finding **F-2**, verified on 2026-08-19.

`manage_cache.py list` reports four namespaces on a warm cache — `history`,
`history_yf`, `holdings`, `fx`. `clear --namespace` accepts only
`{quote, history, fx, fmp}`. Two of the namespaces that exist cannot be named,
and one of the choices (`quote`) is offered whether or not anything is in it.

`JsonFileCache.clear` globs `f"{namespace}-*.json"`. That matching is **already
exact** — `history-*.json` does not match `history_yf-abc.json`, because the
character after `history` is `_`, not `-`:

```
history-*.json     matches -> ['history-abc.json']
history_yf-*.json  matches -> ['history_yf-abc.json']
```

So the clearing mechanism is correct. The defect is narrower and entirely in the
CLI: `--namespace` is a **hand-written `choices` list** that has drifted from the
namespaces the cache actually holds. `history_yf`, `holdings`, `profile`,
`fundamentals`, `screener` and `index_constituents` all exist and none can be
named.

The bare `clear` and `--namespace fmp` glob `*.json` and **do** remove
everything, so an escape hatch exists — this story is not about data being
unreachable. It is about an operator reasoning *"I poisoned the history cache,
let me clear history"*, getting a **partial** clear, and being told
`Removed 172 cache file(s).` with no hint that 51 more were left. That happened
during US-34.9 and cost a second confused debugging round on top of the first.

Implementer must read: `scripts/manage_cache.py`; `app/core/cache.py`
(`clear`, `list_entries`, `build_key`); the Epic 35 PRD.

### Where the namespaces actually come from

They are not declared anywhere — a namespace exists because some caller passed
that string to `build_key`. Verified by grep on 2026-08-19:

| Namespace | Written by |
|---|---|
| `history` | `FmpClient._get` for equity history |
| `fx` | `FmpClient._get` when the symbol ends `USD` |
| `quote` | `FmpClient.get_quote_short`, `get_profile` |
| `profile` | `FmpClient.get_profile` |
| `fundamentals` | income / balance / cash-flow / ratios / key-metrics |
| `screener`, `index_constituents` | screener + S&P 500 constituents |
| `holdings` | `FmpClient.get_etf_holders` |
| `history_yf` | `YFinanceClient` |

So the `--namespace` choice list was a hand-maintained subset of a set nobody
owns, and it had drifted — exactly the shape US-32.1 dealt with for doc paths.
The fix is to stop hand-maintaining it.

## Acceptance criteria

- [x] AC1 — **`--namespace` accepts every namespace the cache can hold**,
  including `history_yf`, and the accepted set is not a hand-written list that
  can drift from reality.

- [x] AC2 — **Suffixed namespaces stay separately targetable**, and a test says
  so. `--namespace history` removes `history-*.json` and leaves
  `history_yf-*.json`; `--namespace history_yf` removes exactly the yfinance
  entries. This behaviour is **already correct** — the AC is a *guard*, not a
  fix, because the obvious "simplification" (matching by prefix) would silently
  merge two providers' caches.

- [x] AC3 — **`clear` reports what it did per namespace**, so a partial clear is
  visible at the moment it happens rather than discovered later. Clearing
  `history` on a cache that also holds `history_yf` says so.

- [x] AC4 — **`list` shows totals**, so an operator can see at a glance which
  namespaces hold entries and how many — the information needed to choose what
  to clear.

- [x] AC5 — **The bare `clear` still removes everything**, unchanged. It is the
  escape hatch this story is not taking away.

- [x] AC6 — **`--namespace` rejects an unknown name** with a message listing
  what is actually present, rather than silently removing nothing and reporting
  `Removed 0 cache file(s).`

- [x] AC7 — **No production behaviour changes.** `JsonFileCache` is used by the
  engines at runtime; only its `clear`/`list` reporting surface changes.
  `dashboardGoldens.ts` byte-identical; full suite + tsc + dead-code gate green.

## Out of scope

- **Changing cache keys, TTLs, or the on-disk envelope format.** Renaming
  `history_yf` to something without a prefix collision would invalidate every
  cached entry for the 14 UCITS listings; the collision is fixable in the
  matcher without touching the data.
- **The negative-caching policy** — that was US-35.1, and 402/403/404 keep the
  behaviour it deliberately preserved.
- **A cache-clearing UI or route.** `/cache` exists as a route; extending it is
  not required to fix the CLI gap this story is about.
- **Making `list` show sizes on disk or ages in human units.** Useful, unrelated.

## Notes / decisions

- **No formula, no methodology, no trust-class change**; no academic citation
  applies.
- **Why derive the choices instead of adding `history_yf` to the list.** Adding
  one string fixes today's instance and leaves the mechanism that produced it.
  Namespaces are created implicitly by whoever calls `build_key`, so any
  hand-maintained list is guaranteed to drift again — the same argument
  US-32.1 made for the module table, and the same fix: stop maintaining it by
  hand.
- **Premise correction (2026-08-19).** The story was first drafted claiming
  `--namespace history` wrongly matched `history_yf` through a prefix collision.
  It does not: the glob includes the `-` separator, so the matching is already
  exact, verified before implementing. The real defect is only the hand-written
  `choices` list. The AC that described the collision became a **guard** against
  introducing one — matching by bare prefix is the obvious "tidy-up" and would
  silently merge two providers' caches.

## Outcome (2026-08-19)

**Two premise corrections, both caught before implementing.**

1. **There was no prefix collision.** The story first claimed `--namespace
   history` wrongly matched `history_yf`. It never did — the glob includes the
   `-` separator, so matching was always exact. The AC that described the
   collision was turned into a **guard** against introducing one: matching by
   bare prefix is the obvious tidy-up and would silently merge two providers'
   caches, throwing away the yfinance rows for the 14 UCITS listings whenever
   someone cleared FMP history.
2. **`test_cache.py` already existed** — the test plan called it new. The six
   planned cases became five additions there plus six in a new
   `test_manage_cache_cli.py`.

**`clear()` kept its `int` return, deliberately.** The first implementation had
it return a per-namespace dict — until `cache_admin.py` showed that
`CacheClearResult.removed` on the `/cache` **route** is typed from it. AC7
forbids a production behaviour change, so the breakdown is derived at the CLI
from `namespaces()` either side of the call instead. The route contract is
untouched.

**What the CLI does now**, on the real cache:

```
Namespaces:
  fx                   2 entries
  history              87 entries
  history_yf           23 entries
  holdings             12 entries
  TOTAL                124
```

and clearing a namespace reports what it left:

```
Removed 2 cache file(s).
Still cached: history_yf (1), holdings (1)
Note: history_yf is a separate namespace and was NOT cleared by
--namespace history. Clear it explicitly, or run without --namespace to
clear everything.
```

**The choices are derived, not listed.** `--namespace` no longer carries an
`argparse` `choices=[…]`; it validates against what is on disk and rejects an
unknown name with the present namespaces, instead of removing nothing and
reporting `Removed 0 cache file(s).` — which was indistinguishable from success
on a typo. A test uses `holdings`, which no version of the old list contained,
so reintroducing a hand-maintained list fails the suite.
