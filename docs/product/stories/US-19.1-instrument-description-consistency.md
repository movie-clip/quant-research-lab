# US-19.1: Instrument description-consistency check

**Epic:** Epic 19 — Instrument Identity Integrity
**PRD:** [`epic-19-instrument-identity-integrity.md`](../prd/epic-19-instrument-identity-integrity.md)
**Status:** Done
**Last updated:** 2026-06-05

## Story

As a **portfolio researcher**, I want the app to flag when a ticker's registry
fund-name disagrees with my broker statement's own description of that holding,
so that a mislabeled instrument (like `DFND` → "VanEck Defense" when it's
actually iShares Global Aerospace & Defence) is surfaced to me instead of
silently shown as the wrong fund.

## Context

The instrument registry maps a ticker → fund name/sector. When that mapping is
wrong it propagates silently (wrong name, wrong sector, and previously wrong
prices). The broker statement carries ground-truth identity evidence — a
per-instrument **description** — but nothing cross-checks it against the
registry. This story adds a conservative description-consistency detector and
surfaces mismatches where the researcher will actually see them.

**Surfacing decision (discovered during grounding):** the Import Admission
Review summary is computed and persisted but **not rendered** in the UI today,
so a backend-only admission check would be invisible. Therefore the **visible**
surface is the existing **Data Sources panel** (US-18.2) on the Exposure tab,
which already self-fetches per-holding integrity info. The detector is also wired
into the admission summary as a proper `ImportAdmissionCheckV1` (the correct,
persisted data-quality home), so it is available to a future admission-review UI.

## Acceptance criteria

- [x] AC1 — A pure detector compares each **registry-known** holding's broker
  description against the registry's fund name and flags a mismatch only when
  their normalized significant-token sets are **disjoint** (conservative — no
  shared meaningful token). Formatting/suffix differences (e.g. "Vanguard S&P
  500 UCITS ETF" vs "VANGUARD S&P 500 UCITS ETF USD ACC") never flag.
- [x] AC2 — The `DFND` case flags: broker "iShares Global Aerospace & Defence
  UCITS ETF" vs a registry name like "VanEck Defense UCITS ETF" → mismatch
  (disjoint issuer/identity).
- [x] AC3 — Holdings **not** in the registry are skipped (no registry name to
  conflict with); holdings whose description is trivial (just the ticker) are
  skipped (no evidence to compare).
- [x] AC4 — The Data Sources panel on the Exposure tab shows a visible warning
  line for each mismatch, e.g. `⚠ Possible identity mismatch: DFND — statement
  says "iShares Global Aerospace & Defence UCITS ETF", registry says "VanEck
  Defense UCITS ETF"`. No mismatch → no warning shown.
- [x] AC5 — The detector is also exposed as an `ImportAdmissionCheckV1`
  (`check_id="instrument_description_registry_consistency"`): `warn` /
  `severity=warning` / `trust_impact=degraded` when any mismatch exists, else
  `pass` / `info` / `none`. It is added to `build_import_admission_summary`.
- [x] AC6 — It is a **flag only** — nothing rewrites the registry, remaps the
  symbol, or changes prices/sector. No fabrication; missing description → skipped.
- [x] AC7 — `npx tsc --noEmit` clean; backend + frontend suites green (only the
  known pre-existing FMP-offline failures remain); design-system audit green.

## Out of scope

- **Auto-correcting** the registry or remapping the symbol (flag only).
- **ISIN-keyed** verification — US-19.2 (needs authoritative ISIN data).
- A **dedicated Import Admission Review UI** — the check is added to the summary
  data, but building a full review screen is separate.
- Aggressive fuzzy matching — v1 flags only token-disjoint (clear) mismatches.

## Notes / decisions

- **Conservative by design.** Flag only when the two identity token-sets are
  disjoint. This catches different-issuer/different-fund mislabels (the real
  risk) while never firing on formatting/suffix noise. Trade-off: it will miss
  subtle mismatches that share a token (e.g. two different iShares funds) — an
  acceptable v1 limitation; tighten later if needed.
- **Normalization:** uppercase, strip punctuation, drop a stoplist of
  non-identifying tokens (UCITS, ETF, ETC, FUND, ACC, DIST, USD, EUR, GBP, GBX,
  INC, PLC, CLASS, SHARES, HEDGED, the ticker itself, …). Compare the remaining
  significant tokens.
- **Why surface on the Data Sources panel:** the admission summary isn't rendered
  today; the panel is the existing, visible, portfolio-level data-integrity
  surface. The admission check is still added for the correct persisted home.
- No new formula; no academic citation.
