# US-24.11: Render the replay disclosures the engine already computes

**Epic:** Epic 24 — Codebase Improvement
**PRD:** [`epic-24-codebase-improvement.md`](../prd/epic-24-codebase-improvement.md)
**Status:** Done
**Last updated:** 2026-08-09

## Story

As a **portfolio researcher**, I want the Dashboard to tell me when the replay
behind my performance numbers was **degraded** — a plugged cash anchor, a
withheld return day, holdings valued at a flat anchor, unconverted currencies —
so that I can judge how far to trust the numbers instead of reading a confident
chart built on inputs the engine already knows are imperfect.

## Context

Tech-debt register row **US-24.11**, logged by US-24.10 (2026-08-09).

Five replay disclosures are computed, schema'd, contract-documented and
golden-pinned on `DashboardHistoryRunMetadata`:

| Field | Story | Means |
|---|---|---|
| `fx_fallback_currencies` | US-27.8 | needed base conversion, no FX rate — carried unconverted |
| `unpriced_replay_symbols` | US-31.2 | held on some day, valued at $0 (no history, no anchor, no trade price) |
| `replay_cash_anchor` | US-31.3 | how opening cash was derived + its trust (`degraded` on a date mismatch) |
| `withheld_return_dates` | US-31.3 | days whose return was withheld as an accounting correction |
| `trade_price_anchored_symbols` | US-24.10 | valued at a carried broker trade price, flat between trades |

**`DashboardPanel.tsx` renders none of them** — `grep run_metadata` returns
zero occurrences. So on the committed IB2026 portfolio the researcher today
sees a performance chart, a TWR, monthly returns and a max drawdown built on a
`degraded` cash anchor (`statement_nav_date_mismatch`, −$1,196.61 residual),
with one return day withheld and LQQ valued flat at its statement close — and
**no indication that any of it happened**.

That contradicts the project's own stated rules: CLAUDE.md's frontend
convention ("Trust levels rendered visibly — never silently suppress `withheld`
or `degraded`") and guardrail #3 (surface the level, don't fill in plausible
values). The engine is honest; the screen is not.

The presentation pattern already exists on the Exposure side —
`DriftBenchmarkPanel.tsx:165-179` and `ExposurePanel.tsx:197` render exactly
this kind of degradation as `<p className="helper">` notes. This story brings
the Dashboard up to that bar. **No backend, no schema, no math** — the data is
already on the response.

Implementer must read: `.claude/skills/ui-polish/SKILL.md` (tokens, `CardShell`,
the audit contract); `apps/desktop/src/features/portfolio/DriftBenchmarkPanel.tsx:155-180`
(the note pattern to mirror); `docs/contracts/dashboard-fields.md` (the five
`run_metadata` rows — the wording there is the source of truth for what each
note must say); `apps/desktop/src/test/designSystem.audit.test.ts`.

## Acceptance criteria

- [x] AC1 — When the dashboard-history run reports **any** of the five
  disclosures, the Dashboard renders a card naming each one that is present,
  in plain language that states **what was degraded and what it affects** —
  not just a field dump.
- [x] AC2 — When **no** disclosure is present the card does not render at all;
  a clean run shows no empty card and no reassuring "all good" banner (absence
  of a warning is not a claim).
- [x] AC3 — The cash anchor renders **only** when its trust is not `verified`,
  and states the basis, both dates and the residual. A `verified` anchor is not
  worth a warning; a `degraded` one always is.
- [x] AC4 — Withheld return dates are shown **with the engine's own stated
  reason** (`withheld_return_reason`), never as an unexplained gap. `withheld`
  is never presented as `unavailable` (guardrail #3).
- [x] AC5 — **Truth class is not misrepresented.** These are broker-replay
  degradations, not synthetic history, so the card renders **no** `Synthetic`
  TrustBadge. (`TrustBadge` only supports `synthetic | unavailable`; using it
  here would assert a truth class that does not apply.)
- [x] AC6 — The card meets the design-system baseline: built on `CardShell`
  (so it is a `role="region"` with an accessible name), tokens only — no hex
  literals, no `px` literals — and it is listed in the audit's
  `ALL_CARD_FILES`.
- [x] AC7 — **Frontend stays thin** (guardrail #5): the component performs no
  financial computation — it reads, formats and renders fields the engine
  already produced. Formatting a currency residual or joining a symbol list is
  presentation, not finance.
- [x] AC8 — Backend untouched: no schema, route, engine or methodology change;
  `dashboardGoldens.ts` byte-identical.

## Out of scope

- **Any backend change.** The disclosures are already correct and complete;
  this is a rendering gap only.
- **Extending `TrustBadge`** with `verified`/`degraded`/`withheld` types. That
  is a design-system change affecting every card, and these notes read better
  as prose than as a badge. Recorded as a possible follow-up, not done here.
- **Rendering the same disclosures on the Exposure or Risk tabs.** Those tabs
  consume different engines with their own disclosure sets (Exposure already
  renders its two).
- **Blocking or gating any number** on a disclosure. This story makes
  degradation *visible*; the policy decisions about what to withhold already
  live in the engine and are not revisited here.

## Notes / decisions

- **Why a card and not an inline note per surface.** The five disclosures
  describe the *replay as a whole*, not one chart — the same degraded cash
  anchor underlies the performance chart, the TWR, monthly returns and max
  drawdown. One card that names the run's degradations is honest; sprinkling
  the same warning under four cards is noise.
- **Why no badge.** `TrustBadge` renders `Synthetic`/`Unavailable`. The
  imported ledger replay is **broker truth**, degraded — a different truth
  class (guardrail #2). Labelling it `Synthetic` would be a more precise-looking
  claim that is simply wrong. Prose notes carry the nuance the badge cannot.
- **Wording discipline.** Each note must say what is degraded *and what it
  affects* — the `DriftBenchmarkPanel` precedent ("...so window returns and the
  chart are degraded for the non-USD sleeve") is the bar. A note that only
  names a field teaches the researcher nothing.
- No new formula, so no academic citation is required; the methodology sections
  behind each disclosure (§Synthetic History Coverage Rule, §Rolling Pearson
  Correlation, and the US-31.3 cash-anchor rules) are unchanged by this story.
