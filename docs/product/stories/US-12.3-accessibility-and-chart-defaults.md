# US-12.3: Accessibility pass + Recharts defaults (ChartShell)

**Epic:** 12 — UI Polish & Design System
**PRD:** [`epic-12-ui-polish-design-system.md`](../prd/epic-12-ui-polish-design-system.md)
**Status:** Done
**Last updated:** 2026-05-28

## Story

As a **portfolio researcher**, I want every Exposure-tab chart to share the
same axis / grid / tooltip defaults and meet a baseline accessibility bar
(keyboard focus visible, ρ-sign distinguishable without color, charts and
cards screen-reader-announced) — so that the surface is usable on a real
research workstation (mouse, keyboard, color-blind, screen reader) and the
next analytics chart inherits the look without copy-pasting another twelve
lines of Recharts props.

## Context

US-12.2 extracted card-level primitives but the chart bodies still hand-roll
Recharts axis/grid/tooltip styling. `IndexedReturnChart`,
`RollingCorrelationChart`, and `FactorAttributionCard` each repeat:

```tsx
<CartesianGrid strokeDasharray="3 3" stroke="var(--color-border-subtle)" />
<XAxis tick={{ fontSize: 'var(--font-chart-tick)', fill: 'var(--color-text-muted)' }} minTickGap={40} ... />
<Tooltip contentStyle={{ background: 'var(--color-surface-elevated)', border: '...', borderRadius: '...', fontSize: '...' }} ... />
```

— and `RollingCorrelationChart` even has the chart wrapped in a manual
`<div style={{ height: 260 }}><ResponsiveContainer ...>` pair that other
charts duplicate with subtly different heights.

Separately, the surface has not had an accessibility pass. The custom
buttons (window selectors, table cells, badges) have no `:focus-visible`
styles — keyboard users get no indication of focus. The benchmark
correlation table encodes ρ sign **only** through color (teal/green/neutral/
orange/red), which fails the WCAG "do not use color as the sole means of
conveying information" criterion (and is unreadable for color-blind users).
And the cards themselves have no `role` / `aria-labelledby`, so a screen
reader sees an undifferentiated stream of paragraphs.

This story closes both gaps: a chart-defaults module + thin `<ChartShell>`
wrapper for the Recharts side, and per-primitive accessibility plumbing
(focus styles, sign symbols, region roles, chart aria-labels) for the a11y
side.

No backend changes. No analytics changes. No schema changes. No new
user-visible analytics — refactor + a11y polish only.

Implementer must read:

  to inventory the duplicated Recharts props that move to chart-defaults

  `aria-pressed` is the current contract; arrow-key keyboard support
  (moving focus between buttons with Left/Right) would be nice-to-have

## Notes / decisions

- **jsdom and `:focus-visible`**: jsdom (the DOM env vitest uses) does
  not apply `:focus-visible` styles automatically — it can compute that
  an element matches the selector but does not paint the outline.
  Implementer choices for AC6: (a) add a CSS class to `styles.css`
  for `.window-selector-btn:focus-visible` and assert in the test that
  the button has the class — clean but the test can't verify the
  outline color renders; (b) handle `onFocus`/`onBlur` in JS to set
  inline `outline` style and assert via `getComputedStyle`. Recommended:
  (a) — relies on real-browser behaviour for visual correctness, test
  pins the contract (button has the class).
- **`useId` over hand-rolled ids**: React 18's `useId` produces SSR-safe,
  collision-free ids without state. The CardShell story is the right
  place to introduce this pattern in the codebase — every future
  card-shaped primitive will benefit.
- **Sign symbols use Unicode geometric shapes**: ▲ U+25B2, ▼ U+25BC,
  • U+2022 (or ◆ U+25C6 for neutral if dot reads as bullet-list).
  No emoji — they render unreliably across operating systems and themes.
- **`ariaLabel` is required on ChartShell** because every Recharts chart
  is essentially an `<svg>` with no semantic content — a screen reader
  user gets nothing without an explicit label. Making it required forces
  the chart's caller (the three chart files) to provide one. The labels
  used in this story:
  - IndexedReturnChart → `"Indexed return time series for portfolio and benchmark"`
  - RollingCorrelationChart → `"Rolling correlation and beta vs benchmark, dual-axis line chart"`
  - FactorAttributionCard → `"Cumulative factor return attribution line chart"`
- **Recharts and `role="img"`**: setting `role="img"` on the outer
  container suppresses screen-reader announcement of every internal
  `<svg>` element and substitutes the single aria-label. This is the
  WAI-ARIA recommended pattern for data-visualization charts.
- **No academic citation** needed — pure UI story.
- **The opacity-via-`var()` JSDOM gotcha from US-12.1 / 12.2 still
  applies** to any numeric CSS prop. Focus outline width / color should
  go through CSS classes (option (a)), not React inline-style on
  numeric props.
