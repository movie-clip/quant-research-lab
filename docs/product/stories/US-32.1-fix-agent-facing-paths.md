# US-32.1: Fix the agent-facing instructions that point at files that do not exist

**Epic:** Epic 32 — Project Hygiene & Agent-Facing Doc Accuracy
**PRD:** [`epic-32-project-hygiene-and-agent-docs.md`](../prd/epic-32-project-hygiene-and-agent-docs.md)
**Status:** Next phase
**Last updated:** 2026-08-12

## Story

As a **developer or agent implementing a story**, I want every file path in
CLAUDE.md and the skills to resolve to a file that actually exists, so that I
stop losing time discovering by grep that the instruction was wrong.

## Context

Two agent-facing documents currently give instructions that cannot be followed
(PRD findings F-3, F-4), both verified on 2026-08-12.

**CLAUDE.md, Backend Conventions:** *"Schemas → service → route → register in
`app/main.py`"*. There is no `app/main.py` — the FastAPI app and every
`include_router` call live in `app/api/main.py`. The `write-story` and
`write-tests` skills already say it correctly, so CLAUDE.md is the only wrong
copy. This was surfaced on 2026-06-19, deferred because that task was scoped to
skills, and it cost time again in the 2026-08-11 session. The same section's
route list also omits `provenance`, `cache` and `currency_risk`.

**The `write-story` skill's analytics module table** lists three modules that do
not exist and omits eight that do:

| Listed, absent | Where it actually lives |
|---|---|
| `analytics/drift.py` | `services/drift_engine.py` |
| `analytics/exposure.py` | sector/look-through live inside `analytics/risk.py` |
| `analytics/portfolio.py` | the real module is `analytics/performance.py` |

Absent from the table but real: `activity.py`, `currency.py`,
`currency_exposure.py`, `currency_risk.py`, `overview.py`, `performance.py`,
`portfolio_imports.py`, `reconciliation.py`.

**This table has now been wrong three times.** The `quant-research` skill
carries an explicit warning saying so, and telling the reader to `ls` the
directory before trusting it. A warning that tells you not to trust the
document is a signal the document should be mechanically checked instead —
which is what this story adds.

Implementer must read: `CLAUDE.md` (Repository Layout ~:77, Backend
Conventions ~:164, doc map ~:41); `.claude/skills/write-story/SKILL.md` (module
table); `.claude/skills/quant-research/SKILL.md` (its table + the warning);
`services/quant-engine/app/api/main.py`.

## Acceptance criteria

- [ ] AC1 — CLAUDE.md's route-registration instruction names **`app/api/main.py`**,
  the file that actually holds the router registrations.
- [ ] AC2 — CLAUDE.md's `api/routes/` inventory lists every route module that
  exists, including `provenance`, `cache` and `currency_risk`.
- [ ] AC3 — The `write-story` module table names **no** module that does not
  exist, and every analytics module that *does* exist appears with a one-line
  description of what belongs there.
- [ ] AC4 — The same correction is applied to **`quant-research`**'s table,
  which carries the same three phantom rows.
- [ ] AC5 — **A test fails the suite when an agent-facing doc names a
  non-existent `app/...` path.** Scope: CLAUDE.md and the skill files. This is
  the deliverable that makes the fix durable — the table has been corrected
  before and drifted again.
- [ ] AC6 — The test reports **which file and which path** failed, so the fix is
  obvious without hunting.
- [ ] AC7 — The test cannot pass vacuously: if the scan finds no paths at all
  it fails, rather than silently succeeding on an empty set.
- [ ] AC8 — Behaviour-neutral: no production code changes,
  `dashboardGoldens.ts` byte-identical, full suite + tsc + dead-code gate green.

## Test plan

Backend (pytest):

- `test_docs_paths.py` *(new)* — **4 tests**: (1) every `app/<...>.py` path
  mentioned in `CLAUDE.md` resolves under `services/quant-engine/`, with the
  offending file+path named in the assertion message (**AC5/AC6**); (2) the
  same for every `.claude/skills/*/SKILL.md`; (3) every module in
  `app/analytics/` appears in the `write-story` table, so a *new* module cannot
  be silently omitted (the other half of the drift); (4) the scan is
  non-vacuous — it finds a known-good path such as `app/api/main.py`, so an
  empty or broken regex fails loudly (**AC7**).

Regression / guardrail:

- Documentation-only change: `dashboardGoldens.ts` byte-identical (**AC8**).
- `python scripts/run_all_tests.py` green; dead-code gate clean.

## Out of scope

- Rewriting the skills' workflow or structure — only the facts they state.
- Auditing paths in `docs/finance/` and `docs/contracts/` — **already verified
  correct** on 2026-08-12; the scan may cover them later, but this story fixes
  what is broken.
- Non-`app/...` paths (`apps/desktop/...`, `scripts/...`). Worth a follow-up if
  the same drift appears; no evidence of it today, and scope creep here would
  bury the finding that matters.

## Notes / decisions

- **Why a test rather than "just fix the table".** It has been fixed before and
  drifted back. The `quant-research` skill's own warning ("this table has been
  wrong more than once … run `ls` before trusting any row") is documentation
  admitting it cannot be trusted. Converting that into a failing test is the
  same move US-24.5 made for broker section labels, and US-24.9/US-24.10 made
  for the trade-leg rule: fix the class, not the instance.
- **Why CLAUDE.md matters more than an average doc.** It is injected into every
  agent's context automatically, so a wrong path there is read on every task in
  the repository.
- No formula or methodology change; no academic citation required.
