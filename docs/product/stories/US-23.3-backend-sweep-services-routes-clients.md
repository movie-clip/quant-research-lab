# US-23.3: Backend dead-code sweep — services, routes, clients, core, importers

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Done
**Last updated:** 2026-06-19

## Story

As a **developer of this project**, I want the backend wiring tier
(`app/services/`, `app/api/`, `app/clients/`, `app/core/`, `app/importers/`)
swept of confirmed-dead code and its smells catalogued, so that the request/
data-flow plumbing is only live code, with every route reachable and every
service method used.

## Context

This is the largest backend tier (~25 services, ~16 api files, clients, core,
importers). Using the US-23.1 detectors + the removal protocol, this story
deletes dead service helpers, unreachable/unregistered routes, unused client
methods, dead core utilities, and importer cruft — and records wiring smells
(inlined thresholds, fragile string parsing, duplicated helpers, broad
`except`) into the register. Route removal must respect dynamic registration:
the response-integrity property test (US-21.3) introspects the route table, so a
route that is registered-but-unreached is not necessarily dead.

Implementer must read:
- `docs/tech-debt-register.md` + removal protocol (US-23.1).
- `app/api/main.py` (route registration) + `test_engine_response_integrity.py`
  (route-table coverage) — to confirm route reachability.
- `app/services/*`, `app/clients/*`, `app/core/*`, `app/importers/*`.

## Acceptance criteria

  explicit attention to dynamic use: FastAPI route registration, importer

## Out of scope

- **Backend analytics/schemas/domain** — US-23.2.

## Notes / decisions

- **Route reachability ≠ test coverage:** a route can be registered and correct
  yet have no dedicated test; that is a coverage gap (register it), not dead
  code. Only an *unregistered* or *unreferenced* route handler is dead.
- **Broad `except Exception`** patterns (common in the fail-graceful market-data
  paths) are intentional fail-closed behaviour — record as a smell only if truly
  swallowing errors that should surface; do not "fix" here.
- No new formula; no methodology change.
