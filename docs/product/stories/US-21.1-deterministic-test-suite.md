# US-21.1: Deterministic suite — no live network in tests

**Epic:** Epic 21 — Testing Strategy & Architecture Hardening
**PRD:** [`epic-21-testing-strategy-hardening.md`](../prd/epic-21-testing-strategy-hardening.md)
**Status:** Next phase
**Last updated:** 2026-06-10

## Story

As a **developer of this project**, I want the entire backend test suite to
pass offline with zero live-network calls, so that "green" is unambiguous —
no standing "4 known failures" asterisk — and no future test can silently
depend on live FMP/Yahoo data again.

## Context

Four "real portfolio" tests construct engines with an **unmocked**
`MarketDataService` and hit live FMP:

- `test_stress_engine.py::test_run_stress_engine_returns_three_scenarios_with_non_null_pct`
- `test_drawdown_engine.py::test_run_drawdown_engine_returns_synthetic_for_real_portfolio`
- `test_drawdown_engine.py::test_run_drawdown_engine_populates_decomposition_for_episodes_when_positions_present`
- `test_distribution_engine.py::test_run_distribution_engine_returns_synthetic_for_real_portfolio`

Offline / keyless they fail; every verification report in Epics 17–20 carried
them as "known failures". `conftest.py` already has the machinery to fix this:
deterministic synthetic price generation (`_mock_price_rows`, sha256-seeded,
holiday-aware) and autouse `MarketDataService` mocks for the exposure /
dashboard-history / diagnostics engines — the stress / drawdown / distribution
engines were simply never given the same treatment. Beyond fixing these four,
the story adds an enforcement layer so a live-network test can never be merged
silently again.

Implementer must read:
- `services/quant-engine/app/tests/conftest.py` — `_mock_price_rows`,
  `_mock_prices_for_symbols`, the three existing autouse engine mocks, and the
  `_disable_yfinance_fallback` fixture (US-18.1) as the pattern
- the four failing tests + their engines (`stress_engine.py`,
  `drawdown_engine.py`, `distribution_engine.py`) to see which
  `MarketDataService` methods each consumes
- `.claude/skills/write-tests/SKILL.md` — to update with the no-network policy

## Acceptance criteria

- [ ] AC1 — `SKIP_GOLDEN_FRESHNESS_CHECK=1 pytest` passes **with zero failures**
  on a machine with no network access and no FMP API key.
- [ ] AC2 — The four listed tests run against mocked `MarketDataService` data
  (the conftest synthetic generator) and still assert their original intent:
  stress → 3 scenarios, non-null pcts, `trust='synthetic'`; drawdown →
  `trust='synthetic'` + populated decomposition; distribution →
  `trust='synthetic'`.
- [ ] AC3 — An autouse **network guard** makes any test that attempts a real
  network connection **fail loudly** with a message naming the offending test
  and the opt-out marker. Tests marked `@pytest.mark.live_data` are excluded
  from the default run (deselected, not skipped-silently-green) and can be run
  explicitly via `-m live_data`.
- [ ] AC4 — The guard does not break legitimate non-network I/O (file cache,
  `TestClient` in-process ASGI calls, tmp_path fixtures).
- [ ] AC5 — The `write-tests` skill documents the policy: no live network in
  default tests; use the shared conftest mocks; `live_data` marker for the rare
  explicitly-live test.
- [ ] AC6 — No engine/production code changes (test-layer only); frontend suite
  and `npx tsc --noEmit` unaffected.

## Test plan

This story *is* tests; the deliverable checks are:

Backend (pytest):
- The 4 converted tests pass offline (run with network disabled to prove it).
- `test_network_guard.py` (new) — **3 tests**: an unmarked test function that
  attempts a real socket connection fails with the guard's message (use
  `pytest.raises` around a direct call to the guard helper, or a `pytester`
  sub-run); a `live_data`-marked test is deselected by default (`-m "not live_data"`
  implied via `addopts`); file I/O and `TestClient` requests pass under the guard.

Regression / guardrail:
- Full backend suite green offline (AC1 is the gate).
- The three existing autouse engine mocks keep precedence semantics (tests that
  `mocker.patch` their own `MarketDataService` still override).

## Notes / decisions

- **Deselect, don't skip:** `live_data` tests must not show as green-skipped in
  the default run — deselection via `addopts = -m "not live_data"` keeps the
  default report honest. (After T-21.1.1 there may be zero `live_data` tests;
  the marker exists for future genuinely-live checks.)
- **Patch at import site:** each engine module does
  `from app.services.market_data import MarketDataService`, so mocks must patch
  `app.services.<engine>.MarketDataService` (the existing conftest pattern) —
  not the source module.
- **Why pytest-socket:** standard, tiny, battle-tested on Windows; a hand-rolled
  fixture is acceptable if adding the dep is undesirable, but must cover both
  `socket.socket` and `socket.getaddrinfo` to catch httpx and yfinance alike.
- No financial formula; no academic citation.
