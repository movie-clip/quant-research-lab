# US-18.4: Sanitize non-finite price rows at the market-data seam

**Epic:** Epic 18 — Secondary Market-Data Provider (bugfix follow-up)
**PRD:** [`epic-18-secondary-market-data-provider.md`](../prd/epic-18-secondary-market-data-provider.md)
**Status:** Done
**Last updated:** 2026-06-10

## Story

As a **portfolio researcher**, I want price rows with non-finite values to never
enter the analytics pipeline, so that a single bad provider bar (a Yahoo `NaN`
for an untraded day) cannot 500 my correlation views or silently poison any
other history-based metric.

## Context

**Live bug (2026-06-10):** `POST /engines/correlation/intra` and
`/engines/correlation/multi` return 500 with `ValueError: Out of range float
values are not JSON compliant: nan`. Root cause confirmed by cache scan: **38
`history_yf` cache entries carry `price: NaN` rows dated 2026-06-09** (all
Yahoo-sourced UCITS symbols). pandas represents missing bars as `float('nan')`
— not `None` — so `YFinanceClient._fetch`'s `if adj is None` check passes and
`float(nan)` succeeds, storing NaN rows into the cache. Downstream,
`pearson()`'s zero-variance guard doesn't catch NaN (NaN comparisons are always
False), so NaN propagates into the response. The attribution route survives only
because of the 2026-06-10 per-date finiteness hotfix.

Two-layer fix, per the fail-closed guardrail:

1. **Source:** `YFinanceClient` must skip rows whose adjusted close is not a
   finite number (it's a *missing bar*, not data).
2. **Seam:** `MarketDataService.get_historical_prices` must drop rows with
   non-finite/absent `price` before returning — this single choke-point protects
   **every** engine from the 38 already-poisoned cache entries (until TTL/clear)
   and from any future provider quirk, FMP included.

Implementer must read:
- `services/quant-engine/app/clients/yfinance_client.py` — `_fetch` row mapping
- `services/quant-engine/app/services/market_data.py` — `get_historical_prices`
  (both the FMP loop and the yfinance fallback return paths)
- `services/quant-engine/app/analytics/correlation.py` — `pearson()` (why NaN
  slips past the variance guard)

  `price`/`adjClose` is non-finite: a frame containing NaN bars yields only the

- [x] AC2 — `MarketDataService.get_historical_prices` never returns a row with a
  missing or non-finite `price`, regardless of provider or cache state — i.e.
  the 38 existing poisoned cache entries are neutralized **without** requiring a
  cache clear.
- [x] AC3 — With a NaN-bearing history (as cached today), `POST
  /engines/correlation/intra` and `/engines/correlation/multi` return **200**

  series, and correlations compute over the remaining overlap.
- [x] AC4 — Sanitization drops only non-finite rows; valid rows pass through
  byte-identical (no reordering, no value coercion beyond the drop).
- [x] AC5 — Full suites stay green (`npx tsc --noEmit` untouched — backend-only).

## Notes / decisions

- **Why sanitize at the seam too (not just the client):** the poison is already
  *cached*; fixing only the client leaves every engine broken until TTL expiry
  or manual clear. The seam filter also covers FMP (which could serve nulls/NaN
  someday) and is the single choke-point all ten engines share.
- **Missing bar semantics:** a non-finite bar is treated as *no data for that
  date* (row dropped), consistent with how providers represent untraded days —
  never zero-filled, never interpolated (fail-closed guardrail).
- No financial formula; no academic citation.
