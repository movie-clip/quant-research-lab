# US-27.1: Fix the Information Ratio annualization

**Epic:** Epic 27 — Financial Calculation Correctness
**PRD:** [`epic-27-financial-calculation-correctness.md`](../prd/epic-27-financial-calculation-correctness.md)
**Status:** Done
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher**, I want the Information Ratio on the Risk
Summary card to be the annualized IR the methodology documents, so that the
number is comparable to published IR figures instead of being ~15.9× too
small.

## Context (audit finding F1)

`analytics/risk.py` `build_relative_risk_summary` computes:

```python
information_ratio = (mean_active * sqrt(252)) / tracking_error   # tracking_error is already annualized (σ_daily × √252)
```

which algebraically reduces to `mean_daily / σ_daily` — the **daily** IR.
`financial-methodology.md` §Information Ratio (written in US-25.5, after the
code) documents the standard annualized form:

```text
information_ratio = (mean_active_return * 252) / tracking_error
```

i.e. the daily IR × √252. The displayed value (Dashboard → Risk Summary card,
US-25.5) is under-stated by √252 ≈ 15.87. No test pins a numeric IR value —
`test_analytics.py` / `test_routes.py` only assert null vs not-null, which is
exactly how this slipped through.

Implementer must read:
- `analytics/risk.py` `build_relative_risk_summary` (the one-line fix site).
- `docs/finance/financial-methodology.md` §Information Ratio (the target
  formula, edge cases — do not change the doc; change the code to match).
- `apps/desktop/src/features/portfolio/RiskSummaryCard.tsx` — display only;
  confirm formatting still reads sensibly at the new magnitude.
