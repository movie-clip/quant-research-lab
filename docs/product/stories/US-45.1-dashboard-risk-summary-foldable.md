## Story statement

**As a** portfolio researcher,
**I want** to collapse the Dashboard's Risk Summary card to a compact header
and re-expand it,
**so that** I can reduce it to a glance-level summary when I don't need its
detail, without it crowding the rest of the Dashboard.

## Context

`RiskSummaryCard` (`apps/desktop/src/features/portfolio/RiskSummaryCard.tsx`)
is the densest card on the Dashboard tab: it renders up to 14 stat rows (11
always-shown volatility/drawdown/concentration metrics plus 2 conditional
relative-risk metrics shown only when tracking error is present). No other
Dashboard, Exposure, or Risk tab card currently folds or collapses as a whole
unit — `DrawdownAnalyticsCard.tsx` has row-level expand/collapse
(`expandedKey` state, per drawdown episode), which is a different pattern at a
different granularity and is not reused or generalized by this story.

This is a **presentation-only** change: fold/expand state affects only whether
`RiskSummaryCard`'s detail rows are rendered. No financial value changes, no
trust-state computation or rendering changes, and no other Dashboard card's
state is read or affected. The card's `unavailable` empty state (rendered when
`diagnosticsAnalysis` or its sub-sections are missing) is unaffected by this
story — collapse/expand applies to the populated-data rendering path only.

The implementer must read: `apps/desktop/src/features/portfolio/RiskSummaryCard.tsx`
(current rendering); the `ui-polish` skill (card scaffold conventions —
mandatory for any card work per project routing); and
`apps/desktop/src/test/designSystem.audit.test.ts`, since this changes an
audited card's rendering shape.

## Acceptance criteria

1. **Default expanded.** On first render, with data available, the Risk
   Summary card shows all of its current detail rows (the same content it
   renders today) — the fold defaults to expanded, not collapsed.

2. **Toggle control.** The card exposes a control the researcher can activate
   to switch between expanded and collapsed, and activate again to switch
   back — a single control, not a separate collapse action and a separate
   expand action.

3. **Collapsed hides detail.** When collapsed, none of the card's stat rows
   (volatility, drawdown, concentration, or the conditional relative-risk
   rows) are rendered.

4. **Collapsed shows a compact header summary.** When collapsed, the card
   still renders a compact header-level summary — at minimum the card's title
   and its current trust label (the "Risk contribution basis" indicator shown
   today) — so the researcher can tell at a glance that the card is present
   and what basis its (hidden) figures are on, without seeing the row detail.

5. **Toggle state is legible to assistive technology.** The toggle control's
   expanded/collapsed state is programmatically exposed (for example via
   `aria-expanded`), matching the convention `DrawdownAnalyticsCard.tsx`
   already uses for its row-level expand/collapse.

6. **Scoped to this card.** Collapsing or expanding the Risk Summary card
   changes no other Dashboard card's rendering, layout, or state — the
   Benchmark, Monthly Returns, and any other Dashboard card render identically
   regardless of this card's fold state.

7. **No change to values or trust rendering.** Every figure and trust
   indicator the card shows while expanded is identical, in value and in
   trust treatment, to what it shows today — this story changes only whether
   the rows are rendered, never what they would render.

8. **Unavailable state unaffected.** When the card is in its existing
   `unavailable` empty state (no diagnostics data), the fold control does not
   apply — the card renders its current empty-state message as it does today,
   with no collapse affordance offered over an empty state that has nothing to
   collapse.

## Test plan

Names the files and behaviours; individual test names and counts are the test
lane's to determine.

**Frontend (vitest, `apps/desktop/src/features/portfolio/`)**

- A test file colocated with `RiskSummaryCard.tsx` (or extending its existing
  coverage if any) asserting: default-expanded rendering shows all rows;
  activating the toggle collapses the card and hides the rows; activating it
  again re-expands and restores the rows.

  no stat rows.
- `aria-expanded` (or equivalent) reflects the current state through both
  transitions.

  rendered/offered over the empty state, and the empty-state message still
  renders.

  integration coverage lives) confirms collapsing the Risk Summary card
  leaves sibling Dashboard cards' rendered output unchanged.
- `apps/desktop/src/test/designSystem.audit.test.ts` still passes against the
  modified card without requiring a new exemption.

## Out of scope

- A reusable `CollapsibleCard` primitive, or any generalization of this fold
  pattern to another Dashboard, Exposure, or Risk tab card. Deferred as a
  follow-up if a second card later needs the same interaction — not built or
  proposed here, per the human's decision recorded in § Open decisions.
- Persisting the collapsed/expanded preference across sessions (e.g. to
  `localStorage`). Not required by this story; may be added later without
  this story's ACs blocking it, since it is additive to the toggle this story
  defines.
- The row-level expand/collapse pattern already present in
  `DrawdownAnalyticsCard.tsx` — unrelated, untouched.
- The drawdown/information-ratio withholding-gate findings from the financial
  audit (`01-quant-audit.md`) — separate, unrelated work.
- Any change to `RiskSummaryCard`'s data source, computed values, or trust
  derivation.
