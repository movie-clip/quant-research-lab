# US-34.9: Source adjusted closes so the verified benchmark rung can fire

**Epic:** Epic 34 — An Answerable Dashboard: Reachable Trust States
**PRD:** [`epic-34-answerable-dashboard-and-reachable-trust.md`](../prd/epic-34-answerable-dashboard-and-reachable-trust.md)
**Status:** Done (2026-08-17)
**Last updated:** 2026-08-17

## Story

As a **portfolio researcher**, I want the benchmark comparison to rest on
**dividend-adjusted** closes, so that "how did I do against SPY" is answered on
a like-for-like total-return basis instead of a price return that structurally
flatters my portfolio.

## Context

US-34.5 publishes the benchmark return and the excess, correctly labelled
`price_return_only`, and states the resulting bias on the card: a price return
omits the benchmark's dividends, so it understates the benchmark and flatters
the excess by roughly 0.7pp over the current window. That label is honest, but
it is a workaround for **F-9** — the `verified_total_return` rung exists and
**cannot fire against the real provider**.

`_validate_verified_benchmark_slice` (`app/services/dashboard_history_engine.py`)
admits the verified rung only when *both* hold:

1. `fetch_meta.endpoint == VERIFIED_BENCHMARK_ENDPOINT`, pinned to
   `"historical-price-eod/light"`; and
2. **every** in-window row carries `adjClose`.

The FMP client has exactly one history method, `get_historical_price_light`, and
the light endpoint returns `symbol, date, price, volume`. The two conditions are
mutually unsatisfiable, so the rung is unreachable by construction — the same
shape as F-1a.

This story sources adjusted closes from FMP's dividend-adjusted endpoint for the
**benchmark only**, and makes the gap between "the code can fire" and "the
committed data makes it fire" a *tested* fact rather than a silent one.

§*Benchmark and Factor Return Methodology* and its §*Mixed-basis
portfolio-vs-benchmark comparison (US-34.5)* subsection;

### Verified facts this story rests on

Established by reading the code and the committed data, not assumed:

- **The endpoint exists.** FMP `/stable/historical-price-eod/dividend-adjusted`
  returns `adjOpen, adjHigh, adjLow, adjClose` alongside `close` and `volume`.
  `close` is split-adjusted only; `adjClose` is split **and** dividend adjusted.
  The client's `fmp_base_url` already points at `/stable`.
- **`adjClose` already flows through the stack — from the other vendor.** Of the
  9,288 frozen rows in `golden_market_data.json`, **2,079 carry `adjClose`**
  across 14 of 65 series. All 14 are non-US listings (SXRV, VUAA, IUIT, SGLD…)
  served by the **yfinance fallback**, whose `_fetch` reads `Adj Close` with
  `auto_adjust=False`. Every US symbol — including all 148 SPY rows — has none.
  So the row shape and the classifier already work; only the FMP fetch is
  missing.
- **The seam is clean.** `get_direct_verified_benchmark_history` is a dedicated
  benchmark-only method. Nothing else calls it, so changing its endpoint cannot
  reach portfolio valuation.
- **`_sanitize_price_rows` filters, it does not reshape** — it drops rows whose
  `price` is absent or non-finite and preserves every other key, so `adjClose`
  passes through untouched.
- **The benchmark's *plotted* prices switch too, and that is intended.**
  `select_history_price_series` (`app/analytics/risk.py`) prefers `adjClose`
  whenever **every** dated row carries it, and `build_benchmark_comparison`
  builds `points[].price` from that same selection. So on re-capture the chart's
  SPY line and `performance_series[].benchmark_price` become the adjusted
  series. For a chart that indexes both lines to 100, a total-return benchmark is
  the *more* correct comparison — but it is a visible change to a published
  family, so AC3 scopes byte-identity to the **portfolio** valuation families
  rather than to the goldens as a whole.
- **`adjClose` alone is not sufficient.** `classify_history_return_basis_contract`
  maps adjusted-close rows to `unverified_adjusted_proxy`, which US-34.5
  deliberately excludes from publishing. Only a non-`None`
  `_validate_verified_benchmark_slice` promotes `benchmark_path` to
  `verified_total_return`, so the endpoint constant and the scope evidence must
  move together with the data.

## Acceptance criteria

- [x] AC1 — **The benchmark is fetched from an endpoint that carries adjusted
  closes.** `get_direct_verified_benchmark_history` requests
  `historical-price-eod/dividend-adjusted`, and `VERIFIED_BENCHMARK_ENDPOINT`
  names that same path, so the endpoint condition and the `adjClose` condition
  are satisfiable by the same response.

- [x] AC2 — **The response is mapped into this project's row shape.** Rows expose
  `price` (the unadjusted/split-adjusted close, so the chart and every existing
  consumer are unchanged) **and** `adjClose`. A response that omits `close`
  yields no rows rather than rows silently dropped by `_sanitize_price_rows` —
  the failure is visible, not a blank benchmark.

- [x] AC3 — **Only the benchmark changes basis.** Position and FX history still
  go through `get_historical_price_light`. Every `total_market_value`,
  `total_portfolio_value`, `cash` and position-level valuation in the goldens is
  **byte-identical**: portfolio valuation must use real traded prices, never
  dividend-adjusted ones. The benchmark's own price families
  (`benchmark.points[].price`, `performance_series[].benchmark_price`) *do*
  change on re-capture, because the shared price selector prefers `adjClose` —
  that is the intended like-for-like comparison, and AC8 requires the diff to be
  characterised rather than merely accepted.

- [x] AC4 — **With adjusted rows present, the rung fires.** Given an in-window
  SPY slice where every row carries `adjClose` and the fetch meta reports the
  dividend-adjusted endpoint with `direct_path_only`, `benchmark_path` is
  `verified_total_return`, `benchmark.return_pct` is published, and the range
  scalars publish on that basis.

- [x] AC5 — **The dividend caveat disappears exactly when it stops being true.**
  On `verified_total_return` the card renders no price-return marker and no
  "understates the benchmark" caveat; on `price_return_only` both still appear.
  US-34.5 already made the caveat conditional — this AC pins that it is keyed to
  the basis and not to anything else.

- [x] AC6 — **Fail-closed is preserved on every degraded path.** A partial
  `adjClose` (one row missing it), a fallback/proxy/override fetch, a
  non-allowlisted symbol, or an unordered/duplicated slice each keep
  `benchmark_path` **below** `verified_total_return` and never fabricate an
  adjusted value from an unadjusted one.

- [x] AC7 — **The committed data's real state is asserted, not assumed.** A test
  reads `golden_market_data.json` and asserts the SPY slice's actual `adjClose`
  coverage together with the basis the engine derives from it. F-9 survived
  because the verified rung's tests used hand-written rows while the shipped data
  had none; this test fails the day the two diverge, in either direction.

- [x] AC8 — **The re-capture step is explicit and its effect is characterised.**
  Until `golden_market_data.json` is re-captured with an `FMP_API_KEY`, SPY
  carries no `adjClose` and the basis stays `price_return_only` — the shipped
  behaviour is unchanged and honest. The story records the exact command, and the
  expected direction of the change: a total return **exceeds** the price return,
  so `benchmark_return_pct` rises and `excess_return_pct` falls by approximately
  the window's dividend yield (~0.7pp on the current window; the precise figure
  is not claimed here because it cannot be measured without the key). The diff is
  characterised by family, and must show the benchmark return, excess, basis and
  benchmark price families changing while every portfolio valuation family stays
  byte-identical.

- [x] AC9 — **The `fmp-data` skill stops asserting the opposite of the truth.**
  It currently states that `historical-price-eod/light` "returns `adjClose` for
  US-listed equities and ETFs". The committed data shows the exact inverse:
  `adjClose` appears only for **non-US** listings, and only via **yfinance**. The
  corrected claim names the endpoint per field and the vendor per basis.

## Out of scope

- **Promoting `unverified_adjusted_proxy`.** The yfinance-sourced adjusted closes
  for non-US listings stay exactly where they are. This story reaches the
  verified rung through the *allowlisted, direct, single-vendor* path the
  validator already specifies; it does not widen the validator.
- **Adjusted prices for portfolio valuation.** Market values must use real traded
  prices. Dividend-adjusted closes are for the benchmark *return* only (AC3 pins
  this).
- **The drawdown family.** Still withheld under F-10's scoping; adjusted
  benchmark closes do not change that, and F-11 already established the Dashboard
  drawdown chain is total-return-like via ledger cash.
- **Adding QQQ data.** QQQ is already in the allowlist; nothing here depends on
  capturing it.
- **The portfolio leg's exact-slice admission (F-1a).** Unreachable for
  independent structural reasons; untouched.

## Notes / decisions

- **No new formula.** The benchmark return is still `end/start − 1`; this story
  changes only *which price series* it is computed from. The methodology entry
  gains a row and a source, not an equation.
- **Why the benchmark-only scope is a hard constraint, not a preference.** A
  dividend-adjusted series is a *return* series, not a *value* series. Using it
  for holdings would make `total_market_value` disagree with the broker's own
  statement — the exact truth-class mixing the project's second guardrail
  forbids. The dedicated `get_direct_verified_benchmark_history` seam is what
  makes the narrow scope enforceable rather than merely intended.
- **The row-shape trap.** `_sanitize_price_rows` drops any row without a finite
  `price`. The dividend-adjusted response has `close`/`adjClose` and **no `price`
  key**, so swapping the endpoint without mapping the shape would drop *every*
  row and blank the benchmark silently — a fail-closed path reached for an
  accidental reason. AC2 exists specifically to prevent that.
- **Why AC7 is not optional.** F-9 is a story about a rung whose tests passed
  while the shipped data could never satisfy it. Fixing the endpoint without
  pinning the committed data's real state would leave the same class of gap open,
  just moved one step along.
- **On the expected magnitude.** SPY's trailing yield is ~1.2%/yr, so over the
  current ~7-month window the total return should exceed the price return by
  roughly 0.7pp, moving the excess from −11.21pp to about −11.9pp. This is an
  *estimate*, deliberately not written as a measured figure anywhere in the ACs —
  it cannot be measured without the re-capture, and F-9 is a story about exactly
  the danger of asserting what has not been checked.

## Outcome (2026-08-17)

**The rung fires.** SPY publishes **+12.35%** on `verified_total_return` against
the **+11.75%** price return it showed before, and the excess moves from
**−11.21pp** to **−11.92pp**. The dividend caveat is gone from the card because
it is no longer true. Per range: 1M **+2.86%** (excess +1.28pp), 3M **+4.50%**
(−2.94pp), All/YTD/1Y **+12.35%** (−11.92pp).

Getting there took **two** fixes beyond the story's premise, both found only
because the data was actually re-captured rather than simulated:

- **F-14 — vendor row order.** `_validate_verified_benchmark_slice` requires
  ascending dates; FMP returns newest-first. With the endpoint fixed and every
  row carrying `adjClose`, the validator still rejected the slice — and the
  failure was **silent and strictly regressive**: the basis fell to
  `unverified_adjusted_proxy`, which publishes nothing, so the Dashboard briefly
  went from a labelled +11.75% to no figure at all. Every existing fixture
  hand-wrote its rows in ascending order, so nothing failed. Fixed by
  normalising order in the client join, not by relaxing the validator.
- **F-15 — the fallback provider valued holdings at adjusted prices.**
  `yfinance_client` put the adjusted close in both `price` and `adjClose`, so
  the 14 non-US holdings were *valued* on a different basis from FMP-served
  ones. Same defect this story was fixing on the FMP side, so it was fixed in
  the same pass.

**The response shape was not what the story assumed.** `dividend-adjusted`
returns `adjOpen/adjHigh/adjLow/adjClose` and **no `close`**; `full` returns
`close` and no adjusted figure. The first implementation mapped `price` from a
`close` key that is not there, dropped all 148 rows, and emptied the benchmark —
which then degraded the whole capture to 21 of 73 series. The client now joins
the two responses. `test_fmp_client.py` pins that failure mode.

**The re-capture also improved valuation accuracy**, independently of the
benchmark work. The 14 European-listed holdings previously had no 2026-08-11
quote and were carried forward from 2026-08-10; they now have the real
terminal-day close, which is the date the statement itself is drawn on. Against
the broker's own stated values: **VUAA +$24.00 → $0.00**, **SEMI −$6.40 →
$0.00** — exact — and the terminal reconciliation residual fell from
**−$58.11 to −$19.98**. Several replay pins moved accordingly; each was updated
to the value that now agrees with the statement, not merely to whatever the code
emitted.

**A cache hazard worth knowing.** The first capture attempt ran with the broken
mapper and left 81 negative-cached (`[]`) history entries, because the FMP client
caches 401/402/403/404 as empty. That silently shrank the next capture to 21
series. `python scripts/manage_cache.py clear --namespace history` fixes it, but
note the command does not cover the `history_yf` namespace, which has to be
cleared by deleting `data/raw/fmp-cache/history_yf-*.json`.
