# US-21.4: Golden pipeline determinism

**Epic:** Epic 21 — Testing Strategy & Architecture Hardening
**PRD:** [`epic-21-testing-strategy-hardening.md`](../prd/epic-21-testing-strategy-hardening.md)
**Status:** Done
**Last updated:** 2026-06-11

## Story

As a **developer of this project**, I want the dashboard goldens generated from
a committed, frozen market-data fixture instead of the live FMP cache, so that
bare `pytest` is green offline with no env var, `dashboardGoldens.ts` stops
churning per machine, and the freshness check compares deterministic input
against a deterministic golden — closing the "`git checkout` the goldens before
every commit" gotcha that recurred all through Epics 16–20.

## Context

`app/scripts/export_dashboard_goldens.py::render_dashboard_goldens_text` builds
the goldens by calling `run_imported_dashboard_history(snapshot, "SPY")`, which
constructs `MarketDataService()` internally and pulls benchmark rows, per-symbol
histories, and fetch-meta from the **live FMP/Yahoo cache**. Those values vary
by machine and over time, so the generated `apps/desktop/src/test/dashboardGoldens.ts`
churns, and the session-scoped goldens-freshness fixture in
`app/tests/conftest.py` re-runs the same live path — which is why bare `pytest`
needs a warm cache (or `SKIP_GOLDEN_FRESHNESS_CHECK=1`) to pass and why
`run_all_tests.py` must pre-warm by regenerating against live data first.

The history **window** (`_derive_imported_history_window`) is already
deterministic — it is `min`/`max` of the parsed ledger trade-dates and position
as-of-dates from the committed `docs/IB2026.pdf` / `docs/FF2026.pdf` statements.
The *only* non-deterministic input is `MarketDataService`. This story severs
that one coupling: it adds a market-data injection seam to
`run_imported_dashboard_history`, captures the exact rows + fetch-meta the
goldens currently consume into a committed JSON fixture, and points both the
generator and the freshness check at a frozen provider that replays it. No
financial formula changes; the goldens' *content* is byte-identical to today's
(the capture records current live output), only its *source* becomes frozen.

Implementer must read:
- `app/services/dashboard_history_engine.py` —
  `run_imported_dashboard_history` (lines ~402–490): the four
  `MarketDataService` calls to replay — `get_direct_verified_benchmark_history`,
  `get_historical_prices` (non-allowlisted-benchmark branch),
  `get_historical_prices_for_symbols`, `get_last_fetch_meta`.
- `app/scripts/export_dashboard_goldens.py` — `render_dashboard_goldens_text`,
  `_build_fixture`, `main`.
- `app/tests/conftest.py` — `_check_dashboard_goldens_freshness` (the
  session-autouse fixture to make deterministic + env-var-free).
- `scripts/run_all_tests.py` — the goldens-regeneration step that pre-warms.

## Test plan

Backend (pytest):
- `test_golden_pipeline_determinism.py` (new) — **4 tests**:
  (1) `render_dashboard_goldens_text()` called twice returns identical text
  (determinism, no network — runs under the socket guard);
  (2) the generated text equals the committed `dashboardGoldens.ts`
  (freshness, deterministic — the in-process analogue of the conftest fixture);
  (3) `FrozenMarketData.get_historical_prices_for_symbols` /
  `get_direct_verified_benchmark_history` replay the fixture rows and
  `get_last_fetch_meta` replays the captured meta;
  (4) `FrozenMarketData` raises (not returns empty) for a symbol/window absent
  from the fixture (stale-fixture detection, AC2).
- `app/tests/conftest.py` — freshness fixture switches to the frozen path;
  existing tests stay green with **no** `SKIP_GOLDEN_FRESHNESS_CHECK`.

Frontend (vitest):
- No new tests. Existing dashboard goldens specs (the `ib2026*` / `ff2026*`
  consumers) must stay green unchanged — the proof that AC6 (byte-identical
  content) holds.

Regression / guardrail:
- Full backend suite green under the network guard with **no env vars set**
  (the gate that AC4 removes the env-var dependency).
- `python scripts/run_all_tests.py` leaves `git status` clean (AC5).
- `run_imported_dashboard_history` route/service tests unchanged (AC1 — seam is
  additive).

## Out of scope

- Re-capturing goldens with *different* market data or a *different* statement
  set — this story freezes today's output, it does not change what the goldens
  represent.
- Generalizing the frozen-provider pattern to other engines' tests (those are
  already mocked via US-21.2 fixtures; this is specifically the golden-generation
  path, which is production script code, not a test).
- Removing the goldens-freshness fixture or the `run_all_tests.py`
  regeneration step — both stay; they just become deterministic.
- Refactoring `MarketDataService` into a formal `Protocol`/ABC — `FrozenMarketData`
  duck-types the four consumed methods; a formal interface is a possible later
  cleanup, not required here.

## Notes / decisions

- **Why capture-then-replay (not synthesize):** the goldens encode real verified
  SPY total-return behaviour and real per-symbol histories; synthesizing prices
  would change the goldens' content and cascade into every frontend dashboard
  spec. Recording current live output and freezing it keeps the content
  byte-identical (AC6) while making the *source* deterministic.
- **Why fail-loud on cache-miss (AC2):** a frozen fixture that silently returns
  `[]` for an unknown symbol/window would make a stale fixture look like an
  "unavailable history" golden — exactly the kind of silent fallback the project
  forbids. Raising turns "the statements changed but nobody re-captured" into a
  test failure, not a wrong golden.
- **Why the window is already safe:** `_derive_imported_history_window` is
  `min`/`max` over parsed ledger/position dates from the committed PDFs — no
  wall-clock dependency — so freezing `MarketDataService` is sufficient for full
  determinism (verified while authoring this story).
- No new financial formula; no academic citation. Methodology unchanged — this
  is test-infrastructure determinism, not analytics.
