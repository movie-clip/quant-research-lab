# US-15.2: Drawdown card "Contributors" drawer

**Epic:** 15 — Position-Level Analytics
**PRD:** [`epic-15-position-level-analytics.md`](../prd/epic-15-position-level-analytics.md)
**Status:** Done
**Last updated:** 2026-06-04

## Story

As a **portfolio researcher**, I want each row in the Drawdown
Analytics card's top-5 episodes table to expand into a
"Contributors" drawer showing the per-position decomposition
(symbol, weight at peak, return over the episode, contribution to
the portfolio drawdown), so that I can answer "which holdings
drove this drawdown?" on screen instead of guessing from
portfolio-level magnitude alone.

## Context

US-15.1 (Done, commit `9e6e967`) shipped the backend half of Epic
15: every `DrawdownEpisode` in the `/engines/drawdown/run`
response now carries `top_contributors: EpisodeContributor[] | null`,
`other_contribution_pct: number | null`,
`decomposition_residual_pct: number | null`, and
`decomposition_trust: 'synthetic' | 'partial' | 'unavailable'`.
The TS mirror types are already in
`apps/desktop/src/features/portfolio/types.ts`. The methodology is
in place under `## Wealth Index and Drawdown` →
`### Drawdown episode decomposition` in
`docs/finance/financial-methodology.md` — arithmetic Brinson-style
attribution, citations recorded.

This story is the frontend half: extend
`apps/desktop/src/features/portfolio/DrawdownAnalyticsCard.tsx`'s
existing top-5 episodes table with an expandable per-row "Contributors"
drawer. No backend, no methodology, no schema change. UI is
rendering-only: it consumes the new schema fields and surfaces
them with the established design-system tokens.

## Notes / decisions

- **Single-open drawer vs multi-open.** Single-open is
  intentional for a 5-row table — clicking a different
  episode signals "I'm done comparing the previous one." It
  also keeps the table compact: at most one drawer's worth
  of vertical real estate is added. Multi-open would let
  researchers compare two episodes side-by-side, but with
  only 4-row drawers the comparison value is low. Revisit
  if a researcher actually asks for it.
- **Residual row threshold of 0.05%.** Chosen as a "visible
  signal" floor: residuals below 0.05% are almost certainly
  floating-point noise from the synthetic decomposition.
  Above 0.05% the residual is material and indicates either
  a methodology edge case (cash share, position-level data
  gap) OR a methodology violation (which the engine's
  reconciliation invariant would have raised). The 0.05%
  threshold matches typical chart-tick precision for
  percentages and is a reasonable "would a researcher
  notice this?" cutoff.
- **"Other" aggregate row threshold of 0.01%.** Same logic
  as residual: below 0.01% the aggregate is rounding noise
  not worth surfacing. Above 0.01% it represents the bottom
  positions' contribution and is worth showing for
  completeness.
- **No new design-system primitives.** The drawer fits
  inside the existing table semantics + design tokens
  (already exhaustive: spacing, font, color, border, radius
  tokens all cover the drawer's needs). The expand toggle
  is a plain `<button>` styled via inline tokenised CSS — no
  new primitive component needed for a one-off interaction.
- **Why expand toggle in the table, not on row click.** A
  whole-row click would conflict with future row interactions
  (e.g. sortable columns, link to episode detail) and isn't
  obviously interactive from look-and-feel. A dedicated
  `<button>` with a visible glyph is the standard pattern
  and screen-reader-friendly.
- **No methodology change.** All math lives in the
  US-15.1-shipped `decompose_drawdown_episode`. This story
  is rendering-only. The frontend never computes
  contribution, weight, or return — it formats and colors
  what the backend supplies (per CLAUDE.md guardrail #5,
  desktop stays thin).
- **No backend change, no schema change, no methodology
  change.** Everything this story needs is already in place
  from US-15.1.
- **No contract doc update here.** Reconciling
  `docs/contracts/risk-fields.md` with the
  decomposition fields lands in US-15.4 (epic close-out),
  not this story.
