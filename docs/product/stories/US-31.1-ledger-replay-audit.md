# US-31.1: Findings-first audit of the imported ledger replay

**Epic:** Epic 31 — Ledger Replay Correctness
**PRD:** [`epic-31-ledger-replay-correctness.md`](../prd/epic-31-ledger-replay-correctness.md)
**Status:** Done
**Last updated:** 2026-07-18

## Story

As a **portfolio researcher**, I want the imported ledger-replay path — the one
the product presents as broker truth — audited and its defects recorded with
reproducible evidence before anyone changes it, so that the fixes that follow
are grounded in a written record rather than guesswork, and so I learn which of
the numbers on my screen I can trust **today**.

## Context

This audit was seeded by a defect found while scoping tech-debt **US-24.9** (the
deferred ledger-path cash de-dilution from Epic 30 / PRD F-10). The intended
work — refine the return-series basis on the ledger path — turned out to be
premature: **the series that basis would refine is itself corrupted.**

Reproduced against the committed `docs/IB2026.csv` portfolio using the **frozen**
`app/scripts/golden_market_data.json` (deterministic, network-free — so the
numbers are not a local FMP-cache artifact):

- Day 1 (2026-01-08): only **11 of 38** reconstructed opening positions are
  priced; opening market value **$14,582.03** vs implied true **$50,116.24**.
- Opening cash anchors at **$37,799.09** where the statement implies
  **$2,264.88** — a **$35,534.21** drift, exactly the position undervaluation.
- The terminal reconciliation corrects it all on the final day, producing a
  **−36.34%** fabricated return (vs **+0.57%** without reconciliation) and
  inflating annualised volatility **36.05% → 64.55% (+79%)**.

The PRD's F-1..F-3 table records the full causal chain with file:line evidence.
**This story is audit only** — it produced that table and adds no fixes. Fixes
are US-31.2 / US-31.3, scoped *from* the table. Findings-first is what kept
Epic 27 and Epic 30 honest: the record is written before anyone is tempted to
make a number look right.

### Is any of this actually on screen? — yes (impact map, AC3)

The findings establish the *engine series* is wrong; the impact map establishes
what a **user sees**. Both policy gates are hard constants returning `False`
(`diagnostics_engine.py:208,253`), so part of the corrupted series is withheld
— but **not the most prominent surfaces**:

- **Surfaced and corrupted:** the Exposure tab's rolling correlation & beta
  chart; risk-summary `portfolio_beta` / `portfolio_correlation` / `r_squared`;
  `portfolio_volatility_pct` (where the +79% inflation lands); the statistical
  factor model (and, through it, `risk_contribution_breakdown`);
  `realized_vol_60d` / `downside_vol_60d` (the drawdown gate nulls only the
  drawdown fields, not the vol fields).
- **Gated to `null` (protected today):** the relative-return family (tracking
  error, active return, information ratio) and the drawdown family.

So F-1..F-3 are genuinely user-facing. The full table is in the PRD.

## Test plan

This is an audit story, so the "tests" are **reproduction pins**, not fixes.

Backend (pytest), new `test_ledger_replay_audit.py` (**+3**), each marked as
documenting *current, known-wrong* behaviour (so a future fix flips them
deliberately rather than surprising someone):

- (1) **F-1 pin** — building imported daily states for the IB2026 snapshot with
  the frozen fixture leaves a substantial share of day-1 reconstructed
  positions unpriced (asserts the *presence* of the gap, e.g. unpriced count > 0
  and opening MV materially below the statement-implied opening position value).
- (2) **F-2 pin** — the engine's opening cash differs from the
  statement-implied opening cash (`cash_total − net_window_flow`) by a material
  amount, demonstrating cash absorbing the valuation error.
- (3) **F-3 pin** — the final replayed daily return differs materially between
  `apply_terminal_reconciliation=True` and `False`, demonstrating that the
  reconciliation is being read as performance.

Each test carries a docstring naming the finding, the expected post-fix
behaviour, and the story that will change it — the US-27 "documented defect"
convention.

Regression / guardrail:
- `dashboardGoldens.ts` **byte-identical** (AC5).
- Full `run_all_tests.py` + tsc + dead-code gate green.

## Notes / decisions

- **Why this pre-empted US-24.9:** US-24.9 would change the return-series basis
  on precisely the path F-1..F-3 corrupt. Its payoff (~3% cash de-dilution) is
  an order of magnitude smaller than the artifact it would sit on top of (+79%
  volatility inflation), and shipping it first would have regenerated goldens
  around a fabricated number. Fix order matters; this is recorded so the
  deferral of US-24.9 reads as a decision, not an oversight.
- **Why a new epic rather than a tech-debt row:** the register is for
  improvements. F-1..F-3 are correctness defects on the truth-class the product
  presents as broker truth — the same weight as Epic 27 / Epic 30, and they
  need a findings table plus staged fixes, which is what an epic provides.
- **Severity honesty:** F-1/F-2 are marked Critical on the *engine series*. The
  user-facing severity depends on the impact map (AC3) still being completed —
  the audit must not overstate what is on screen before that is known.
