# US-21.2: Shared test-fixtures module

**Epic:** Epic 21 — Testing Strategy & Architecture Hardening
**PRD:** [`epic-21-testing-strategy-hardening.md`](../prd/epic-21-testing-strategy-hardening.md)
**Status:** Done
**Last updated:** 2026-06-10

## Story

As a **developer of this project**, I want one canonical test-fixtures module
for snapshot payloads and market-data mocks, so that new engine tests stop
re-implementing the `ImportedPortfolioSnapshot` shape (the recurring 422
gotcha) and per-file mock installers, and US-21.3's property test has a
standard portfolio to drive every route with.

## Context

Snapshot builders are re-implemented in `test_correlation_engine.py`,
`test_intra_correlation_engine.py`, and `test_provenance_engine.py` (dict-based,
near-identical), and each of those files also hand-rolls its own
`MarketDataService` mock installer. The `ImportedPortfolioSnapshot` 422-shape
gotcha is documented in two skills precisely because every new file re-trips it.
This story extracts the canonical builders into `app/tests/fixtures.py`
(requires adding `app/tests/__init__.py` so tests can import it), migrates the
three dict-based files to consume it, and points the write-tests skill at it.

Implementer must read:
- the three files' `_snapshot`/`_position`/installer helpers (the union of their
  needs defines the fixtures API)
- `app/tests/conftest.py` — `_mock_price_rows` / `_mock_prices_for_symbols`
  (fixtures may build on, but must not duplicate, these)

## Notes / decisions

- `app/tests/__init__.py` makes the directory a package so
  `from app.tests.fixtures import …` works under pytest's rootdir imports —
  the same mechanism the tests already use for `from app.api.main import app`.
- The installer takes the **target module path** ("app.services.intra_correlation_engine")
  because every engine imports `MarketDataService` at module load — patching the
  source module wouldn't take effect (documented gotcha).
- No financial formula; no academic citation.
