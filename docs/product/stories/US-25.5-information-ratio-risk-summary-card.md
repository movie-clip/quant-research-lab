# US-25.5: Information Ratio on the Risk Summary card

**Epic:** Epic 25 — Dashboard Performance & Risk Summary
**PRD:** [`epic-25-dashboard-performance-risk-summary.md`](../prd/epic-25-dashboard-performance-risk-summary.md)
**Status:** Done
**Last updated:** 2026-07-04

## Story

As a **portfolio researcher**, I want **to see my Information Ratio next to
tracking error on the Risk Summary card**, so that **I can judge whether my
active risk-taking versus the benchmark actually paid off, not just how much
of it there was**.

## Context

A project-wide review found `RelativeRiskSummary.information_ratio` (and its
sibling `active_return_pct`) is **already fully computed** in
`services/quant-engine/app/analytics/risk.py`, already flows into
`DiagnosticsResult.relative_risk`, and is already contract-documented in
`docs/contracts/diagnostics-fields.md` — but had no methodology section
(added by this research pass — see `financial-methodology.md`
§Information Ratio) and is rendered nowhere in the UI. This is the same
"computed but never surfaced" pattern Epic 25 (US-25.1–25.3) found and fixed
for the rest of the Dashboard tab.

`RiskSummaryCard.tsx` (US-25.3) already receives the full
`diagnosticsAnalysis: DiagnosticsEngineResponse` prop and already reads
`diagnosticsAnalysis.volatility_summary.tracking_error_pct` — this story adds
two more fields from the same already-fetched object
(`diagnosticsAnalysis.relative_risk.information_ratio` and
`.active_return_pct`), no new fetch, no new prop.

Read before implementing:
- `docs/finance/financial-methodology.md` §Information Ratio (new — read the
  distinction it draws between `active_return_pct` (compounded, whole-window)
  and the IR's own annualized-mean-daily numerator; do not conflate them in
  a UI label)
- `docs/contracts/diagnostics-fields.md` "Benchmark-relative refusal rule"
  (`relative_risk.information_ratio`/`active_return_pct` may be `null` even
  when `availability.status = ok` — investor-economics refusal, not a
  generic unavailable)

## Acceptance criteria

- [x] AC1 — The Risk Summary card shows Information Ratio and Active Return
      from `diagnosticsAnalysis.relative_risk.{information_ratio,active_return_pct}`,
      each `n/a` when its field is `null`.
- [x] AC2 — Active Return is labeled and formatted distinctly from Time-
      Weighted Return / Money-Weighted Return on the Performance card
      (US-25.1) — it is a benchmark-relative compounded figure, not a
      portfolio-only return; the label must not imply they are the same
      number.
- [x] AC3 — When `relative_risk` itself or both its ratio fields are `null`
      (investor-economics refusal per the contract rule, or insufficient
      paired-return history), the two new rows do not render as `n/a` inside
      an otherwise-populated card if the *whole* card is already showing its
      EmptyState (US-25.3's existing unavailable path) — i.e. this story
      does not introduce a second, inconsistent unavailable state.
- [x] AC4 — Information Ratio and Active Return never render when
      `tracking_error_pct` itself is `null`/unavailable in the same response
      (they are mathematically dependent — a coherence check, not a new
      trust rule).

## Out of scope

- No new backend field, engine, or route — `information_ratio` and
  `active_return_pct` are already computed and already in the schema/TS
  types.
- No rolling/windowed Information Ratio (the existing computation is
  full-history, matching `tracking_error_pct`'s own scope) — a rolling IR
  time series would be new scope for a future story if wanted.
- No Sharpe ratio, Sortino ratio, or risk-free-rate-based metric — those
  require a risk-free-rate data source this project does not have; separate
  research item if pursued.
