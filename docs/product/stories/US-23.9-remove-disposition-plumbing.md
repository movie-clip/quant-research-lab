# US-23.9: Remove the unused disposition plumbing (cross-seam)

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Next phase
**Last updated:** 2026-06-17

## Story

As a **developer of this project**, I want the never-used Import Admission
Review **disposition** plumbing removed across the FE persistence layer and the
BE schema, so that the codebase stops carrying a ~250-line subsystem with no
producer and no consumer — without weakening workspace persistence.

## Context

The `ImportAdmissionReviewDispositionV1` subsystem (accept-known-exception /
needs-source-correction / deferred review metadata) was built but **never wired
to any UI producer or consumer** (established in the US-22.2 close-out, which
closed the disposition *workflow* as not-needed). US-23.5 confirmed it's dead
across the seam; US-23.4 carved it out here because it is a large,
persistence-touching change that must be done as its own focused, well-verified
slice — **not** mixed into the file/type sweep.

This story is **carved out of US-23.4** specifically so the removal can be gated
by the workspace save/load round-trip tests (persistence stability is the
priority). The complete, verified removal map already lives in
[`docs/tech-debt-register.md`](../../tech-debt-register.md) → "⚑ Ready-to-execute:
disposition-plumbing removal" — follow it.

Implementer must read:
- `docs/tech-debt-register.md` — the closed removal set + persisted-state safety note.
- `apps/desktop/src/app/portfolioWorkspaceStorage.ts` — the disposition save fn,
  the 8 sanitize/canonicalize/match helpers, the fingerprint subsystem
  (disposition-only, confirmed no production users), and the
  `admissionReviewDispositions` field handling.
- `apps/desktop/src/app/portfolioWorkspaceStorage.test.ts` — the ~14 disposition/
  fingerprint test blocks to remove (keep the non-disposition round-trip tests).
- `app/schemas/import_bootstrap.py` — the BE `ImportAdmissionReviewDispositionV1`
  + `ImportAdmissionReviewEvidenceSummaryV1` + `ImportAdmissionReviewDisposition`
  enum (+ `test_import_admission.py` refs).

  `ImportAdmissionReviewEvidenceSummaryV1`, and `ImportAdmissionReviewDisposition`

  unchanged; only disposition-specific tests are removed (with reference). Full

## Notes / decisions

- **Why a dedicated slice:** the removal is ~250 lines across the persistence
  layer + a 726-line test file + the BE schema. Done alone, gated by the
  round-trip tests, it stays low-risk; mixed into the bulk sweep it would put
  workspace persistence at risk. (Carved out of US-23.4 per the 2026-06-17
  decision.)
- **The fingerprint subsystem is disposition-only** (`buildImportSnapshotFingerprint`
  / `buildImportAdmissionSummaryFingerprint` / `buildDeterministicImportAdmissionFingerprint`
  / `canonicalizeForFingerprint`) — verified no production users (only the
  disposition save + the test). Remove with the subsystem.
- No financial formula; no methodology change.
