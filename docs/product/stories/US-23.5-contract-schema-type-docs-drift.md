# US-23.5: Contract & schema↔type↔docs drift reconciliation

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Done
**Last updated:** 2026-06-12

## Story

As a **developer of this project**, I want the cross-seam contracts (backend
Pydantic schemas ↔ desktop TS types ↔ `docs/contracts/*`) audited for drift, so
that the dead-code sweeps in US-23.2/23.3/23.4 can delete a schema field or type
without leaving a dangling mirror or a lying contract doc.

## Context

The project's discipline is "types mirror backend schemas exactly; update the
matching `docs/contracts/<area>-fields.md` in the same pass." Over 22 epics,
drift accumulates: a TS field with no backend source (or vice-versa), a contract
row for a field that was renamed/removed, a nullability mismatch. This story is
the **map** the deletion stories rely on — it inventories each seam, flags
defined-but-unused fields and three-way mismatches, and reconciles them (or
records a deliberate deferral). Sequenced **early** in the epic so US-23.2–23.4
delete against a known contract.

Implementer must read:
- `docs/contracts/*.md` (the field inventory docs).
- `app/schemas/*` (Pydantic source of truth) +
  `apps/desktop/src/features/portfolio/types.ts` (TS mirror).
- `CLAUDE.md` conventions (schemas-first; types mirror exactly).

## Acceptance criteria

- [x] AC1 — A drift inventory is produced: for each `docs/contracts/<area>.md`,
  every documented field is matched to its Pydantic field and its TS type; the
  audit lists (a) backend fields with no TS mirror, (b) TS fields with no backend
  source, (c) contract rows for non-existent fields, (d) type/nullability
  mismatches. Recorded in `docs/tech-debt-register.md` (area = `contracts`).
- [x] AC2 — **Satisfied vacuously — the audit found no drift to fix.** Every
  CamelCase identifier referenced in the contract docs resolves to a live schema
  class, a live TS type, or a UI-component/prose word in a "UI display" column;
  no stale contract rows, no dangling documented types, no backend field missing
  a mirror. (The only mismatches are FE-dead types with no backend source/no
  consumer — flagged to US-23.4, not drift.) No reconciliation edits were
  required; `tsc` + suite stay green.
- [x] AC3 — A field that is **defined-but-unused on both sides** (dead across the
  seam) is flagged for removal and the owning sweep story (US-23.2/23.3/23.4) is
  named, so the deletion happens once, coherently — not half-removed here.
- [x] AC4 — **No behaviour change**: full `python scripts/run_all_tests.py` green;
  `npx tsc --noEmit` clean; goldens untouched. Reconciling a contract doc or
  removing a provably-dead-both-sides field does not alter any response or render.
- [x] AC5 — The contract docs are left **accurate**: after this story, each
  `docs/contracts/<area>.md` matches the actual schema + TS type (or carries an
  explicit, dated deferral note for anything intentionally left).

## Test plan

Backend + Frontend:
- Full suites green after each reconciliation; `npx tsc --noEmit` clean (the main
  gate for TS-mirror changes).
- Round-trip / route tests that assert response shapes stay green (proof a
  reconciled field was genuinely unused).

Regression / guardrail:
- No schema field removed here unless dead on **both** sides AND its owning sweep
  story removes the implementation; otherwise only docs/types are reconciled.
- Goldens untouched.

## Out of scope

- **Deleting the backend implementation** of a dead-both-sides field — that is
  the owning sweep story (this story flags + names it).
- **Changing a live field's type/shape** — a real contract change, not drift
  cleanup; record it for Epic 24.
- **Fixing catalogued smells** — Epic 24.
