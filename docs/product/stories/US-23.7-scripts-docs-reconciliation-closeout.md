# US-23.7: Scripts, tooling & docs reconciliation + epic close-out

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Next phase
**Last updated:** 2026-06-12

## Story

As a **developer of this project**, I want `scripts/` swept of dead code and the
project docs reconciled with the now-leaner codebase, then the tech-debt
register consolidated into seeds for a follow-up improvement epic — so that
Epic 23 closes with accurate docs and a ready-to-build improvement backlog.

## Context

This is the closing story. After US-23.1–23.6 have removed dead code across the
project and populated `docs/tech-debt-register.md`, this story: sweeps `scripts/`
(dev/runner/cache/statement-refresh/golden tooling) for dead code; reconciles
the canonical docs (`current-product-state.md`, `system-architecture.md`,
`epic-roadmap.md`, the contract docs) so they describe only what now ships; and
consolidates the register into a prioritized list that seeds **Epic 24 — Codebase
Improvement** (the epic that actually *fixes* the catalogued hardcodes/
anti-patterns).

Implementer must read:
- `docs/tech-debt-register.md` (populated by US-23.2–23.6).
- `scripts/*` + the detection tooling from US-23.1.
- `docs/product/current-product-state.md` + `docs/architecture/system-architecture.md`.

## Acceptance criteria

- [ ] AC1 — `scripts/` dead code is removed under the protocol (watch for
  entry-point scripts invoked only from docs/CLI — those are *live* even with no
  importer); the detection tooling runs clean for `scripts/` (or reasoned
  allowlist).
- [ ] AC2 — The canonical docs are reconciled with the leaner codebase: any
  reference to a removed module/component/field/route in
  `current-product-state.md`, `system-architecture.md`, the contract docs, and
  the architecture/testing docs is removed or corrected.
- [ ] AC3 — `docs/tech-debt-register.md` is **consolidated**: deduplicated,
  prioritized (severity × effort), and grouped by area — a coherent backlog, not
  a raw dump.
- [ ] AC4 — A PRD seed for **Epic 24 — Codebase Improvement** is drafted
  (`docs/product/prd/epic-24-*.md`) whose story list is derived from the
  register's high/medium-severity entries (hardcode removal, magic-number
  extraction, anti-pattern fixes). Epic 24 stays `Backlog` — not built here.
- [ ] AC5 — **No behaviour change**: full `python scripts/run_all_tests.py`
  green; `npx tsc --noEmit` clean; goldens untouched. Epic 23's net effect is a
  leaner tree + accurate docs + a ready improvement backlog, with the suite green
  throughout.
- [ ] AC6 — The substantive cleanup is reconciled: `epic-roadmap.md` slice log
  updated with total removal counts (symbols/files/lines) across US-23.1–23.7;
  the tech-debt register is consolidated and the Epic 24 seed drafted. The
  **enforcement gate (US-23.8) is the epic's tail** and performs the final
  Epic 23 → Completed flip — this story does not close the epic.

## Out of scope

- **Building Epic 24 / fixing any catalogued smell** — Epic 24 owns the fixes;
  this story only seeds it.
- **Removing a script invoked only via CLI/docs** — those are live entry points,
  not dead code.

## Notes / decisions

- **Entry-point scripts have no importer by design** — `run_dev.py`,
  `run_all_tests.py`, `refresh_statement.py`, `manage_cache.py` are invoked from
  the shell, so "no static reference" does NOT make them dead. Confirm via the
  documented CLI surface before touching any script.
- The register → Epic 24 hand-off is the whole point of cataloguing during the
  sweep: cleanup (delete) and improvement (refactor) stay separate epics so each
  diff is low-risk and reviewable.
- No new formula; no methodology change.
