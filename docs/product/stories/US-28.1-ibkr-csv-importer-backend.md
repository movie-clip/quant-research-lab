# US-28.1: IBKR Activity-Statement CSV importer (backend)

**Epic:** Epic 28 — IBKR CSV Importer & Statement-Refresh Resilience
**PRD:** [`epic-28-ibkr-csv-importer.md`](../prd/epic-28-ibkr-csv-importer.md)
**Status:** Backlog
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher**, I want to import my broker's CSV Activity
Statement export directly, so that my imports parse a machine-readable data
format instead of a regex reconstruction of a PDF layout.

## Context

New module `app/importers/interactive_brokers_csv.py` (a new format is a new
importer file, mirroring the freedom24/espp/interactive_brokers split), plus
a shared `preview`/`import_statement(path)` entry-point pair matching the
existing importer protocol. Target fixture: `docs/IB2026.csv` (committed with
the Epic 28 PRD; UTF-8 **BOM**, 887 lines, 22 sections — see the PRD "Facts"
section for the format gotchas: stdlib `csv` module mandatory, `--` missing
cells, quoted thousands separators, mid-file Header restatement in `Trades`,
`DataDiscriminator=Summary` position rows, per-currency positions).

Section → schema mapping (same `ImportedPortfolioSnapshot` contract as the
PDF path — schemas do NOT change shape):

| CSV section | Snapshot target |
|---|---|
| `Statement` (Period, WhenGenerated, BrokerName) | `ImportedStatement.statement_period` (normalized `YYYY-MM-DD - YYYY-MM-DD`), `detected_format="csv"` |
| `Account Information` (Account, Base Currency) | `statement.account_id`, `statement.base_currency` |
| `Net Asset Value` (Cash/Stock/Total rows + TWR header) | `statement_totals.{starting_nav,ending_nav,cash_total,stock_total,time_weighted_return_pct}` |
| `Change in NAV` | `statement_totals.{dividends_total,withholding_tax_total,interest_total,other_fees_total,commissions_total,deposits_total}` |
| `Open Positions` (`DataDiscriminator=Summary`) | `positions[]` (per-currency: quantity, cost_basis, close_price, market_value, unrealized_pnl, currency; `as_of_date` = period end) |
| `Trades` (`DataDiscriminator=Order`; Stocks) | `ledger_entries[]` BUY/SELL (quantity sign, T. Price, Proceeds, Comm/Fee) |
| `Deposits & Withdrawals` | ledger DEPOSIT/WITHDRAWAL (skip currency-summary `Total*` rows) |
| `Dividends` / `Withholding Tax` / `Fees` / `Interest` | ledger DIVIDEND / WITHHOLDING_TAX / FEE / INTEREST (skip `Total*` rows) |
| `Cash Report` | `cash_balances[]` (per-currency starting/ending; base-summary rows only) |
| `Financial Instrument Information` | `instruments[]` (symbol, description, ISIN from `Security ID`, listing exchange, type) |

Fail-safe discipline (US-24.4/24.8, methodology "Importer resilience rule"):
a malformed record is skipped and parsing continues — partial snapshot, never
a crash, never a zero-filled row; the totals gap surfaces through
reconciliation. FX: non-base cash/ledger amounts keep their own currency in
the schema fields that carry currency — the importer does not convert
(consistent with the PDF path; conversion policy is the engine's concern, see
US-27.8).

Implementer must read:
- `app/importers/freedom24.py` + `interactive_brokers.py` — the importer
  protocol (`preview_*`, `import_statement`, fail-safe per-record pattern,
  named format constants per US-24.4).
- `app/schemas/imports.py` — the exact snapshot contract (422-proof shape).
- `docs/finance/financial-methodology.md` — Importer resilience rule +
  statement reconciliation scoping rule (extend both for the CSV importer).
- `app/analytics/reconciliation.py` — `build_reconciliation_summary` (the
  imported snapshot must reconcile against its own totals).

## Acceptance criteria

- [ ] AC1 — `import_statement(docs/IB2026.csv)` returns a valid
  `ImportedPortfolioSnapshot`: account U8516450, base USD, period
  `2026-01-01 - 2026-06-30`, `detected_format="csv"`, statement totals
  matching the CSV's own `Change in NAV`/`Net Asset Value` values (starting
  52381.12, ending 63234.80, dividends 122.64, withholding −17.47, interest
  1.64, other fees −1.05, deposits 9963.00, TWR 1.250764 — at the schema's
  established rounding).
- [ ] AC2 — Positions are per-currency and complete: every
  `Open Positions,Data,Summary` row lands with quantity/cost basis/close
  price/market value/unrealized P/L and its own currency (EUR/GBP/USD rows
  from the fixture pinned); Σ market_value reconciles to the NAV stock total
  within the reconciliation tolerance.
- [ ] AC3 — Ledger entries cover BUY/SELL/DEPOSIT/WITHDRAWAL/DIVIDEND/
  WITHHOLDING_TAX/FEE/INTEREST with section-total rows excluded;
  `build_reconciliation_summary` passes for the dividends/withholding/
  interest/fees/deposits checks against the statement totals.
- [ ] AC4 — Instruments carry ISIN (`Security ID`), description, listing
  exchange, and type from `Financial Instrument Information`.
- [ ] AC5 — Fail-safe: a mutated fixture row (non-numeric quantity, malformed
  date, short row) degrades that record only — import succeeds, the record is
  absent, no exception, no fabricated zeros (regression tests per mutation).
- [ ] AC6 — BOM + quoting handled: file read as `utf-8-sig`, parsed with the
  stdlib `csv` reader; the quoted-thousands (`"1,069.8600"`) and `--` cells
  parse/skip correctly.
- [ ] AC7 — The PDF importer path is untouched (its tests pass unmodified);
  the new module carries named format constants (no magic offsets/strings
  inline) per the US-24.4 convention.
