# US-17.1: Pairwise correlation matrix engine + heatmap

**Epic:** Epic 17 — Intra-Portfolio Correlation
**PRD:** [`epic-17-intra-portfolio-correlation.md`](../prd/epic-17-intra-portfolio-correlation.md)
**Status:** Done
**Last updated:** 2026-06-05

## Story

As a **portfolio researcher**, I want a holdings × holdings correlation heatmap
on the Exposure tab, so that I can see which of my own positions move together —
and therefore how much real diversification my position count actually buys me.

## Context

The Exposure tab shows how the portfolio co-moves with *external* benchmarks
(Benchmark Correlation card + rolling correlation chart) but nothing about how
the portfolio's *own holdings* co-move with each other. This story adds a
full-stack **Intra-Portfolio Correlation** card: a symmetric pairwise Pearson
correlation matrix over a selectable 20d/60d/252d window, plus an average
pairwise correlation and the most/least-correlated holding pair.

The methodology is already written (research phase). It reuses the existing
synthetic-history machinery — the same per-symbol return construction
`correlation_engine.py` already performs — and the existing `pearson()` helper.
**No new market-data provider, no new FMP calls beyond the price history the
correlation engine already fetches.**

## Acceptance criteria

- [x] AC1 — An `IntraCorrelationHeatmap` card is visible on the Exposure tab when
  a portfolio with ≥ 2 priceable holdings (each with sufficient history) is
  loaded. It renders inside a `CardShell` (`role="region"` + `aria-labelledby`)
  using the Epic 12 design system — no raw hex / px in inline styles (the
  `designSystem.audit.test.ts` contract holds, with the new file added to the
  audited set).
- [x] AC2 — The card renders a square heatmap whose rows and columns are the
  portfolio's priceable holdings (by symbol), ordered by current weight
  descending, capped at the top **15** holdings by weight for readability.
- [x] AC3 — Each cell shows the pairwise Pearson ρ for that row/column pair,
  computed by the engine over the selected window. The **numeric ρ value is
  printed in every cell** (2 decimals) — color is never the sole encoder. A
  sign glyph (▲ positive / ▼ negative / • ≈0) accompanies the value, and the
  cell background uses the existing `--color-corr-*` palette tokens
  (strong-positive → neutral → strong-negative).
- [x] AC4 — The diagonal (a holding with itself) is always exactly `1.00` and is
  visually de-emphasised (muted) to distinguish it from computed off-diagonal
  cells.
- [x] AC5 — A pair with fewer than the minimum overlapping daily returns (20),
  or with a zero-variance series, renders as an explicit **"n/a"** cell (neutral
  styling) — never `0`, never a fabricated value. The engine returns `null` for
  that cell.
- [x] AC6 — A window selector (20d / 60d / 252d, default 60) is visible and uses
  the shared `WindowSelector` primitive (aria-pressed, `:focus-visible`
  outline); changing it re-fetches and re-renders the matrix and the summary
  callouts.
- [x] AC7 — A summary strip shows the **average pairwise correlation** (mean of
  the off-diagonal non-null pairs, 2 decimals) and the **most-correlated** and
  **least-correlated** holding pairs (each as `SYM_A · SYM_B  ρ`). When no valid
  pair exists, each reads an explicit unavailable label, never `0`.
- [x] AC8 — Holdings excluded from the matrix because they have no fetchable /
  insufficient price history are disclosed (e.g. a caption "N holdings excluded:
  insufficient history"), so the matrix is never silently incomplete. Cash and
  non-priceable instruments are excluded from the priceable universe and are not
  disclosed as excluded (they are out of scope by construction).
- [x] AC9 — A `Synthetic` `TrustBadge` is shown on the card header with tooltip:
  `"Pairwise correlations are computed from current holdings applied to historical prices. Not verified broker return basis."`
  Every response value carries `synthetic` trust; no value is ever `verified`.
- [x] AC10 — When fewer than 2 priceable holdings have sufficient history, the
  engine returns top-level `trust='unavailable'` and the card renders an
  `EmptyState` (`"Not enough priceable holdings for a correlation matrix."`) —
  never a blank or zeroed grid. Loading and error states render via
  `LoadingState` / `ErrorState`.
- [x] AC11 — `npx tsc --noEmit` is clean; `python scripts/run_all_tests.py` is
  green including the new tests; the design-system audit stays green; existing
  `correlation.py` analytics tests and the multi-benchmark engine/route tests

## Out of scope

- **Diversification Ratio and Effective Number of Bets** — these are US-17.2
  (ENB introduces numpy). Do not implement them here.
- No rolling time-series of the matrix (point-in-time for the selected window only).
- No clustering, dendrogram, or PCA factor extraction.
- No partial/imputed correlations — a sub-threshold pair is `null`, full stop.
- No optimizer, target weights, or rebalancing suggestion (no-execution guardrail).
- No change to the existing Benchmark Correlation card — this is additive.

## Notes / decisions

- **Reuse, don't duplicate**: the pairwise matrix is built from the same
  per-symbol return series the multi-benchmark engine already constructs; the
  only new analytics are the matrix assembler and the off-diagonal mean. Both
  reuse `pearson()`. Frontend stays thin — it formats/colors engine-computed ρ
  values, never computes a correlation.
- **Top-N cap**: the matrix is capped to the top 15 holdings by weight to keep
  the heatmap legible; `max_holdings` is a request field so it is testable and
  tunable. Holdings beyond the cap are not "excluded for missing history" — the
  excluded-caption (AC8) is specifically for no-history symbols, distinct from
  the legibility cap.
- **Color-blind safety**: per the Epic 12 baseline, the heatmap pairs the
  `--color-corr-*` background with a printed numeric ρ + sign glyph in every
  cell, mirroring the `BenchmarkCorrelationTable` ▲/▼ convention. Color is never
  the sole encoder.
- **Trust**: top-level `trust='unavailable'` only when < 2 priceable holdings
  have sufficient history; otherwise `synthetic`. A `null` matrix cell denotes an
  unavailable *pair* (sub-threshold overlap or zero variance) and renders "n/a".
  The diagonal is always exactly 1.0 and is outside the trust ladder.
- **Academic precedent** (already in methodology §Intra-Portfolio Correlation):
  Markowitz (1952) for the diversification rationale; pairwise Pearson follows
  the same definition as §Multi-Benchmark Correlation. (Choueifaty & Coignard
  2008 and Meucci 2009 are cited for US-17.2, not this story.)
- **Research brief**: see the Epic 17 PRD + the methodology §Intra-Portfolio
  Correlation section authored in the research phase.
