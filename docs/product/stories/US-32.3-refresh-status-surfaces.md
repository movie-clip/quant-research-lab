# US-32.3: Refresh the status surfaces so "where are we?" is answerable

**Epic:** Epic 32 — Project Hygiene & Agent-Facing Doc Accuracy
**PRD:** [`epic-32-project-hygiene-and-agent-docs.md`](../prd/epic-32-project-hygiene-and-agent-docs.md)
**Status:** Next phase
**Last updated:** 2026-08-12

## Story

As a **developer or agent returning to this project**, I want the first
paragraph of the roadmap and the pointers in CLAUDE.md to describe the project
as it is today, so that I can answer "what's open, what shipped last?" without
reading a 900-line slice log to discover the summary was wrong.

## Context

PRD findings **F-1, F-2, F-6, F-7, F-8** — all status text, no code.

**F-1.** `epic-roadmap.md` line 3 is the "living execution snapshot", the first
thing any reader sees. It currently says Epic 31 is **active** with
"F-1..F-3 open" and Epic 24 is **active**. Both closed. Epic 26 — the most
recently shipped epic — is not mentioned at all. Every epic is now Completed.

**F-2.** CLAUDE.md names **Epic 13** as "the most-recent shipped epic PRD" in
two places: the doc map, and the "what's the scope of this epic" guidance.
Epic 13 is thirteen epics behind.

**F-6.** `current-product-state.md`'s header reads *"Updated: 2026-07-04 (after
Epic 25)"* though it has been updated for Epics 30, 31, 24 and 26 since.

**F-7.** `US-8.4-strip-app-state.md` records its status as a `## Status`
section rather than the `**Status:**` header field every other story uses, so a
sweep across `docs/product/stories/` reports it as statusless. It is Done
(2026-05-25) and the index agrees — this is format, not substance.

**F-8.** `build-story`'s close-out instructs "commit … squash-merge … open PR"
unconditionally, which conflicts with the harness rule to commit and push only
when the user asks. Deferred from 2026-06-19; a wording fix.

Implementer must read: `docs/product/epic-roadmap.md` (line 3 + the epic
headers); `CLAUDE.md` (doc map, "When in doubt" section);
`docs/product/current-product-state.md` (header);
`docs/product/stories/US-8.4-strip-app-state.md`;
`.claude/skills/build-story/SKILL.md` (Closing out).

## Notes / decisions

- **AC3 is the part that matters beyond this cleanup.** Pointing CLAUDE.md at
  "Epic 26" simply re-creates the F-2 problem one epic later. The pointer
  should name the roadmap as the authority and treat any specific epic as an
  example, so the next reader who finds it stale knows immediately where the
  truth lives.
- **Why F-7 is worth the one-line fix** despite being cosmetic: it is exactly
  what made the end-of-cycle sweep for this epic noisy — a story that is
  genuinely Done reported as statusless. Small, but it costs a false positive
  every time anyone audits story state.
- No formula or methodology change; no academic citation required.
