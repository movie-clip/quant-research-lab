# US-34.5: Publish the benchmark and excess return on a stated basis

**Epic:** Epic 34 — An Answerable Dashboard: Reachable Trust States
**PRD:** [`epic-34-answerable-dashboard-and-reachable-trust.md`](../prd/epic-34-answerable-dashboard-and-reachable-trust.md)
**Status:** Done (2026-08-17)
**Last updated:** 2026-08-17

## Unparking note (2026-08-17)

**The owner made the F-10 decision that this story was parked on**, in two
parts: *retire the anti-derivation rule* (for the benchmark leg), and scope the
unlock to *benchmark + excess only*. The parked implementation was re-applied,
and the ~15 policy tests were restated on substance rather than blanket-updated.

**The evidence that decided it.** The response already publishes the benchmark
prices these figures are computed from — 148 dated points, twice over
(`benchmark.points` and `performance_series[].benchmark_price`) — alongside 148
portfolio values and, since US-34.2, the portfolio return chain. Every withheld
figure was therefore *already derivable by a reader with a spreadsheet*. The
rule removed the **label**, not the information. And the unlabelled version is
the more dangerous one: a researcher who computes the benchmark return
themselves gets no basis marker, so a **price** return reads as a **total**
return. Publishing it labelled is strictly safer than the silence it replaced.

**What was NOT unlocked.** The daily benchmark return chain
(`benchmark_relative_series`) stays withheld — the chart indexes prices itself,
so publishing the chain buys nothing (the AC2 overreach the parking note already
caught). `drawdown_family` stays withheld. The verified-total-return rung is
untouched. `investor_economics_status` still reads `withheld`, and the basis
contract still reads `price_return_only`: **published is not promoted**, and a
test asserts exactly that pairing.

**A latent bug was found while retiring the rule.** The old gate read
`benchmark_basis == "verified_total_return" AND slice_is_admitted`. Replacing
the first clause alone would have left the fallback `slice_is_admitted` able to
publish an **`unverified_adjusted_proxy`** return whenever the *portfolio's*
slice happened to be admitted — one leg's proof status standing in as evidence
about the other leg's data. The gate is now the basis and nothing else.

**The deeper failure the parking note flagged was real and was answered.**
`test_build_true_performance_series_refuses_compounded_..._for_price_only_basis`
asserts a methodology claim, not a policy one. Its **portfolio** half is
unchanged and still refuses; its **benchmark** half now publishes, because
compounding a price-return chain yields a price return — a real measurement that
is simply not a total return, which is what the basis label says.

**Two dead helpers went with the rule**
(`_allow_future_exact_slice_excess_return_output`,
`_compute_future_exact_slice_excess_return_pct`) along with the four unit tests
that existed only to test them. The one piece of substance in those tests — an
excess needs *both* published legs, and a missing leg must never be read as zero
— is now asserted against the engine itself.

## Parking note (2026-08-13, superseded by the above)

**Implemented, measured, and then parked without shipping.** The engine work
proved out — on the committed statement it publishes SPY **+11.75%** and an
excess of **−11.21pp** — but landing it requires rewriting ~15 investor-economics
policy tests, and that policy is a deliberate design this story has no mandate
to overturn. The code was reverted; only the findings are kept.

**What blocked it.** `investor_economics_partial_unlock` declares
`client_derivation_rule = server_side_scalar_only_no_daily_series_subtraction_equivalence`,
and `withheld_families` names `benchmark_relative_series`,
`benchmark_relative_path_derived_outputs` and `rebucketed_window_summaries`.
US-34.2 already publishes the portfolio TWR **per range**, so publishing a
benchmark scalar per range makes those withheld families derivable by
subtraction. That is a real breach of a stated rule, not a stale assertion.

**Two scoping corrections were made before the block was understood**, both
worth keeping as evidence:

1. **AC2 was overreach.** It proposed publishing the daily benchmark return
   chain "so the chart's benchmark line carries returns". The chart never reads
   it — `buildIndexedSeries` indexes `portfolio_value` and `benchmark_price` to
   100 itself — so AC2 bought nothing visible while breaching the
   series-subtraction rule directly.

2. **"Full window only" does not shrink the test blast radius.** The owner chose
   it on the understanding that it would. It does not: the ~15 policy tests use
   2-point mocked fixtures where *every* range **is** the full window, so the
   rung fires and publishes there regardless of scoping. Same 18 failures either
   way. The premise that choice rested on was mine and it was wrong.

**One failure is deeper than scoping.**
`test_build_true_performance_series_refuses_compounded_portfolio_and_benchmark_returns_for_price_only_basis`
asserts the chain function itself must refuse to compound a price-return series.
That is a **methodology** claim — may a price-return chain be compounded at
all? — not a publication-policy one, and it contradicts this story's premise
directly rather than merely gating it.

**What unblocks this story:** a decision on what the investor-economics
withholding policy should be, now that F-1a and F-9 have shown both of its
verified rungs are unreachable in production. Until then the Dashboard's
benchmark comparison stays silent, and the reason is recorded rather than
latent.

The measured evidence, the F-9 finding and the AC set below are preserved so the
work does not need re-deriving.

## Story

As a **portfolio researcher**, I want to see how my portfolio did against its
benchmark, labelled with the basis the comparison rests on, so that the
Dashboard answers the question it exists to answer instead of drawing me a
benchmark line with no number beside it.

## Context

PRD finding **F-6**, and it is the last of the headline nulls US-34.2 left
behind.

148 SPY closes are fetched, returned to the client and drawn on the chart, and
`benchmark_return_pct` is `null` on every one of them. The number is trivially
computable from rows already in hand:

```text
SPY  689.51 (2026-01-08)  ->  770.56 (2026-08-11)   =  +11.75%
portfolio (All, replay_derived)                     =   +0.54%
excess                                              =  -11.21pp
```

A researcher currently cannot see that they trailed their benchmark by eleven
points. That is the single most decision-relevant fact on the tab.

**Four gates suppress it**, and none of them is about the data being
unavailable: `_withhold_benchmark_return_series` blanks the series
(`dashboard_history_engine.py:423`), `allow_return_pct=False` is hardcoded at
the `build_benchmark_comparison` call site (:661), that function additionally
requires `verified_total_return` (`benchmark_service.py:25`), and
`build_true_performance_series` computes the benchmark chain only on the same
verified basis.

### F-9 (Medium) — the verified-benchmark pilot is unreachable in production

Found while checking this story's premise. `_validate_verified_benchmark_slice`
admits a benchmark as `verified_total_return` only when every in-window row
carries `adjClose` **and** the fetch came from
`VERIFIED_BENCHMARK_ENDPOINT = "historical-price-eod/light"`.

The FMP client has exactly **one** history method,
`get_historical_price_light`, and **no `adjClose` handling anywhere** — the
light endpoint returns `symbol, date, price, volume`. All 148 committed rows
carry no `adjClose`.

So the two conditions cannot both hold against the real provider: the verified
path is unreachable by construction, exactly like the five structural
disqualifiers in F-1a. The tests that exercise it supply hand-written rows with
`adjClose`, which is why it has never been noticed.

**This story does not fix F-9** — sourcing adjusted closes needs a different FMP
endpoint, a client change and a `golden_market_data.json` re-capture. It is
recorded as its own story so the gap is visible rather than latent.

**Owner decision (2026-08-13): publish both, with the caveat quantified.** A
price return omits SPY's dividends — roughly **0.7%** over this 7-month window
at a ~1.2% trailing yield — so it **understates the benchmark and flatters the
portfolio**. That bias is knowable and directional, so it is stated as a number
rather than hidden or used as a reason for silence.

Implementer must read:
- PRD F-6, and F-9 above.
- `docs/finance/financial-methodology.md` §Publication rungs for the replayed
  return (US-34.2 established the pattern this story follows).
- `app/services/benchmark_service.py` and the four gates listed above.
- `docs/contracts/dashboard-fields.md` → `return_basis_contract.benchmark_path`.

## Acceptance criteria

- [ ] AC1 — **The benchmark return is published on whatever basis it has.**
  `BenchmarkComparison.return_pct` is computed whenever the basis is
  `verified_total_return` **or** `price_return_only`, and is `null` only when
  the basis is genuinely `unavailable`. On IB2026 it is **+11.75%** with basis
  `price_return_only`.

- [ ] AC2 — **The cumulative benchmark series is published too**, so the chart's
  benchmark line carries returns rather than raw prices: all 148 points gain a
  `benchmark_return_pct`, and `_withhold_benchmark_return_series` no longer
  blanks a series the basis supports.

- [ ] AC3 — **Every range publishes a benchmark return**, re-based to that
  range's own starting point exactly as US-34.2 does for the portfolio — not the
  since-inception figure repeated five times.

- [ ] AC4 — **The excess return is published, and is the difference of the two
  published figures.** On IB2026 the `All` window reports **−11.21pp**
  (0.54% − 11.75%), and a test asserts the identity rather than recomputing it
  independently, so the three numbers on screen can never disagree.

- [ ] AC5 — **The mixed basis is disclosed with its direction and size.** The
  Dashboard states that the benchmark is a price return, that it therefore
  excludes dividends, and that the excess is consequently **flattering to the
  portfolio by roughly the benchmark's dividend yield over the window**. A
  researcher must not be able to read −11.21pp as a dividend-inclusive
  comparison.

- [ ] AC6 — **Each figure carries its basis.** The benchmark return and excess
  return report `price_return_only` in `return_basis_contract.benchmark_path`,
  and the UI marks them, using the same vocabulary US-34.2 introduced for the
  portfolio path.

- [ ] AC7 — **The verified rung is untouched and still refuses.** With no
  `adjClose` on any row the basis stays `price_return_only`,
  `investor_economics_status` stays `withheld`, and nothing in this story can
  promote a benchmark to `verified_total_return`. A test pins all three.

- [ ] AC8 — **An unavailable benchmark still publishes nothing.** A run with no
  benchmark rows reports `return_pct: null`, basis `unavailable`, and null
  excess — the fail-closed path is intact and is not collapsed into "0%".

- [ ] AC9 — **The portfolio side is unchanged.** `time_weighted_return_pct`,
  the daily states, every valuation and the withheld-day set are byte-identical:
  this story publishes benchmark-derived figures only.

## Notes / decisions

- **No new formula.** A price return is `end/start − 1`, already implemented in
  `build_benchmark_comparison`; this story changes *when it may be published*.
  The methodology entry documents the mixed-basis comparison rule and its
  stated bias, not a new equation.
- **Why the excess is a subtraction, not an independent computation.** Deriving
  it separately invites the three displayed figures to disagree by rounding.
  AC4 makes it the difference of exactly the two published numbers.
- **The dividend bias is directional and must be stated as such.** A price
  return always understates a positive-yield benchmark, so the excess always
  flatters the portfolio. Roughly 0.7pp over this window at SPY's ~1.2% trailing
  yield — enough to matter for a close comparison even though it does not change
  the sign of −11.21pp here.
- **F-9 is the reason this story cannot simply "use adjClose".** Recording it
  properly is part of the story's value: a pilot that cannot fire in production
  is indistinguishable from one that has never been tried.
