# US-31.5: Convert each replayed holding by its fund currency, not the broker listing

**Epic:** Epic 31 — Ledger Replay Correctness
**PRD:** [`epic-31-ledger-replay-correctness.md`](../prd/epic-31-ledger-replay-correctness.md)
**Status:** Done
**Last updated:** 2026-07-25

## Story

As a **portfolio researcher** holding EUR- and GBP-denominated UCITS ETFs, I
want each holding's replayed market value converted to my base currency using
the currency its price is actually quoted in, so that my portfolio's historical
value reconciles to the broker statement instead of silently mixing currencies.

## Context

PRD finding **F-4 (High)**, verified 2026-07-24. The ledger replay carries
every position's market value **unconverted** — every replay call site passes
`fx_history={}`, so `PortfolioStateEngine.to_base_currency` records an FX
fallback (US-27.8) and returns the raw number. The obvious fix — convert by
`position.currency` (the broker's **listing** currency) using the statement's
own `fx_rates` — is **unsafe and was proven 4.3× worse** by the audit: the
provider's **quote** currency varies per resolved line and is not the listing
currency. `DEFS` is listed EUR but its resolved line `DEFS.L` quotes **USD**
(converting would double-count); `SXRV` is listed EUR and `SXRV.DE` quotes
**EUR** (conversion is required); `SEMI` (post-US-31.4) is listed GBP and
`SEMI.L` quotes **GBP** (conversion required).

**The reliable quote-currency source is the InstrumentRegistry `currency`**,
verified against the committed portfolio: for every priceable holding the
registry currency equals the observed quote basis (ratio ≈ 1 when it matches
the statement close, ≈ EURUSD/GBPUSD when the line quotes USD against a
non-USD-listed position) — **zero mismatches across 19 priced holdings**, incl.
the three that differ from `position.currency` (DEFS→USD, SXRV→EUR, SEMI→GBP).
The registry currency was hand-curated to the fund currency (US-24.2, US-18.3),
which is exactly the quote currency of the resolved line. The snapshot's own
`instruments[].currency` is `None` on the CSV path, so the engine must read the
registry.

This story wires two things together, both already precedented:
1. **Currency selection** — market-priced values use the **fund currency**
   (registry); statement-anchored values (US-30.2, e.g. `LQQ` with no fetchable
   history) stay in the **position currency**, because the anchor *is* the
   statement close, quoted in the broker's listing currency.
2. **Conversion** — a static per-date `fx_history` built from
   `statement_totals.fx_rates` (US-28.1 broker truth), exactly as
   `run_drift_engine` already does for the drift path (US-30.2).

After this story the IB2026 terminal replayed market value is **$61,239.88**
vs the statement's own `stock_total` **$61,238.53** — a **$1.35** residual
(0.002%), down from the pre-fix cross-currency mix. The remaining terminal
reconciliation gap is then almost entirely the F-2 cash plug (**US-31.3**).

Because this changes only how already-fetched values are **converted** — not
what is fetched — `golden_market_data.json` is **untouched** and no re-capture
(no `FMP_API_KEY`) is needed; only the computed `dashboardGoldens.ts`
regenerates.

- [x] AC1 — On the committed IB2026 portfolio replayed against the frozen
  fixture, each non-base holding's terminal market value is converted by its

  **$8,654.45**, `SEMI` 2,699.70 GBP → **$3,580.07**, `LQQ` 2,048.50 EUR →
  **$2,339.80** (statement-anchored, position currency), while `DEFS`
  (`DEFS.L` quotes USD) is **unchanged** — never double-converted. Pinned at
  exact values.
- [x] AC2 — The replayed terminal total market value reconciles to the
  statement's `stock_total`: **$61,239.88** vs **$61,238.53**, within a
  documented tolerance (≤ $2, i.e. < 0.01%). Pre-fix it was a currency-mixed
  sum. Regression-pinned.
- [x] AC3 — The conversion basis is the fund currency, never the broker
  listing currency: a unit test shows `DEFS` (listed EUR, fund USD) is **not**
  multiplied by EURUSD, and `SXRV` (listed EUR, fund EUR) **is** — the two are
  indistinguishable from `position.currency` alone, so the test pins that the
  engine reads the registry/fund currency.
- [x] AC4 — Statement-anchored holdings keep the position currency: `LQQ` (no
  fetchable history, valued flat at its statement close) is converted by
  **EURUSD** (its listing currency), because the anchor is the statement close
  — not the fund currency of a line that was never fetched.
- [x] AC5 — Trust/disclosure stays honest: currencies with a statement rate no
  longer appear in `run_metadata.fx_fallback_currencies` (they are genuinely
  converted now, not carried unconverted); a currency with **no** statement
  rate still lands in the fallback list and is carried unconverted (US-27.8
  behaviour preserved). A holding whose fund currency cannot be determined
  falls back to the position currency, never to a silent 1:1 base assumption.
- [x] AC6 — Behaviour is unchanged when no rates are supplied: with
  `statement_totals.fx_rates` absent, every value is carried unconverted and
  disclosed exactly as today (US-27.8), so a snapshot without implied rates is
  byte-identical to pre-story output.
- [x] AC7 — The goldens are regenerated **deliberately** (no `--capture`,
  `golden_market_data.json` byte-identical): the `dashboardGoldens.ts` diff is
  confined to the EUR/GBP holdings' converted `market_value`/`market_price` and
  the dependent `total_market_value`/`total_portfolio_value`/return series;
  every USD-quoted position series, plus statement-identity, ledger-count,
  weight, sector, cost-basis, ISIN and cash-by-currency families, are

## Notes / decisions

- **No new formula** — this applies the existing base-currency conversion
  (methodology §FX Conversion Fallback Disclosure / §Currency Exposure) to the
  replay path, choosing the currency correctly. No new citation required.
- **Why registry currency, not a captured provider currency:** the FMP light
  endpoint does not return a quote currency and the frozen fixture rows carry
  none, so capturing it would mean a price-row schema change + re-capture + an
  FMP gap to paper over. The registry already curates the fund currency and it
  matches the observed quote basis for every priced holding (0 mismatches).
  The story adds a guard test pinning that equivalence for the committed
  portfolio, so a future mis-curated currency is caught at golden-regen time.
- **Why anchored holdings use position currency:** a statement-anchored value
  (US-30.2) is the broker's own statement close, quoted in the position's
  listing currency — not the fund currency of a market line that was never
  fetched. `LQQ` is the live example (EUR listing, no registry entry, no
  history). The `symbol_currencies.get(symbol, position.currency)` fallback
  handles this naturally: `LQQ` is absent from the fund-currency map, so it
  uses EUR.
- **Fail-closed on unknown currency (AC5):** if neither a fund currency nor a
  usable rate is available, the value is carried unconverted and the currency
  disclosed (US-27.8) — never a silent 1:1 base assumption. This preserves the
  guardrail-#3 behaviour the drift/dashboard paths already have.
- **This is the last correctness fix before US-31.3.** After it, terminal MV
  reconciles to the statement (± $1.35), so US-31.3 can pin a fail-closed
  tolerance against a clean number — the sequencing US-31.2 established.
