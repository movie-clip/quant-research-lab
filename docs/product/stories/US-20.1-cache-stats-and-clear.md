# US-20.1: Cache stats + clear (route + UI)

**Epic:** Epic 20 — Market-Data Cache Efficiency & Control
**PRD:** [`epic-20-market-data-cache-efficiency.md`](../prd/epic-20-market-data-cache-efficiency.md)
**Status:** Done
**Last updated:** 2026-06-05

## Story

As a **portfolio researcher**, I want to see how much market-data is cached and
clear it from the app, so that I can force fresh data when needed and understand
my local cache footprint — without dropping to a CLI.

## Context

Today the market-data cache (FMP + Yahoo, one JSON file store) can only be
inspected/cleared via `scripts/manage_cache.py`; there is no backend `/cache`
route and no wired UI button. This story adds a read-only stats endpoint and a
clear endpoint, plus a small Cache control card on the Exposure tab. It is the
first slice of Epic 20 and also gives us the **stats surface** used to validate
the FMP-reduction work in US-20.2/20.3.

Implementer must read:
- `services/quant-engine/app/core/cache.py` — `JsonFileCache.list_entries()` and
  `clear(namespace)` (note: `clear(None)`/`clear("fmp")` removes **all** entries
  in the dir incl. `history_yf`; `clear("history")` removes only `history-*`)
- `services/quant-engine/app/core/settings.py` — `fmp_cache_dir`, `fmp_cache_enabled`
- `scripts/manage_cache.py` — existing CLI semantics to mirror
- `apps/desktop/src/features/portfolio/DataSourcesPanel.tsx` — adjacent data-infra
  card + self-fetch + design-system pattern (`.claude/skills/ui-polish`)

## Acceptance criteria

- [x] AC1 — `GET /cache/stats` returns the cache footprint: total entry count,
  a per-namespace breakdown (namespace + entry count), the cache directory path,
  and `enabled` (from `fmp_cache_enabled`). When the cache dir is empty it
  returns zero counts (not an error).
- [x] AC2 — `POST /cache/clear` removes cache files and returns the number
  removed. An optional `namespace` body field clears only that namespace; omitted/
  null clears **all** market-data cache (FMP + Yahoo). Mirrors `JsonFileCache.clear`.
- [x] AC3 — A "Market-data cache" card on the Exposure tab shows the stats
  (total entries + size/namespace breakdown) and a **Clear cache** button.
  Clicking it calls `POST /cache/clear`, then refreshes the stats so the card
  reflects the cleared state (count → 0).
- [x] AC4 — The clear action shows an in-flight state and a short confirmation
  (e.g. "Removed N cached files"); failures surface an error (not a blank/silent
  no-op). No fabricated counts.
- [x] AC5 — The card renders via the Epic 12 design system (CardShell + tokens;
  no hex/px; added to the design-system audit set); the button has an accessible
  label and a `:focus-visible` outline (reuse `WindowSelector`-style button or a
  tokened button).
- [x] AC6 — `npx tsc --noEmit` clean; backend + frontend suites green (only the
  known pre-existing FMP-offline failures remain); design-system audit green.

## Notes / decisions

- **Placement:** no Settings tab exists; the card lives on the Exposure tab next
  to the Data Sources panel (both data-infrastructure). Can move to a future
  Settings surface without API change.
- **Clear semantics:** default clears everything (FMP + Yahoo) — matches the
  CLI's `clear` / `clear fmp`. Per-namespace clear is supported by the API for
  future granularity; v1 UI button clears all.
- **Testability:** the service reads the cache dir from settings; tests point it
  at a `tmp_path` (construct `JsonFileCache(tmp_path)` directly, or override
  `get_settings`). No network.
- No new financial formula; no academic citation.
