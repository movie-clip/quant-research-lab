# US-12.2: Primitive components + refactor cards to use them

**Epic:** 12 — UI Polish & Design System
**PRD:** [`epic-12-ui-polish-design-system.md`](../prd/epic-12-ui-polish-design-system.md)
**Status:** Done
**Last updated:** 2026-05-28

## Story

As a **portfolio researcher**, I want every Exposure-tab feature card to share
a single set of reusable shell, badge, selector, and state-message components
— so that visual consistency is enforced by construction (not by hand-rolled
JSX in each card) and the next analytics card I ship plugs into the system
without re-inventing its header, badge, or empty state.

## Context

US-12.1 unified colors, spacing, and typography via tokens — but each card
still hand-rolls its `<header>` (title + Synthetic badge + window selector),
its empty / loading / error state JSX, and its window-selector button group.
The window-selector pattern in particular appears in three files
(RollingCorrelationChart, FactorAttributionCard, IndexedReturnChart inside
DriftBenchmarkPanel) with subtly different styling and DOM. A change to any
visual convention currently requires editing 4–5 files.

This story extracts that duplication into six primitive components under a
new `apps/desktop/src/app/primitives/` directory, then refactors the five
cards to consume them. The cards become visibly smaller; the next analytics
card pattern becomes: import primitives → assemble.

No backend, no analytics, no schema changes. No new user-visible behaviour
— pure refactor.

Implementer must read:

- `apps/desktop/src/features/portfolio/{DriftBenchmarkPanel,IndexedReturnChart,RollingCorrelationChart,FactorAttributionCard,BenchmarkCorrelationTable}.tsx`
  — to inventory the duplicated JSX that will move into primitives
- `apps/desktop/src/app/styles.css` — for the tokens the primitives will consume
- `apps/desktop/src/test/designSystem.audit.test.ts` — the US-12.1 audit
  that will need its `CARDS_WITH_BADGE` constant updated (badge moves out of
  the cards into TrustBadge.tsx)

## Notes / decisions

- **Where primitives live**: `apps/desktop/src/app/primitives/`, not
  `apps/desktop/src/features/portfolio/primitives/`. They're cross-cutting
  (any future feature can import them); they belong at the app shell
  layer, not the portfolio feature.
- **No barrel export**: import primitives by individual file path
  (`from '../../app/primitives/CardShell'`). Avoids accidental
  whole-directory imports + keeps tree-shaking simple. The audit test
  greps for these import strings.
- **Generic over option type for WindowSelector** is deliberate: the drift
  panel uses string labels (`'1m' | '3m' | '6m' | '12m' | 'since'`),
  the correlation chart uses numeric (`20 | 60 | 252`). A non-generic
  primitive would force one of them to stringify, losing type info.
- **No academic citation needed** — UI design story, no formula.
- **CardShell's `actions` slot is intentionally untyped `ReactNode`** to
  accept either a `<WindowSelector>` or a `<select>` (drift panel still
  uses a native `<select>` for benchmark choice — that's fine).
- **TrustBadge type list is closed at `'synthetic' | 'unavailable'`** for
  this story. Future work to wire `'verified' | 'degraded' | 'withheld'`
  is its own decision and likely needs new styles, not just a label
  change.
- **The opacity-via-`var()` constraint from US-12.1 still applies**: any
  numeric CSS prop (opacity, lineHeight) can't use `var()` in JSDOM. The
  state primitives don't use opacity for dimming, so this should not bite,
  but the implementer should remember it if tempted.
