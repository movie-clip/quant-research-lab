## Story statement

**As a** portfolio researcher who adds a second statement to my portfolio,
**I want** the Exposure tab's Import Admission Review to describe the combined
portfolio and never claim more than the weakest statement in it supports,
**so that** a verified label is never shown over a portfolio whose dominant
statement did not reach verified.

## Context

Closes finding F2 (tech-debt register row F2; `02-quant-audit.md` § Findings F2).
On add-statement the new node persists the admission of the added file only. IB
plus ESPP therefore shows "admitted / verified" over a portfolio that is 95.1% IB
holdings, and IB2026 alone is `degraded`. The multi-file first import already
recomputes admission on the combined snapshot, so the same two files get
different labels depending on which button was used.

Constraints carried from the research brief (`02-quant.md` § F2) and D-3, which
the tech lead must design within:

- The label rule is the weakest of (a) each input statement's own admission and
  (b) the admission recomputed on the combined snapshot, on the ladder
  verified > degraded > withheld > unavailable (decision: admitted > degraded >
  withheld). Recomputation alone is insufficient: offsetting per-account deltas
  (+x in one account, -x in another) net to a pass in summed totals and would let
  the combined label exceed a constituent.
- All input statements count, including a same-account statement that a later
  one supersedes, because a superseded statement still contributes ledger
  entries and flow totals to the combined snapshot. D-3 says "each statement's
  own admission"; this is the reading taken.
- Constituent evidence is kept alongside the roll-up, not collapsed into one
  label.
- The roll-up is engine logic (thin frontend): the frontend renders it and does
  not compute it. Where it lives and how it reaches the client is the design
  lane's.
- The same rule applies to the multi-file import path and the add-statement path.
- A combine that is refused has no combined portfolio and no combined label
  (US-46.1 AC 7).

The rule is not yet in the methodology doc; proposed edit E2 is applied by the
docs lane once this story ships (T-46.3.4), under guardrail 1.

Truth classes: admission is read-only evidence over Broker Truth. This story does
not change any single-statement admission rule and does not unlock a higher rung.

## Acceptance criteria

1. **IB plus ESPP.** After IB2026 is imported and ESPP2026 is added, the Import
   Admission Review shows decision `degraded` and trust `degraded`, not
   "admitted / verified".
2. **FF plus ESPP.** After FF2026 is imported and ESPP2026 is added, it shows
   `degraded` and `degraded`, not "admitted / verified". (FF2026 is 47.1% of this
   pair by value, ESPP2026 52.9%.)
3. **IB plus IB.** After IB2026 is imported and IB2026 is added again, it shows
   `degraded` and `degraded`.
4. **Reverse order.** ESPP2026 imported first and IB2026 added shows `degraded`
   and `degraded`.
5. **Path independence.** The same set of statements shows the same label whether
   it was built by the multi-file first import or by add-statement.
6. **Never above a constituent.** For a synthetic pair of statements whose
   position-check deltas offset (+x and -x), so that the combined snapshot on its
   own would pass, the combined label is no higher than `degraded`.
7. **Superseded statements count.** When a later statement supersedes an earlier
   one from the same account, the earlier statement's own admission still
   contributes to the combined label.
8. **Constituent evidence stays visible.** For a combined portfolio the review
   still shows each input statement's own label and checks, alongside the
   combined label.
9. **No rung is raised.** A combined multi-currency portfolio is never labelled
   above `degraded` by this story.
10. **Single statements unchanged.** IB2026 alone remains `degraded`, and ESPP2026
    alone remains admitted with trust `verified`.
11. **Refused combine has no label.** When adding a statement is refused, no
    combined admission is shown or saved.
12. **Label survives reload.** After the workspace is saved and reopened, a
    combined node shows the same combined label it showed before.
13. **Saved last-file-only label is recomputed on load (D-7).** A workspace saved
    by the old add-statement path with IB2026 then ESPP2026, which persisted
    "admitted / verified", shows decision `degraded` and trust `degraded` once
    opened.
14. **Recomputation on load uses the same rule.** A saved combined node reopened
    shows the label the D-3 rule gives for its input statements, the same label
    that adding those statements now would show, including the constituent labels
    of AC 8.
15. **A node that cannot be recomputed keeps no stale label.** When a saved combined
    node cannot be re-derived on load, its old persisted label is not presented as
    current, and the existing error disclosure is displayed.

## Test plan

Names the files and behaviours; individual test names and counts are the test
lane's to determine.

**Backend (pytest, `services/quant-engine/app/tests/`)**

- Admission tests alongside the existing `import_admission` coverage: the five
  fixture pairs (IB+IB, IB+ESPP, ESPP+IB, IB+FF, FF+ESPP) produce the labels in
  AC 1-4 and, for IB+FF, `degraded`.
- **A synthetic statement pair with offsetting position deltas** (+x / -x). The
  committed fixtures cannot tell the recompute-only rule from the weakest-of-both
  rule, because all five pairs agree under both (`02-quant.md` § F2 risks). Only
  this pair proves the constituent floor holds. It is the load-bearing regression
  test of the story.
- The superseded-statement case: same account twice, the earlier one weaker.
- The multi-file import and the add-statement combine produce the same label for
  the same inputs.
- A refused combine yields no combined admission.

**Frontend (vitest, `apps/desktop/src/`)**

- Exposure panel / `ImportAdmissionReviewCard` tests: the combined label and each
  constituent's label are rendered; the frontend does not derive the label itself.
- Persistence test (`app/portfolioWorkspaceStorage` coverage): a saved combined
  node reloads with the combined label.
- Persistence test on the pre-fix saved shape (D-7): a workspace fixture with an
  IB2026 + ESPP2026 combined node persisted as "admitted / verified" shows
  `degraded / degraded` after load, with constituent labels; a node that cannot be
  re-derived shows no stale label and the error disclosure.
- App-level add-statement test for IB2026 + ESPP2026 asserting `degraded /
  degraded` at the point the user reads it, not only at the function level.
