# US-22.1: Import Admission Review card

**Epic:** Epic 22 — Import Admission Review UI
**PRD:** [`epic-22-import-admission-review-ui.md`](../prd/epic-22-import-admission-review-ui.md)
**Status:** Done
**Last updated:** 2026-06-12

## Story

As a **portfolio researcher**, I want the Import Admission Review rendered as a
card on the Exposure tab — overall decision and trust level, plus every
individual check with its status, message, and evidence — so that I can see at
a glance whether the imported numbers are trustworthy and exactly which check
degraded or withheld trust, instead of that signal being computed and then
hidden.

## Context

`build_import_admission_summary` produces an `ImportAdmissionSummaryV1`
(`decision`: admitted/degraded/withheld; `trust_level`; a list of
`ImportAdmissionCheckV1` results — residual-cash, NAV, position-market-value,
symbol identity, instrument description-consistency, instrument ISIN
consistency). It is already returned on the import/analyze responses, mapped
into the desktop workspace state as `admissionSummary` (App.tsx ~line 803), and
persisted by `portfolioWorkspaceStorage`. **Nothing renders it** — only the
identity-mismatch slice reaches the screen, via the Data Sources panel's
provenance `identity_warnings`. This story adds a self-contained
`ImportAdmissionReviewCard` on the Exposure tab that renders the existing
`admissionSummary` state. Frontend-only: no backend, schema, route, or fetch
change — the data is already in state.

Implementer must read:
- `apps/desktop/src/features/portfolio/types.ts` — `ImportAdmissionSummaryV1`
  (already mirrors the backend `ImportAdmissionCheckV1` shape: `status`,
  `severity`, `trust_impact`, `message`, `observed`/`comparison`/`delta`/
  `currency`, `affected_fields`).
- `apps/desktop/src/app/App.tsx` — where `admissionSummary` is set into
  workspace state and where `<ExposurePanel … />` is rendered (the active
  source's summary must be threaded in as a prop).
- `apps/desktop/src/features/portfolio/ExposurePanel.tsx` +

## Acceptance criteria

- [x] AC1 — On the Exposure tab, after an import, an **Import Admission Review**
  card shows the overall `decision` (admitted / degraded / withheld) and the
  `trust_level` (verified / degraded / withheld / unavailable) as visible,
  design-system-styled badges — not raw enum text buried in a list.
- [x] AC2 — The card lists **every** check in `summary.checks`, each row showing
  its status (pass / warn / fail / unavailable), its human-readable `message`,
  and — when present — the `observed`/`comparison` label+value, the signed
  `delta` (with `currency` when given), and the `affected_fields`. No check is
  omitted and no `warn`/`fail`/`unavailable` is silently dropped (trust
  guardrail).
- [x] AC3 — Check status is conveyed by a design-system tone/badge (not colour
  alone): `pass` reads as OK, `warn` as caution, `fail`/`unavailable` as
  negative/withheld — consistent with how the existing Exposure cards surface
  trust. Status text is present for accessibility (not colour-only).
- [x] AC4 — When there is no admission summary for the active snapshot
  (`admissionSummary` is `null`/`undefined` — e.g. a pre-feature persisted
  workspace, or the draft node), the card renders an explicit unavailable/empty
  state ("Import Admission Review unavailable…"), never a fabricated "all clear"
  or a blank card.
- [x] AC5 — The card renders purely from persisted workspace state and survives
  a reload: re-opening a saved workspace shows the same review without re-import
  or re-fetch. No network call is made by the card.
- [x] AC6 — The existing Data Sources panel identity-warning line is unchanged
  (the identity slice is **not** relocated — the full review is additive); the
  design-system audit and `npx tsc --noEmit` stay green.

## Notes / decisions

- **Truth-class:** the admission summary is a *persisted-import* artifact (it
  describes the imported snapshot's integrity), distinct from snapshot analytics
  and synthetic history — the card must read it from the persisted
  `admissionSummary` state, never recompute or merge it with engine analytics
  (truth-class separation guardrail).
- **Why a presentational (not self-fetching) card:** unlike the attribution/
  correlation cards, the admission summary is not a per-snapshot engine call —
  it arrives with the import bootstrap and lives in workspace state. So this is
  a pure prop-driven component (no `useEffect` fetch, no adapter), which also
  satisfies AC5 (survives reload, no network).
- **Status→tone mapping (for the implementer):** `pass`→positive/ok,
  `warn`→caution, `fail`→negative, `unavailable`→withheld/neutral-disabled —
  reuse the existing trust tone tokens rather than inventing new ones.
- No new financial formula; no academic citation; methodology untouched.
