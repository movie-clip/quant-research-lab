# US-24.7: Name the unnamed financial tolerances, and delete the orphaned risk-contribution path the methodology cites

**Epic:** Epic 24 — Codebase Improvement
**PRD:** [`epic-24-codebase-improvement.md`](../prd/epic-24-codebase-improvement.md)
**Status:** Done
**Last updated:** 2026-08-09

## Story

As a **portfolio researcher**, I want the methodology doc to describe the code
that actually runs, and every financial tolerance to be a named number with a
stated rationale, so that "trace the metric to one formula and one code path"
is true rather than aspirational.

## Context

Tech-debt register row **US-24.7**, the epic's low-severity tail. Re-validated
item by item on 2026-08-09 (Epic 24 discipline). Two items are real, one is a
**guardrail violation** rather than debt, and three are scoping corrections.

### F-1 (the real finding) — the methodology cites a dead code path

`analytics/risk.py:596` `build_position_risk_contributions` (public) has **no
production caller**. The live Risk Summary surface uses the *private*
`_build_position_risk_contributions` (`:2056`, called from `:966`); the public
function is reached only from `test_analytics.py`. US-30.5b already noticed it
was "orphaned" and correctly applied its fix to the live path as well.

What makes this more than dead code: `financial-methodology.md:970` names
**`build_position_risk_contributions`** as the source of per-position
beta/correlation. So the canonical methodology document points a reader at a
function that never executes — a direct hit on guardrail #1 ("every UI metric
maps to one engine formula and **one code path**"). A reader auditing the
beta a card displays would read the wrong function.

It survives the dead-code gate because `vulture` sees the test callers. This is
the Epic 23 deletion class, surfaced late.

### F-2 — two unnamed financial tolerances

- `analytics/reconciliation.py:78` — `abs(difference) <= 0.25` decides whether
  a statement reconciliation check **passes**. A materiality threshold with no
  name and no stated rationale.
- `services/portfolio_proof.py:1264` — `_terminal_totals_match(..., tolerance:
  float = 0.01)`. Both call sites (`:1339-1340`) use the default, so it is a
  constant wearing a parameter's clothes — and it sits beside the already-named
  `REPLAY_RECONCILIATION_TOLERANCE` (1.00), so a reader cannot tell why two
  related checks use tolerances 100× apart without reading both.

### Scoping corrections (examined, deliberately not changed)

- **`statement_importer.py:197` `/100` is not a magic number.** It is
  `growth *= 1 + (value / 100)` converting a percentage to a fraction —
  a unit conversion that is self-evident in context. Naming it would obscure it.
- **The `"USD"` repetition is not worth a constant.** 76 non-test sites, but
  they are two different things: base-currency *fallbacks* (`base_currency or
  "USD"`) and currency *data* in per-currency logic. A blanket constant would
  conflate them, touch 76 sites for zero behaviour change, and make the
  fallbacks harder to find rather than easier. Recorded as examined.
- **De-export is stale** — already noted in the register: US-23.8 shipped knip
  with `ignoreExportsUsedInFile: true`, so over-exports never trip the gate.
- **Hand-rolled test builders** were deliberately deferred by US-23.6 with a
  recorded reason (many return route-payload dicts, not the shared model
  builder). That reason still holds; not revisited.

## Out of scope

  right materiality threshold is would be a methodology decision with its own
  evidence requirement.
- **Migrating the hand-rolled test builders** to `fixtures.py` (US-23.6's

- **A `DEFAULT_BASE_CURRENCY` constant** (scoping correction above).

  public one is the accident.

## Notes / decisions

- **Why delete rather than wire up.** The two functions are not equivalent —
  the live private one feeds the Risk Summary card's per-position volatility
  and risk share against the response schema the card consumes. Promoting the
  orphan would change a shipped surface to satisfy a tidiness argument. The
  orphan is the accident; deleting it is what makes the methodology doc true.
- **Why the dead-code gate did not catch this.** `vulture` sees the test
  callers and counts the symbol as used. A function reachable *only* from tests
  is invisible to that gate — worth remembering as a general limitation, not a
  gate bug.
- No new formula, so no academic citation is required.
