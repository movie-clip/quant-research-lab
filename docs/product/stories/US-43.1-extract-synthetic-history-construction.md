# US-43.1: Extract synthetic-history construction into its own module

**Epic:** Epic 43 — Engine Seam Consolidation
**PRD:** [`epic-43-engine-seam-consolidation.md`](../prd/epic-43-engine-seam-consolidation.md)
**Status:** Done
**Last updated:** 2026-09-02

## Story

As a **developer of this project**, I want the reconstruction of a daily
portfolio-state series from current holdings × historical prices — the
**Synthetic History** truth class — to live in one module named for it, imported
as a public function, so that six engines stop reaching into
`diagnostics_engine.py` for a private helper and the synthetic-history seam is
testable on its own.

## Context

`_build_synthetic_snapshot_history_states_with_coverage` (and its thin caller
`_build_synthetic_snapshot_history_states`) are defined in
`services/diagnostics_engine.py` but imported by **five** other engines:

- `services/attribution_engine.py:24`
- `services/correlation_engine.py:35`
- `services/distribution_engine.py:25`
- `services/drawdown_engine.py:26`
- `services/stress_engine.py:26`

plus `diagnostics_engine.py` itself. A named truth class (`CLAUDE.md` →
Architecture: Truth Classes; `docs/architecture/system-architecture.md`) is
reachable only through another engine's underscore-prefixed name — the seam
leaks. This is a **behaviour-neutral relocation**: the function body does not
change, only its home and the loss of the leading underscore, so every computed
result and the goldens stay byte-identical.

Recorded in `docs/tech-debt-register.md` as row US-43.1.

Implementer must read:
- `services/diagnostics_engine.py` — the two function definitions (~L761–L925)
  and its own call site (~L733).
- The five importing engines' call sites (all pass `(snapshot, benchmark_symbol,
  market_data, …)` and unpack `(daily_states, coverage)`).
- `services/quant-engine/app/tests/test_synthetic_history_coverage.py` — imports
  the helper directly; `test_correlation_engine.py:310` — monkeypatches it at
  `correlation_engine._build_synthetic_snapshot_history_states_with_coverage`
  (patched where used, so the patch target survives the move — only the name
  loses its underscore).
- `services/` layering: a new `services/` module importing from `schemas` /
  `analytics` / `engine` is cycle-free; confirm no engine imports back into it
  in a way that cycles.

## Notes / decisions

- **Home = `services/synthetic_history.py`.** The function needs
  `MarketDataService`-shaped input and returns engine-domain `DailyPortfolioState`
  objects, so it belongs in `services/`, not `analytics/`. It has no schema
  consumer, so there is no layering pull toward `core/`.
- **Monkeypatch survival.** `test_correlation_engine.py` patches the name on the
  *consuming* module (`correlation_engine.<name>`), not on the definition site,
  so re-homing the definition does not break the patch — only the underscore
  drops from the string.
- No new formula; a relocation, not a methodology change.
