## Story

As a **portfolio researcher** holding niche defense UCITS ETFs, I want the
engine to resolve the **correct** Yahoo Finance symbol for each fund, so that
VanEck Defense (`DFND`) gets price history — without ever silently pulling a
**different** look-alike fund's prices.

## Context

US-18.1 added the Yahoo fallback and recovered most excluded UCITS ETFs. Three
defense ETFs were flagged for follow-up; investigation (by `yfinance` `longName`)
shows only **one** is a genuine gap, and it carries a correctness trap:

- **`DEFS`** (Amundi STOXX Europe Defense) — its rule already has `DEFS.L`, which
  `yfinance` confirms is "Amundi Stoxx Europe Defense UCITS ETF Acc" (USD).
  **Already correct — no change.**
- **`IDFN`** (Invesco Defence Innovation) — its rule already has `IDFN.L`, which
  `yfinance` confirms is the Invesco (USD) fund. **Already correct — no change.**
- **`DFND`** (VanEck Defense UCITS ETF, GBP) — its rule has only the bare
  `("DFND",)` candidate, which 404s on both providers, so the holding gets no
  history. The tempting `DFND.L` is **iShares Global Aerospace & Defence UCITS
  ETF — a different fund** — and must never be used. The correct VanEck Defense
  Yahoo lines are `DFNS.L` (USD), `DFEN.DE` (EUR), `DFNG.L` (GBP).

This story fixes the `DFND` resolution rule and pins a guard so a future edit
can't reintroduce the wrong-fund `DFND.L`.

Implementer must read:
- `services/quant-engine/app/core/symbols.py` — `DEFAULT_SYMBOL_RULES`, the
  `DFND` rule (the VUAA/SGLD/SXRV rules are the pattern to mirror)
- `.claude/skills/fmp-data/SKILL.md` — symbol-resolution + the UCITS table
- US-18.1 (`US-18.1-yfinance-fallback-provider.md`) — the fallback this rides on

## Out of scope

- **Broadening the provenance badge** to other surfaces — US-18.2.
- **Currency-exact line selection** — for return correlation any liquid line of
  the *same* fund is acceptable; `DFNS.L` (USD) is preferred to minimise FX noise
  in the USD analytics framework. Picking the exact statement-currency line is not
  required.
- **ISIN-based resolution** — not introduced here; identity was verified via
  `yfinance` `longName`. A general ISIN-matching resolver is a possible future epic.

## Notes / decisions

- **Correctness over coverage:** the whole point of this story is to *avoid* the
  `DFND.L` trap. `yfinance` `longName` confirmed: `DFND.L` = "iShares Global
  Aerospace & Defence UCITS ETF"; `DFNS.L`/`DFEN.DE`/`DFNG.L` = "VanEck Defense
  ETF". Mapping `DFND`→`DFND.L` would silently show a different fund — a
  truth-class violation. AC2's guard test exists to prevent regressions.
- **DEFS/IDFN were never broken** — the earlier "3 deferred" assessment was a
  probe artifact (a 2024 date range predating these 2024/25 fund launches). With
  an in-lifetime window they already resolve via US-18.1's `DEFS.L`/`IDFN.L`.
- **Line ordering:** `DFNS.L` (USD) first → cleanest underlying for USD-based
  correlation; `DFEN.DE`/`DFNG.L` as further fallbacks.
- No new formula; no academic citation needed.
