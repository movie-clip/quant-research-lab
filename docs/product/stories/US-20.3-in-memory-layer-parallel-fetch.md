# US-20.3: In-memory layer + parallel fetch

**Epic:** Epic 20 — Market-Data Cache Efficiency & Control
**PRD:** [`epic-20-market-data-cache-efficiency.md`](../prd/epic-20-market-data-cache-efficiency.md)
**Status:** Done
**Last updated:** 2026-06-11

## Story

As a **portfolio researcher**, I want repeated cache reads served from an
in-memory layer and multi-holding history fetched concurrently, so that loading
the Exposure tab for a many-holding portfolio is noticeably faster — without any
change to the numbers, the trust semantics, or the on-disk cache.

## Context

Two latency costs remain after US-20.1 (cache control) and US-20.2 (range
normalization). (1) Every engine builds a fresh `MarketDataService` →
`FmpClient` → `JsonFileCache`, and `JsonFileCache.get` re-reads and re-parses the
same JSON file from disk on every call; one Exposure page load runs ~7 engines
that each re-read overlapping cache files (PRD problem #2). (2)
`MarketDataService.get_historical_prices_for_symbols` fetches symbols **one at a
time** (PRD problem #3) — slow for a portfolio with many holdings, even when
every read is a cache hit, because each is a separate disk round-trip.

This story adds (A) a **process-level in-memory memo** over `JsonFileCache.get`,
keyed by absolute file path and validated by file mtime, so a file is read +
JSON-parsed at most once per (path, mtime) per process — every later read across
any engine is an in-memory hit; and (B) **parallelizes**
`get_historical_prices_for_symbols` with a bounded `ThreadPoolExecutor`. Both are
pure performance: the bytes returned, the TTL/stale semantics, `last_fetch_meta`,
and the trust ladder are all unchanged.

Implementer must read:
- `app/core/cache.py` — `JsonFileCache.get` / `set` / `clear` (where the memo
  goes; `get` already applies the `fetched_at`/`max_age`/`allow_stale` logic on
  the parsed payload — the memo must store the full parsed dict so that logic is
  unchanged).
- `app/services/market_data.py` — `get_historical_prices_for_symbols` (the
  sequential loop), `get_historical_prices`, `_yfinance()` (lazy build),
  `last_fetch_meta`.
- `app/clients/fmp.py` — `FmpClient.__init__` (builds a `JsonFileCache` per
  instance over `settings.fmp_cache_dir`; the memo being process-global is what
  makes it shared across engines' separate instances).
- `app/tests/conftest.py` — autouse-fixture pattern (US-21.1/21.4) for the
  memo-clear fixture.

## Acceptance criteria

- [x] AC1 — A second `JsonFileCache.get(key)` for an unchanged file does **not**
  re-read/parse from disk: it returns the memoized parsed payload. Verified by
  asserting the underlying file read / `json.loads` happens once across two gets.
- [x] AC2 — The in-memory layer is **correctness-transparent**: identical return
  values to the pre-memo behaviour for fresh, stale (`allow_stale`), expired
  (`max_age_seconds` exceeded), and missing-file cases; a `set(key, …)` is
  immediately visible to the next `get` (memo refreshed on write).
- [x] AC3 — A cache file modified on disk (new mtime) **invalidates** the memo:
  the next `get` re-reads and returns the new contents, never a stale memo entry.
- [x] AC4 — The memo is shared **across `JsonFileCache` instances** for the same
  file (process-global), so separate per-engine `MarketDataService`/`FmpClient`
  instances reading the same cache file in one analysis hit memory after the
  first read.
- [x] AC5 — Test isolation: an autouse fixture clears the in-memory layer before
  each test, so the memo never leaks state across tests; the full suite is green
  and deterministic under the network guard **and** xdist parallel workers.
- [x] AC6 — `get_historical_prices_for_symbols` fetches symbols **concurrently**
  (bounded worker pool) and returns the **same** dict — same keys (canonicalized
  symbols), same per-symbol rows, same `last_fetch_meta` entries — as the
  sequential version, regardless of completion order. Concurrency introduces no
  data races: per-symbol `last_fetch_meta` writes and the lazy `_yfinance()`
  build are safe.
- [x] AC7 — Fail-closed and trust semantics unchanged: a symbol with no data
  still yields `[]` and no fabricated rows; `vendor`/provenance metadata is
  identical to the sequential path. Goldens untouched (`FrozenMarketData`
  bypasses this seam); `git status` clean after `run_all_tests.py`.

## Out of scope

- **Cross-process / persistent shared memory** (e.g. an mmap or a sidecar
  process) — the memo is per-process only; cross-process sharing is already what
  the on-disk file cache provides.
- **Async/`httpx.AsyncClient` rewrite** — thread-pool parallelism is sufficient
  for the I/O-bound fetch and keeps the synchronous call sites unchanged.
- **Parallelizing anything beyond `get_historical_prices_for_symbols`** (e.g.
  quotes, profiles, holdings) — out of scope for this story; the multi-holding
  history fetch is the hot path.
- **A configurable memo size / eviction policy** — the working set (one
  analysis's cache files) is small; a plain dict cleared per analysis-process is
  sufficient. Add an LRU only if a real memory concern appears (it won't here).
- **Any change to TTL policy, provider priority, trust/provenance, the on-disk
  format, or `last_fetch_meta` shape** (PRD non-goals).

## Notes / decisions

- **Why process-global, mtime-keyed, with an autouse clear:** the repeated reads
  this targets are *across* engines, each of which builds its own
  `JsonFileCache` instance — so an instance-level memo would barely help. A
  process-global memo keyed by `(absolute_path, mtime_ns)` is shared across those
  instances, is self-invalidating on any write (mtime bump), and — because keys
  are absolute paths — never collides between the real cache and `tmp_path` test
  caches. The autouse `_clear_cache_memory` fixture makes intra-process test
  isolation explicit and keeps the suite deterministic (the project's stability
  gate), including under xdist.
- **Why the memo stores the full parsed dict (not just `payload`):** `get`'s
  `fetched_at`/`max_age`/`allow_stale` logic operates on the serialized envelope;
  memoizing the whole parsed dict means that logic is byte-for-byte unchanged —
  the memo only removes the `read_text` + `json.loads` cost.
- **Why threads, not async:** the fetch is I/O-bound (httpx + disk); a bounded
  `ThreadPoolExecutor` parallelizes it without converting every call site to
  async. `httpx.Client` is thread-safe for concurrent requests; the existing
  rate-limiter and in-flight-dedup locks already guard shared client state.
- **Latency is the deliverable, measured not asserted:** unit tests prove
  *correctness + concurrency-safety*; the wall-time improvement for a
  many-holding portfolio is recorded in the slice log (like US-21.5's xdist
  measurement), not pinned in an assertion.
- No new financial formula; no academic citation. Methodology unchanged.
