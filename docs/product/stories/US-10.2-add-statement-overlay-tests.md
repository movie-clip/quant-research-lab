# US-10.2: Sequential add-statement overlay tests

**Epic:** Epic 10 — Multi-broker Import Correctness
**PRD:** [`epic-10-multi-broker-import-correctness.md`](../prd/epic-10-multi-broker-import-correctness.md)
**Status:** Done
**Last updated:** 2026-05-27

## Story

As a **portfolio researcher**, I want the frontend "Add Statement" merge logic to be regression-tested for the 3-step sequential import scenario (IB → +FF → +ESPP), so that any future change to `overlayImportedSnapshot` that breaks position accumulation, cash merging, or `sourceFileNames` tracking fails a test before it reaches production.

## Context

When a researcher imports IB2026, then clicks "Add Statement" and selects FF2026, and again for ESPP2026, the frontend calls `overlayImportedSnapshot(existing, new)` twice in sequence. The function merges positions (overwrites by symbol, adds new) and cash balances (overwrites by currency), and accumulates `sourceFileNames`. This client-side merge is the final combined snapshot that gets sent to the backend for analytics.

`overlayImportedSnapshot` and `buildPortfolioSnapshotFromAnalysis` are defined in `apps/desktop/src/features/portfolio/portfolioSnapshot.ts`. No vitest covers the 3-step overlay sequence.

Implementer must read:
- `apps/desktop/src/features/portfolio/portfolioSnapshot.ts` — `overlayImportedSnapshot`, `buildPortfolioSnapshotFromAnalysis`
- `apps/desktop/src/features/portfolio/workspaceTypes.ts` — `PortfolioSnapshot` type

## Acceptance criteria

- [x] A vitest named `overlayImportedSnapshot applies three sequential overlays correctly` passes, simulating the IB → +FF → +ESPP add-statement flow using minimal fixture snapshots. After two overlays the result has: all symbols from all three brokers (e.g. VUAA from IB, VTI from FF, MSFT from ESPP), correct cash balance (ESPP USD overwrites FF USD which overwrites IB USD), and `importedMeta.sourceFileNames` containing all three file names deduplicated.
- [x] A vitest named `overlayImportedSnapshot does not duplicate symbols when same symbol appears in two overlays` passes, asserting that if IB and a hypothetical second broker both hold VUAA, the final result has exactly one VUAA row (last-write-wins, not additive).
- [x] All existing `portfolioSnapshot.ts` tests (if any) continue to pass.
- [x] `npx tsc --noEmit` is clean after the new test file is added.

## Test plan

- `portfolioSnapshot.test.ts` — `overlayImportedSnapshot does not duplicate symbols when same symbol appears in two overlays`: two snapshots both holding VUAA at different market values; assert exactly one VUAA in result with last-write-wins value

## Notes / decisions

- `overlayImportedSnapshot` cash merge is last-write-wins per currency (not additive). The test must assert the ESPP USD value, not the sum.
- `sourceFileNames` deduplication uses `Array.from(new Set([...existing, ...new]))`. The test verifies all three names appear exactly once.
- No real PDF files needed — all fixtures are hand-constructed minimal `PortfolioSnapshot` objects.
