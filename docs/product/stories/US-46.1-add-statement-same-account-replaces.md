## Story statement

**As a** portfolio researcher,
**I want** the Exposure tab to show one copy of each holding after I add a
refreshed statement from the same broker account,
**so that** the normal "add my updated YTD statement" flow does not show every
position and total at twice its real size.

## Context

Closes finding F3 of the 2026-09-29 statement-import audit (tech-debt register
row F3; `02-quant-audit.md` § Findings F3). Today the desktop overlay sums
positions by symbol regardless of account. Adding IB2026 onto IB2026 takes raw
market value 62,843.22 to 125,686.44, VUAA 80 to 160 and USD cash 146.07 to
292.13. The Dashboard, which uses the backend combine, is already idempotent for
the same pair, so the two tabs disagree.

The authoritative rule is `docs/finance/financial-methodology.md` § Multi-Statement
Snapshot Merge: same account replaces (latest wins), distinct accounts sum, a
missing account identity or a base-currency mismatch refuses the combine. The
research brief (`02-quant.md` § F3) fixes a constraint the tech lead must design
within: the backend merge is the only merge, and every surface that shows a
combined portfolio consumes what it produces. The client carries no account
identity, so it cannot apply the rule itself and must not be a second
implementation of the formula (guardrail 2). Which code change satisfies this is
the design lane's.

Recorded prior decision touched: US-14.1 made same-symbol positions sum,
motivated by IB MSFT plus ESPP MSFT (two different accounts). That stays true.
The change narrows the behaviour to distinct accounts, so the two tests US-14.1
pinned for same-symbol overlay (`does not duplicate symbols...`, `applies three
sequential overlays...`) will need to change.

Truth classes: the Exposure view of a combined portfolio is Snapshot Analytics
over Broker Truth; this story does not mix in Synthetic History.

## Acceptance criteria

1. **Same-account re-add is idempotent on positions.** After IB2026 is imported
   and IB2026 is added again, the Exposure tab shows 18 positions, with no
   position's quantity differing from IB2026 alone.
2. **Same-account re-add is idempotent on value.** In that state the Exposure
   tab's raw market value is 62,843.22 and the base-currency value is 65,746.67,
   identical to IB2026 alone (`02-quant.md` § F3).
3. **Named position.** In that state VUAA shows quantity 80 and market value
   12,004.80 USD, not 160.
4. **Cash is not doubled.** In that state cash shows USD 146.07, EUR 0 and GBP 0.
5. **Distinct accounts still sum.** When the added statement is from a different
   account (IB2026 then ESPP2026), a symbol held in both accounts shows the sum
   of the two quantities, preserving the US-14.1 behaviour.
6. **Exposure agrees with the Dashboard.** For the same set of statements the
   Exposure tab's holdings are the ones the Dashboard replays; the two tabs no
   longer describe different portfolios.
7. **Refused combine publishes nothing.** When adding a statement is refused
   (base-currency mismatch, or a statement without an account identity), no
   combined portfolio is saved or shown on any surface, and the existing error
   disclosure is displayed. The portfolio that was on screen before the attempt
   stays as it was (`02-quant.md` § F3, handoff bullet on App.tsx:791-800).
8. **No silent cross-currency sum.** A combined portfolio never adds market
   values held in different currencies without conversion, and never silently
   adopts the added statement's base currency.
9. **Single statement unchanged.** Importing one statement, with no add, shows
   the same Exposure figures as before this story.
10. **Saved doubled node is re-derived on load (D-7).** A workspace saved by the
    old add-statement path with IB2026 added onto IB2026 shows, once opened, 18
    positions, raw market value 62,843.22, VUAA quantity 80 and USD cash 146.07,
    not the doubled values it was saved with.
11. **Re-derivation is stable.** Opening and saving the same workspace repeatedly
    shows the same Exposure figures each time; a combined node is never doubled
    again by being loaded.
12. **A node that cannot be re-derived is not shown as valid.** When a saved
    combined node cannot be re-derived on load (for example its stored statement
    lacks an account identity), the old saved figures are not presented as current,
    and the existing error disclosure is displayed.

## Test plan

Names the files and behaviours; individual test names and counts are the test
lane's to determine.

**Frontend (vitest, `apps/desktop/src/`)**

- The existing overlay/snapshot tests under `features/portfolio/` (those that
  pinned the US-14.1 same-symbol behaviour) are updated to the replace-versus-sum
  rule: same account does not double, distinct accounts sum.
- An App-level add-statement test (`apps/desktop/src/app/`) that drives the flow
  with IB2026 then IB2026 and asserts the Exposure inputs equal IB2026 alone
  (18 positions, 62,843.22, VUAA 80, USD 146.07). The audit proved F3 by running
  the overlay function, not by clicking through the UI, so a UI-level path is
  required here, not only a function test.
- The refused-combine path: a base-currency mismatch and a statement without an
  account identity each leave the prior portfolio in place, save no combined
  node, and show the error disclosure.
- Distinct-account add (IB2026 then ESPP2026) still sums a shared symbol.
- Persistence (`app/portfolioWorkspaceStorage` coverage): a workspace fixture
  built from the pre-fix saved shape, with a doubled IB2026 + IB2026 combined
  node, shows 18 positions, 62,843.22, VUAA 80 and USD 146.07 after load (D-7);
  repeated load and save is stable; a node that cannot be re-derived is not shown
  with its old figures and shows the error disclosure.

**Backend (pytest, `services/quant-engine/app/tests/`)**

- A regression test on the combine: for IB2026, combining the statement with
  itself yields the positions and cash of the statement alone. This is the
  invariant the Exposure fix relies on and it is not currently pinned as a
  property.
- Cross-currency and missing-account refusal on the combine, if not already
  covered.
