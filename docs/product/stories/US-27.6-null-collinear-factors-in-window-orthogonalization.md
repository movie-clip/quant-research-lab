# US-27.6: Null (don't keep raw) collinear factors in per-window orthogonalization

**Epic:** Epic 27 — Financial Calculation Correctness
**PRD:** [`epic-27-financial-calculation-correctness.md`](../prd/epic-27-financial-calculation-correctness.md)
**Status:** Done
**Last updated:** 2026-07-05

## Story

As a **portfolio researcher**, I want a factor that is collinear within a
rolling window to be reported as "no estimate" for that window, so that its
loading is never an arbitrary ridge-split number and later factors stay
properly orthogonalized.

## Context (audit finding F7)

`analytics/risk.py` `_orthogonalize_factors_window`: when a factor's
Gram-Schmidt residual is ~0 (fully collinear with higher-priority factors in
this window), the code appends the **raw** series back into the design matrix
("keep raw to preserve its label"). Consequences:

1. The subsequent ridge OLS fits two (near-)identical columns; the tiny
   λ=1e-5 splits the loading between them **arbitrarily** — both coefficients
   are reported as real loadings.
2. Later factors are residualized against the raw (not orthogonalized)
   series, so their "partial loading after controlling for higher-priority
   factors" interpretation breaks for that window.

The methodology's documented edge case is explicit (§Per-window
orthogonalization): *"A factor's orthogonalized residual has zero variance
(collinear with earlier factors in this window): skip that factor's
coefficient (null), do not propagate to later factors."*

`analytics/attribution.py` consumes the same pipeline
(`_orthogonalize_factors_window` + `_fit_factor_model`), and its documented
edge case ("β̂ null → exclude the date") depends on the null actually being
produced.

Implementer must read:
- `analytics/risk.py` `_orthogonalize_factors_window`,
  `_build_rolling_factor_loadings` (how `values_map` maps positions →
  coefficients — the fix must keep the position↔label mapping correct when a
  factor is dropped from the design matrix but still needs a null in the
  output point).
- `analytics/attribution.py` `build_factor_attribution` (same positional
  mapping; a dropped factor must yield a null contribution → date excluded per
  its documented edge case).
- Methodology §Statistical Factor Model + §Factor Return Attribution edge
  cases.

## Acceptance criteria

- [x] AC1 — A window where factor k is exactly collinear with earlier factors
  produces `loading_k = None` for that date; the other factors' loadings match
  the fit **excluding** factor k's column (hand-checkable 2–3 factor fixture).
- [x] AC2 — Factors ordered after k are orthogonalized against the surviving
  orthogonalized set only — never against k's raw series.
- [x] AC3 — Attribution: on such a date, factor k's contribution is null and
  the date is excluded from period/cumulative sums per the documented edge
  case; the reconciliation identity still holds on all included dates.
- [x] AC4 — Non-collinear windows are numerically unchanged (existing rolling
  loading tests + US-24.2 pins + goldens hold untouched).
- [x] AC5 — The near-collinear (not exact) case is unchanged — the ridge floor
  still handles it; only the ~zero-residual branch changes. The
  `1e-12` residual threshold becomes a named constant with a rationale.
