# US-24.3: De-duplicate the shared analytics constants & lookback helper

**Epic:** Epic 24 — Codebase Improvement
**PRD:** [`epic-24-codebase-improvement.md`](../prd/epic-24-codebase-improvement.md)
**Status:** Done
**Last updated:** 2026-06-24

## Story

As a **developer of this project**, I want the three analytics defaults that are
copy-pasted across the engine layer — the synthetic-history lookback heuristic,
the minimum-daily-observations floor, and the default benchmark symbol — each
defined **once** in a shared module and imported everywhere, so that tuning one
of them is a single edit and the engines can't silently drift apart.

## Context

Three values are re-implemented across `app/analytics/` and `app/services/`
(catalogued in [`docs/tech-debt-register.md`](../../tech-debt-register.md) →
Epic 24 backlog row US-24.3):

1. **Lookback heuristic** `ceil(window * 1.6) + 30` — a private
   `_lookback_calendar_days` in `attribution_engine.py`, `correlation_engine.py`,
   `distribution_engine.py` (the last literally docstring'd "Mirror of
   attribution_engine"), `drawdown_engine.py`, plus a precomputed
   `_STRESS_LOOKBACK_CALENDAR_DAYS = ceil(252*1.6)+30` in `stress_engine.py`.
2. **Minimum daily observations** `_MIN_OBSERVATIONS = 20` (a flat floor) — in
   `analytics/distribution.py`, `services/distribution_engine.py`,
   `services/correlation_engine.py`, `services/drawdown_engine.py`, and as the
   `min_observations: int = 20` parameter default in `analytics/correlation.py`.
3. **Default benchmark** `"SPY"` — `Field`/attribute defaults in
   `schemas/imports.py`, `schemas/portfolio_engine.py`, `schemas/attribution.py`,
   and `... or "SPY"` runtime fallbacks across the dashboard-history / diagnostics
   / distribution / exposure / stress / drift / drawdown engines.

This is a **behaviour-neutral consolidation**: the *values are unchanged*, so
every computed result and the dashboard goldens stay byte-identical. The new home
must be `app/core/` — the lowest layer, importable by `schemas`, `analytics`, and
`services` without a layering cycle.

Implementer must read:
- `app/services/attribution_engine.py` `_lookback_calendar_days` — the canonical
  lookback form (the `build-story` skill already names it as the one to reuse).
- The call sites listed above; `app/core/` for the layering (settings/cache/symbols).

## Out of scope

- **Changing any value** — the lookback factor (`1.6`/`30`), the floor (`20`), and
  the default benchmark (`"SPY"`) are unchanged; re-tuning any of them is a
  separate, methodology-reviewed decision.
- **Merging the distinct constants** — `WINDOW_MIN_OBSERVATIONS` and
  `attribution.min_observations = window` are different concepts (AC3); not touched.
- **A general config/settings system** — these stay as module constants; promoting
  them to `Settings` (env-overridable) is a separate decision, not this story.

## Notes / decisions

- **Home = `app/core/constants.py`** (not `app/analytics/`): the
  `DEFAULT_BENCHMARK_SYMBOL` is consumed by `app/schemas/*`, and schemas must not
  import `analytics`/`services` (layering inversion). `app/core/` is below schemas
  and already hosts cross-cutting infra (`settings`, `cache`, `symbols`), so it is
  the only cycle-free home for all three.
- **The lookback factors are an empirical heuristic, not an academic formula** —
  `ceil(window * 1.6) + 30` over-fetches calendar days to cover weekends/holidays
  for a trading-day window. The shared symbol keeps the existing methodology-doc
  wording; no new citation (none exists).
- No new formula; this is a de-duplication refactor, not a methodology change.
