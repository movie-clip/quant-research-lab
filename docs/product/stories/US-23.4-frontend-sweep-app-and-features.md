# US-23.4: Frontend dead-code sweep — app & features

**Epic:** Epic 23 — Dead-Code Cleanup & Codebase Review
**PRD:** [`epic-23-dead-code-cleanup-and-review.md`](../prd/epic-23-dead-code-cleanup-and-review.md)
**Status:** Next phase
**Last updated:** 2026-06-12

## Story

As a **developer of this project**, I want the desktop frontend
(`src/app/`, `src/features/`) swept of confirmed-dead exports, components, types,
helpers, and CSS, and its smells catalogued, so that the UI codebase is only
live code rendered by a real surface.

## Context

The frontend is `src/app/` (state, storage, App shell, primitives) +
`src/features/portfolio/` (~32 non-test files); `src/features/market-data/` and
`src/features/settings/` appear empty/legacy. Known dead candidates: the
**admission-disposition persistence plumbing** in `portfolioWorkspaceStorage.ts`
(schema-sanitizing code with no producer/consumer — see the US-22.2 close-out)
and any unused exported types/helpers. Using `knip`/`ts-prune` + the removal
protocol, this story removes confirmed-dead TS/TSX and dead CSS tokens/classes,
and records FE smells (un-tokenised literals, prop-drilling, duplicated
formatters) into the register. **Persisted-state sanitizers are the trap**:
removing a sanitizer can corrupt or fail to migrate real IndexedDB/localStorage
state — only remove when the persisted field is provably gone from the type AND
no saved-state migration relies on it.

Implementer must read:
- `docs/tech-debt-register.md` + removal protocol (US-23.1).
- `src/app/portfolioWorkspaceStorage.ts` + `src/features/portfolio/workspaceTypes.ts`
  + `types.ts` — the disposition plumbing and persisted-state contracts.
- `.claude/skills/ui-polish/SKILL.md` + `src/test/designSystem.audit.test.ts` —
  the design-system token/primitive inventory (dead-CSS-token removal must keep
  the audit green).

## Acceptance criteria

- [ ] AC1 — `knip`/`ts-prune` report no unused exports in `src/app` +
  `src/features` except reasoned allowlist entries (Tauri/Vite entry points, test
  utilities); every removed symbol is confirmed dead by the protocol.
- [ ] AC2 — The admission-disposition plumbing in `portfolioWorkspaceStorage.ts`
  (and its `ImportAdmissionReviewDispositionV1` type, the `admissionReviewDispositions`
  field, sanitizers, and the dead evidence-matcher) is removed **only after**
  confirming no saved-workspace migration depends on it; persisted-state
  round-trip tests stay green and a stored workspace without the field still
  loads. (If any migration risk exists, it is recorded, not removed.)
- [ ] AC3 — Empty/legacy feature dirs (`features/market-data`,
  `features/settings`) are either removed (if truly empty/unimported) or their
  remaining live content is documented; no dangling import results.
- [ ] AC4 — Dead CSS tokens/classes in `styles.css` are removed with the
  design-system audit (`designSystem.audit.test.ts`) staying green; no live card
  loses a token it uses.
- [ ] AC5 — **No behaviour change**: full vitest suite green; `npx tsc --noEmit`
  clean (with US-23.1's `noUnusedLocals`); dashboard goldens consumers unchanged.
- [ ] AC6 — FE hardcodes / anti-patterns are appended to
  `docs/tech-debt-register.md` (area = `frontend`), each with `file:line`,
  category, severity, effort — not fixed here.

## Notes / decisions

- **Persisted-state safety is the priority over deletion.** A sanitizer that
  guards malformed IndexedDB is *not* dead even if no feature produces the field
  — it protects load. The disposition plumbing is removable only because the
  field is being removed from the persisted type entirely; verify a pre-existing
  saved workspace (with or without the field) still loads.
- No new formula; no methodology change.
